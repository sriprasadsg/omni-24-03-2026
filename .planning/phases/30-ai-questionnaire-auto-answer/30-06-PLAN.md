Inbound intake — `backend/questionnaire_inbound_endpoints.py` (30-02), prefix `/api/questionnaires/inbound`:
- POST `/api/questionnaires/inbound` — JSON `{title, questions?}` -> created set

- GET  `/api/questionnaires/inbound/{qid}` — one set

Draft generation/list — `backend/questionnaire_answer_draft_endpoints.py` (30-04), prefix `/api/questionnaire-answer-drafts`:
- POST `/api/questionnaire-answer-drafts/generate` — JSON `{question_set_id}` -> one draft per question
- GET  `/api/questionnaire-answer-drafts` — list drafts (optional `?question_set_id=`, `?status=`)

Review/submit — `backend/questionnaire_answer_review_endpoints.py` (30-03), prefix `/api/questionnaire-answer-drafts`:
- GET   `/api/questionnaire-answer-drafts/pending-review` — list pending_review drafts
- POST  `/api/questionnaire-answer-drafts/{draft_id}/review` — create a review record (any authenticated tenant user)
- PATCH `/api/questionnaire-answer-drafts/{draft_id}/review/{review_id}` — body `{decision:"approved"|"rejected"|"needs_revision", comment, edited_answer_text?}` (REVIEWER role only; body reviewer_id is ignored — server-derived)
- GET   `/api/questionnaire-answer-drafts/{draft_id}/reviews` — review thread newest-first
- POST  `/api/questionnaire-answer-drafts/{draft_id}/submit` — mark submitted (REVIEWER role; backend enforces status=='approved' guard)

Draft doc (SHARED CONTRACT, 30-03): `{ id:"qad-…", tenantId, questionSetId, questionId, questionText, answerText, original_answer_text, confidence:"high"|"medium"|"low"|"insufficient_evidence", sourceEvidenceIds:[str], sourceEvidence:[{source,content}], status:"pending_review"|"approved"|"rejected"|"needs_revision"|"submitted", reviewer_id, decided_at, reviewComment, submitted_by, submitted_at, created_at, updated_at }`

DECISION VOCABULARY DIFFERENCE FROM THE ANALOG: `EvidenceReviewPanel.tsx` uses `changes_requested`; the questionnaire backend validates `needs_revision`. Map the "Request Changes" button to `needs_revision`, and use `needs_revision` (not `changes_requested`) in STATUS_STYLES.
