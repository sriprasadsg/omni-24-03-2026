<objective>
Build RAG-02's mandatory human-review gate: the state machine and endpoints that hold every AI-drafted questionnaire answer in `pending_review` until a human explicitly decides on it, and that make `submitted` reachable ONLY from `approved`. This clones `evidence_review_service.py`/`evidence_review_endpoints.py` near-verbatim (Phase 15 precedent) and adds the one transition evidence-review lacks: `approved → submitted`, guarded at the data layer so no code path (bug, refactor, or direct call) can bypass review (Critical Failure Mode #2 / threat T3).

Purpose: Make the compliance control — "no answer reaches submitted without explicit human approval" — enforced in the database query, not just the UI.
Output: A review service, review/decision/submit endpoints (RBAC + server-derived reviewer identity), and tests proving the bypass is rejected.

SHARED CONTRACT (implemented identically by this plan and by 30-04): the `questionnaire_answer_drafts` collection document shape is defined in "Artifacts this phase produces" below — this plan reads/transitions those docs; 30-04 creates them. Both plans MUST use the exact field names and status vocabulary listed there.
</objective>
