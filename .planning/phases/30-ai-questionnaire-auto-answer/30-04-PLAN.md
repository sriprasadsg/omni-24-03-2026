<objective>
Build the grounded answer-drafting pipeline (RAG-01's generation half): retrieve tenant-scoped evidence → grounded-generate a low-creativity answer → Pydantic-validate → store as a `pending_review` draft. This clones `compliance_narrative_service.py`'s validated-generation-with-fallback pattern and uses the two primitives fixed in 30-01 (tenant-scoped `rag_service.query()`, `generate_text(temperature, max_tokens)`). The exact `AnswerDraft` model and `draft_answer_for_question()` entry point are pre-written in 30-AI-SPEC.md Section 3 (lines 156-247) — copy them as the starting implementation and adapt to the shared draft-doc contract.

Purpose: Turn inbound question sets (30-02) into grounded, honest, review-ready drafts that cite their evidence and flag no-evidence cases instead of fabricating.
Output: A draft service, a generate/list endpoint pair, and tests for the insufficient-evidence and grounding invariants.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| ingested evidence → LLM prompt | Retrieved evidence content/source is untrusted text concatenated into the drafting prompt (RAG-specific injection surface) |
| LLM output → stored draft | Model JSON is untrusted until Pydantic-validated |
| client → generate/list API | Tenant must only draft/list against its own question sets |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T4 | Tampering (prompt injection via retrieved content) | draft_answer_for_question() prompt assembly | high | mitigate | Existing `guardrail_service.scan_and_log` scans assembled prompt in/out (defense layer 1) + this plan sanitizes evidence `content`/`source` before prompt assembly (layer 2, AI-SPEC 4b) |
| T1 (consumer) | Information Disclosure | rag_service.query() call site | critical | mitigate | Passes the real `tenant_id` into the 30-01 tenant-scoped query; depends on the 30-01 isolation test passing before this ships |
| T2 | Information Disclosure | generate/list draft endpoints | high | mitigate | Tenant-scoped access to `questionnaire_inbound` and `questionnaire_answer_drafts` via `get_database()` |
</threat_model>
