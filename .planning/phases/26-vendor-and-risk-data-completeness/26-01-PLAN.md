<objective>
Deliver VRISK-01: a DPA (Data Processing Agreement) lifecycle tracked with the same rigor as the existing BAA lifecycle — create → sign (dual-party) → active → terminate, plus list/stats/get — as a standalone `/api/dpa` router cloned from `backend/baa_endpoints.py`.

Purpose: DPA today is only a checkbox option string in the vendor questionnaire; it has zero persistence. This gives it a real, auditable, tenant-scoped lifecycle matching BAA.

Output: `backend/dpa_endpoints.py`, its registration in `router_registry.py`, and `backend/tests/test_dpa_endpoints.py`. Two deliberate deviations from a verbatim BAA clone: (1) add a `vendor_id` field on create (BAA has none), (2) add an explicit admin-role gate on create/sign/terminate (BAA's `create_baa` is ungated — do not copy that gap).
</objective>
