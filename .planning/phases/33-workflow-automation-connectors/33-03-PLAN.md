<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| npm registry → this repo (supply chain) | New dev/peer dependencies are pulled during install; a malicious/typosquatted package would execute at install/build time |
| n8n node → /api/webhooks (client) | The node holds a tenant API key and calls the platform API as an external client |
| platform → n8n Webhook node (inbound POST) | The n8n instance receives event POSTs and must be able to verify authenticity |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-33-SC | Tampering | npm install of eslint-plugin-n8n-nodes-base (SUS) + n8n-workflow / typescript | high | mitigate | Blocking human checkpoint (Task 1) verifies the SUS-flagged package on npmjs.com before any install; versions pinned per the audited Standard Stack; install occurs only after approval. |
| T-33-KEYSTORE | Information Disclosure | apiKey stored in the n8n credential | medium | mitigate | apiKey field uses n8n's password typeOption (masked, encrypted at rest by n8n); README surfaces revocation via the platform's existing revoke_api_key. |
| T-33-SIGN-VERIFY | Spoofing | inbound POST authenticity at the n8n Webhook node | medium | mitigate | README documents verifying the `X-Webhook-Signature: sha256=...` header (produced by 33-02) against the per-webhook secret so users can reject forged POSTs. |
| T-33-DUP | Tampering (availability) | duplicate subscriptions on workflow re-activation | low | mitigate | checkExists reads the stashed webhookId so re-activation does not create duplicate db.webhooks subscriptions (Pitfall 3). |
</threat_model>
