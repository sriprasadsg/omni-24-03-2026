<objective>
Close CHK-03: container image scanning already returns trivy: false + a note string when Trivy is unavailable, but the frontend only surfaces that note in one small banner — so a user looking at the CVE table or scan-history sees no distinction between a real Trivy scan and six hardcoded fake CVEs (CVE-2024-0001..0006). Add an explicit machine-readable `simulated` flag to the data contract and make the UI loudly label simulated data everywhere it appears.

Purpose: Presenting fabricated CVE data as authoritative scan evidence is a compliance-integrity (scan-authenticity) risk that undermines the platform's core value proposition. Per RESEARCH.md Pattern 4, the correct fix is labeling — NOT failing closed: two existing IAC-02 tests assert scan_image() still returns non-empty simulated vulns when Trivy is mocked absent, so a fail-closed change would regress them (Pitfall 4). This plan is purely additive.

Output: An explicit `simulated` field on both container-result paths, a widened TS interface, three UI badge sites, and a test asserting the flag.

Note: this plan is Wave 2 and depends on 25-02 solely because both extend backend/tests/test_iac_scanner.py — sequencing avoids a merge conflict on that shared file.
</objective>
