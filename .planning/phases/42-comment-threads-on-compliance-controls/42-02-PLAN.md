<objective>
Wire @mention notification delivery onto the comment POST. Parse plain-text `@username` tokens server-side AFTER the comment persists (D-04), resolve each token to a tenant user's email, and fire an in-app-only notification via the notification-service factory. This is the one genuinely-new logic in the phase (Pitfall 3 / Assumption A1) — the tickets email-shaped regex and the broken `ticket_notifications.py` import are explicitly NOT reused.

Purpose: Satisfies Success Criterion 3 (@mention triggers a notification) with D-02's in-app-only constraint.
Output: `extract_mention_tokens`/`resolve_mentions` in the service, notification dispatch in the POST handler, and two unit tests proving the db.notifications write happens with no channel dispatch.
</objective>
