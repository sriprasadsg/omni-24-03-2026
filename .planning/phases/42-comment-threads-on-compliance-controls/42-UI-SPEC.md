# Phase 42 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Scope note:** This phase adds one small sub-panel (`ControlCommentsPanel.tsx`) to an existing, already-styled dashboard page (`FrameworkDetail.tsx`'s expanded-control row), mounted immediately after `<ChainOfCustodyPanel controlId={control.id} />` (line 432). It is not a new page, route, or nav entry. Per 42-RESEARCH.md's phase brief, this contract **reuses the project's existing manual-Tailwind design system verbatim** rather than introducing new tokens — every value below is sourced directly from `ChainOfCustodyPanel.tsx` (closest structural analog — lazy-fetch panel in the same expanded row) and `EvidenceReviewPanel.tsx` (closest interaction analog — role-gated comment/decision thread).

## Spacing Scale

Declared values (must be multiples of 4) — all sourced from `ChainOfCustodyPanel.tsx`/`EvidenceReviewPanel.tsx`, no new values introduced:

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-label gaps (`gap-1`, `mt-0.5` rounds to nearest existing usage) |
| sm | 8px | Compact element spacing (`gap-2`, `p-2`, `py-2`) |
| md | 16px | Panel padding, section spacing (`px-4`, `py-4`, `mt-4`) |
| lg | 24px | Not used at this component's scale — reserved for parent page sections only |

Exceptions:
- `gap-1.5` (6px) is used in `ChainOfCustodyPanel.tsx`'s header label (`flex items-center gap-1.5`) — carry forward for the new panel's header only, do not use elsewhere.
- `py-3.5` (14px) appears on `EvidenceReviewPanel.tsx`'s action buttons — this is a pre-existing off-scale value in the codebase. **Do not propagate it into the new comment composer.** Use `py-2` (8px) for the Post Comment button instead, consistent with the 8-point scale.

## Color

Dominant/secondary/accent split reused verbatim from `ChainOfCustodyPanel.tsx` and `EvidenceReviewPanel.tsx` — no new hex values, all via existing Tailwind gray/blue/red/amber/green utility classes (the project has no raw hex in these components; colors come from Tailwind's default palette, not `tailwind.config.js`'s custom `primary`/`secondary`/`flash` tokens, which are reserved for marketing/landing surfaces per the codebase's existing convention of dashboards using plain Tailwind grays).

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `bg-white` / `dark:bg-gray-800` | Panel body background, comment list background |
| Secondary (30%) | `bg-gray-50` / `dark:bg-gray-750`, `bg-gray-100` / `dark:bg-gray-700/50` | Panel header bar, individual comment row background, borders (`border-gray-200` / `dark:border-gray-700`) |
| Accent (10%) | `text-blue-600` / `dark:text-blue-400` (text), `bg-blue-600 hover:bg-blue-700` (button fill) | **Reserved exclusively for:** the "Post Comment" submit button fill, and `@mention` token highlighting inside rendered comment text (e.g. `<span className="text-blue-600 dark:text-blue-400 font-medium">@username</span>`). Not used for panel chrome, icons, or borders. |
| Destructive | `text-red-500` / `dark:text-red-400` | **Reserved exclusively for:** the "Failed to load comments" / "Failed to post comment" error message text. There is no destructive *action* in this phase — D-03 makes comments immutable/append-only, so no delete button, no destructive-confirmation copy, no red button fill anywhere in this panel. |

Accent reserved for: the Post Comment button and `@mention` text highlighting — never the panel header, icons, borders, or comment metadata text.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Panel header label | `Comments` (mirrors `ChainOfCustodyPanel`'s `Chain of Custody` header pattern — icon + label + count, e.g. `Comments (3)`) |
| Primary CTA | `Post Comment` (button label on the composer's submit button; disabled while submitting, label changes to `Posting...` matching `EvidenceReviewPanel`'s `Submitting...`/`Saving...` in-flight pattern) |
| Composer placeholder (reviewer roles) | `Add a comment... (use @username to mention someone)` |
| Empty state heading | not applicable — single-line empty state only, matching `ChainOfCustodyPanel`'s pattern (no separate heading + body split) |
| Empty state body | `No comments yet on this control.` (italic, `text-gray-400`, centered — exact style clone of `ChainOfCustodyPanel`'s `No chain-of-custody events recorded for this evidence.`) |
| Non-reviewer state | Composer is **hidden entirely** for users outside `admin`/`super_admin`/`compliance_reviewer` (D-01) — no disabled input, no placeholder helper text. This matches `EvidenceReviewPanel.tsx`'s exact precedent: `{isReviewer && evidenceStatus === 'pending_review' && (...)}` conditionally renders the whole action block, it does not render a disabled version for other roles. The comment *thread* (read side) remains visible to all authenticated tenant users per RESEARCH.md Assumption A2. |
| Error state (load) | `Failed to load comments. Retry by collapsing and expanding this panel.` (exact clone of `ChainOfCustodyPanel`'s load-error copy, since the panel auto-fetches on mount rather than click-to-expand — see Interaction note below) |
| Error state (post) | `Failed to post comment — please try again.` (matches the existing toast-copy convention seen in `FrameworkDetail.tsx`'s `onDeleteEvidence`/`onUpdateStatus` handlers: `"Failed to update compliance status — please try again"`) |
| Success toast (post) | `Comment posted.` (matches the terse past-tense pattern of existing toasts: `"Evidence deleted."`, `"Request approved."`) |
| Destructive confirmation | **Not applicable.** D-03 makes comments immutable/append-only — there is no edit or delete action anywhere in this phase, so no destructive-confirmation copy exists or should be written. |

**Interaction note (from RESEARCH.md Pattern 4 / Assumption A3):** unlike `ChainOfCustodyPanel`'s click-to-expand-then-fetch UX, this panel fetches automatically when the parent row expands (`expandedControlId === control.id`) — comments are the primary collaboration surface, not a secondary audit drill-down. It still uses the same header-bar visual chrome as `ChainOfCustodyPanel` (icon + label + count) for consistency, but does not require a second click to reveal its contents.

## Component Notes for Executor

- **`@mention` rendering (Security Domain, RESEARCH.md):** comment text MUST render via React's default JSX escaping — `{comment.text}` (optionally with `@token` substrings wrapped in a `<span>` for the accent-color highlight described above, built via a safe split/map, never `dangerouslySetInnerHTML`). This is a hard constraint carried from RESEARCH.md's Security Domain section, not a discretionary style choice.
- **Role gate mirrors backend, never replaces it:** the frontend hides the composer for non-reviewer roles purely for UX; the backend's `_COMMENT_AUTHOR_ROLES` check is the actual enforcement (per `EvidenceReviewPanel.tsx`'s own inline comment convention — carry the same "kept in sync by hand, backend re-enforces" code comment into the new component).
- **Loading spinner:** reuse `ChainOfCustodyPanel.tsx`'s inline animated SVG spinner markup verbatim (no new spinner component/icon needed).
- **List ordering:** comments render oldest-first (`created_at` ascending), matching `list_comments`'s `.sort("created_at", 1)` in RESEARCH.md — top of thread is the earliest comment, newest comment is last (conversation-log order, distinct from `EvidenceReviewPanel`'s reviews thread which has no specified sort direction called out).
