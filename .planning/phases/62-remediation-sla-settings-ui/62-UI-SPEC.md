## Visual Hierarchy

Focal point: the numeric input field (`<input type="number">`, `w-24 px-3 py-2 rounded-md border ... bg-white dark:bg-gray-700`) is the primary visual anchor of the panel — it is the only bordered, filled-background control in the field group, sitting directly beside its `days` suffix on the `flex items-center` row. This matches `EvidenceSettings.tsx`'s actual rendered visual weight verbatim: the bordered input reads first (it is the one element with a visible box and background-color contrast against the panel's flat `bg-gray-50` surface), then the "Remediation SLA" section label above it (14px/500, see Typography), then the "Save SLA Window" button below (filled `bg-primary-600` — secondary anchor, read second only because it sits lower in the panel and is reached after the input is set). Helper text, unit suffix, and the conditional validation message are deliberately lower-weight (12px/400, no border/background) so they never compete with the input for attention.

## Typography

Confirmed against the live clone source (`components/EvidenceSettings.tsx`) with one declared deviation (see below) to hold this project's 2-weight-max typography ceiling — no prior approved UI-SPEC documents a 3-weight scale (44-UI-SPEC.md's own Typography contract locks exactly 2 weights, 400/600), so no citation exists to justify a third weight here:

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 12px (`text-xs`) | 400 (regular) | default (Tailwind `text-xs` line-height, ~1.33) — helper text, unit suffix ("days"), validation message |
| Label | 14px (`text-sm`) | 500 (medium, `font-medium`) | default (~1.43) — field label ("At-Risk Window"), Save button label ("Save SLA Window") — matches the clone source's actual button className (`text-sm font-medium`) verbatim |
| Heading | 14px (`text-sm`) | 500 (medium, `font-medium`) | default (~1.43) — section label ("Remediation SLA") — **deviates from the clone source's literal `font-semibold` (600) on this one element**; downgraded to `font-medium` (500) to hold the 2-weight ceiling. See deviation note below. |
| Display | not applicable | — | — | This phase adds no page/modal-level heading; it is a settings-tab sub-panel only |

Weight contract for new elements: exactly 2 weights used — 400 (regular: helper text, unit suffix, validation message) and 500 (medium: field label, section label, Save button label). Do not introduce `font-semibold` (600) or `font-bold` (700) anywhere in this component.

**Declared deviation from the clone source:** `EvidenceSettings.tsx`'s section label (`<p>` reading "Evidence Quality") literally renders `text-sm font-semibold` (600) in the live code (confirmed `EvidenceSettings.tsx:31`). A true byte-for-byte clone would carry that same `font-semibold` into `RemediationSlaSettings.tsx`'s "Remediation SLA" label, producing a third weight (400/500/600) in this component. Per the project's 2-weight-max typography rule, this is not permitted — `RemediationSlaSettings.tsx`'s section-label `<p>` must use `font-medium` (500) instead of `font-semibold`, one intentional, documented substitution against the otherwise-verbatim clone. This is the only className substitution in the entire component beyond variable names, API calls, and copy strings (see Component-Level Build Notes).

## Color

Confirmed against the live clone source (`components/EvidenceSettings.tsx`) and the live tab-bar source (`components/SettingsDashboard.tsx:288-289`):

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#ffffff` / dark `#374151` (`bg-white` / `dark:bg-gray-700`) | Numeric input field background — inherited from `EvidenceSettings.tsx`'s input, unchanged |
| Secondary (30%) | `#f9fafb` / dark `rgba(55,65,81,0.5)` (`bg-gray-50` / `dark:bg-gray-700/50`) | Panel container background (the outer bordered card wrapping the field + button) — clone verbatim |
| Accent (10%) | `var(--primary-600)` (`bg-primary-600` / hover `bg-primary-700`; tab active state `text-primary-600 dark:text-primary-400` + `border-primary-500`) | Reserved for exactly two elements: (1) the "Save SLA Window" button background, (2) the "Remediation" tab's active-state text/underline when selected. **Never** the input border, never the helper/label text, never any part of the panel container. |
| Destructive | `#dc2626` light / `#f87171`-ish dark (`text-red-600` / `dark:text-red-400`) | Reserved for the validation message only ("Must be between 1 and 365 days.") when the value is out of range — the only error-state element this component has. No destructive *action* exists in this phase (no delete/remove control). |

Accent reserved for: "Save SLA Window" button, "Remediation" tab active-state indicator (text color + bottom border) when `activeView === 'remediation'`. Never the input field, never the section/field labels, never the helper text, never the tab in its inactive state (inactive tabs use neutral `text-gray-500` / `dark:text-gray-400`, per the existing tab-button pattern at `SettingsDashboard.tsx:288`).

No second semantic color system is needed — unlike Phase 44's SLA badge (which introduced a 4-state status-color map), this phase is a single numeric field with binary valid/invalid state, using only the destructive-red validation message and the standard neutral/primary palette already in `EvidenceSettings.tsx`.

## UI Considerations

Applicable state considerations resolved: 4 covered, 1 backstop, 0 unresolved

| Category | Element(s) | Status | Resolution / Reason |
|----------|------------|--------|---------------------|
| loading (pre-fetch) | numeric input, initial value | ✅ covered | Input renders immediately with the hardcoded default (7) before `useEffect`'s fetch resolves — no spinner/skeleton state, matching `EvidenceSettings.tsx`'s identical behavior; this is a single-field settings panel, not a data table |
| error (fetch failure) | numeric input, initial value | ✅ covered | `fetchRemediationSlaWindow()` soft-fails to `{ windowDays: 7 }` on any GET error (network or non-2xx) per RESEARCH.md Pitfall 3 — the panel never renders blank or broken, it silently falls back to the default and lets the user proceed |
| error (save failure incl. 403) | Save button, toast | ✅ covered | `saveRemediationSlaWindow()` throws on `!res.ok`; `handleSave`'s catch shows the generic error toast copy above — covers both non-admin 403 and genuine network/5xx failures identically per D-04 |
| validation (out-of-range input) | numeric input, validation message, Save button | ✅ covered | Client `onChange` clamps to `[1, 365]` before state update (same clamp expression as `EvidenceSettings.tsx`); `isValid` derived check disables Save and shows the red validation message whenever out of range — though the clamp makes true out-of-range state rare, the check exists as defense-in-depth matching the clone source exactly |
| in-flight (saving) | Save button | 🧪 backstop | Button label switches to `Saving...` and is `disabled` while `saving === true`, identical to `EvidenceSettings.tsx` — no dedicated test asserts the button text mid-flight in the existing clone source's test suite (none exists for `EvidenceSettings.tsx` itself); RESEARCH.md's Wave 0 test plan does not explicitly enumerate this sub-state, so treat as a held-out visual assertion the executor's new test file may optionally cover, not a hard requirement |

- **`components/RemediationSlaSettings.tsx`** (new file): byte-for-byte structural clone of `components/EvidenceSettings.tsx` — same `space-y-6` → bordered-card → `space-y-2` field-group → `flex items-center` input-row → conditional validation `<p>` → `mt-4` button-row structure. Substitutions: state var `threshold`→`windowDays`; `api.fetchStalenessThreshold`/`api.saveStalenessThreshold`→`api.fetchRemediationSlaWindow`/`api.saveRemediationSlaWindow`; every copy string per the Copywriting Contract above; success toast string only (error toast stays identical, per D-04); **and the section-label `<p>`'s className changes `font-semibold` → `font-medium`** (the one Typography deviation documented above — required to hold the 2-weight ceiling, not optional).
- **`components/SettingsDashboard.tsx`** (3 edits, exact JSX shape of the existing `'evidence'` button/panel pair at lines ~288-289, ~354): (1) append `| 'remediation'` to the `SettingsView` union type (line 65); (2) insert a new `<button onClick={() => setActiveView('remediation')} className={...same ternary shape...}><ClipboardListIcon size={18} className="mr-2" /> Remediation</button>` immediately after the "evidence" button; (3) insert `{activeView === 'remediation' && <RemediationSlaSettings />}` immediately after the evidence panel mount. Import `ClipboardListIcon` from `./icons` alongside the existing icon import line.
- **`services/apiService.ts`**: two new exported functions, `fetchRemediationSlaWindow`/`saveRemediationSlaWindow`, mirroring `fetchStalenessThreshold`/`saveStalenessThreshold`'s exact shape (GET soft-fails to a default, PATCH throws on `!res.ok`) — see RESEARCH.md Code Examples for the verified signatures.
- **Non-admin behavior (D-04):** no client-side role check anywhere in this component or its Save button — the 403 from a non-admin's PATCH attempt is caught by the same generic `catch` block as any other save failure and shown as the standard error toast. Do not add a `canManageSettings`/`isSuperAdmin` conditional around the tab button, the input, or the Save button.
