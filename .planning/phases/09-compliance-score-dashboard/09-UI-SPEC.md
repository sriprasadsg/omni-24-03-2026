## Design System Context

- `bg-white dark:bg-gray-800` card surfaces with `border border-gray-200 dark:border-gray-700` borders
- `rounded-lg` card radius

## 2. Entry Point (Dashboard.tsx mount)

`ComplianceScorePanel` mounts in `Dashboard.tsx` immediately above the existing `ComplianceStatus` block at line 47.

Current:
```tsx
<div className="mt-8">
  <ComplianceStatus frameworks={complianceFrameworks} />
</div>
```

After edit:
```tsx
<div className="mt-8 space-y-6">
  <ComplianceScorePanel />
  <ComplianceStatus frameworks={complianceFrameworks} />
</div>
```

Rationale: `ComplianceScorePanel` presents the live DB-backed aggregate score; `ComplianceStatus` below it continues to show the static governance posture cards (RESEARCH.md "State of the Art" — ComplianceStatus is not deprecated). Placing the live score above creates a top-to-bottom reading flow: headline KPI → framework detail cards.

`ComplianceScorePanel` takes no props. It owns its own data fetch internally via `useEffect`.

## 3. ComplianceScorePanel Component

### Props

```typescript
// No props — component is self-contained with internal fetch
export const ComplianceScorePanel: React.FC = () => { ... }
```

### State

| State variable | Type | Initial value | Purpose |
|----------------|------|---------------|---------|
| `data` | `ComplianceScorePayload \| null` | `null` | API response |
| `loading` | `boolean` | `true` | Show skeleton |
| `error` | `boolean` | `false` | Show error message |
| `expandedFramework` | `string \| null` | `null` | Which framework row is expanded (SCORE-03 drill-down) |

### Data Fetch

```typescript
useEffect(() => {
  let cancelled = false;
  setLoading(true);
  setError(false);
  fetchComplianceScore().then(result => {
    if (cancelled) return;
    if (result === null) setError(true);
    else setData(result);
    setLoading(false);
  });
  return () => { cancelled = true; };
}, []);
```

No polling. Score is cached on the backend (TTL 300s, invalidated on evidence writes). Manual refresh is out of scope for this phase.

## 4. Overall Score Display

### Large Percentage Number

- Size: `text-3xl font-bold` (30px, weight 700)
- Color rule (applied to the number only):
  - score ≥ 80: `text-green-600 dark:text-green-400`
  - 50 ≤ score < 80: `text-amber-600 dark:text-amber-400`
  - score < 50: `text-red-600 dark:text-red-400`
- Format: `{score}%` — one decimal place from API, rendered as-is (e.g., "87.3%")
- Positioned left inside the Score Summary Block, vertically centered

### "Severity-weighted" tag

- Directly beneath the score number
- Text: `Severity-weighted score` (text-xs, font-medium, text-gray-500 dark:text-gray-400)
- No separate badge wrapper — plain text is sufficient

### Pass/Fail/Partial Counts

Computed from `data.frameworks` by summing `passing`, `failing`, `partial` fields across all frameworks.

- Displayed as three lines in a right-aligned column:
  - `{total_passing} Passing` — `text-sm text-green-600 dark:text-green-400`
  - `{total_failing} Failing` — `text-sm text-red-600 dark:text-red-400`
  - `{total_partial} Partial` — `text-sm text-amber-600 dark:text-amber-400`
- Each line prefixed with a 2px × 12px colored dot (`inline-block w-2 h-2 rounded-full mr-1`)

### Score Summary Block layout

```
┌─────────────────────────────────────────────────────────┐
│  87.3%                          142 Passing              │
│  Severity-weighted score         18 Failing              │
│                                   6 Partial              │
└─────────────────────────────────────────────────────────┘
```

Use `flex items-center justify-between` with left-column containing the score and right-column containing the counts. The block has `rounded-lg p-4 bg-gray-50 dark:bg-gray-700/50 mb-4`.

## 5. Per-Framework Breakdown

### Display approach: always-visible rows, expand for detail

Rationale: SCORE-03 says "can be expanded in a panel." The recommended implementation is always-visible rows (not hidden behind a toggle) with per-row accordion expansion for the passing/failing breakdown. This prevents the panel from appearing empty before the user discovers the expand interaction.

### Framework Row (collapsed state)

```
┌─────────────────────────────────────────────────────────┐
│ SOC 2       ████████████░░░░░░   87.3%    ChevronDown   │
│ ISO 27001   ██████░░░░░░░░░░░░   72.1%    ChevronDown   │
└─────────────────────────────────────────────────────────┘
```

- Row height: auto (min 44px for touch target compliance)
- `framework.short_name`: `text-sm font-medium text-gray-800 dark:text-white`, fixed `w-24` column
- Progress bar: `flex-1 mx-4 h-1.5 rounded-full bg-gray-200 dark:bg-gray-700` container; fill width = `score%`, fill color by threshold (green/amber/red)
- Score value: `text-sm font-medium w-12 text-right` with same color-by-threshold rule as overall score
- Chevron icon: `ChevronDownIcon w-4 h-4 text-gray-400` rotated 180° when row is expanded (`transition-transform duration-200`)
- Row interaction: `cursor-pointer hover:bg-gray-50 dark:hover:bg-gray-700/50 transition-colors duration-150`
- Top border: `border-t border-gray-100 dark:border-gray-700` on every row

### Framework Row (expanded state)

Visible when `expandedFramework === framework.framework_id`. Shown as a sub-row immediately below the framework row.

```
┌─ SOC 2 (expanded) ───────────────────────────────────────┐
│ ✓ 142 controls passing                                    │
│ ✗  18 controls failing                                    │
│ ◑   6 controls partial                                    │
└───────────────────────────────────────────────────────────┘
```

- Background: `bg-gray-50 dark:bg-gray-700/30`
- Padding: `px-4 py-3`
- Three lines with colored leading icon (Lucide `CheckCircle2` green, `XCircle` red, `Circle` amber) at `w-4 h-4 mr-2`
- Text: `text-sm` + count in `font-medium`
- Expand/collapse is toggle on same row click — clicking an expanded row collapses it

### Framework ordering

Frameworks are rendered in the order returned by the API. The API returns them in `compliance_frameworks` collection order (insertion order). No client-side reordering.

## 6. Severity Weight Legend Tooltip

### Trigger

An `InfoIcon` (Lucide `Info`, `w-4 h-4`) placed inline after the "Compliance Score" heading text in the panel header.

- Color: `text-gray-400 hover:text-gray-600 dark:hover:text-gray-300`
- Margin: `ml-2`
- `aria-label="Severity weight explanation"` on the trigger button
- `role="button"` + `tabIndex={0}` for keyboard access

### Tooltip implementation

Use native browser `title` attribute is NOT sufficient (not accessible on mobile/keyboard). Implement as a controlled `<div>` tooltip:

- Trigger: `onMouseEnter` / `onMouseLeave` / `onFocus` / `onBlur` toggles `tooltipVisible` boolean state
- Tooltip container: `absolute z-10 w-64 p-3 bg-gray-900 dark:bg-gray-700 text-white rounded-lg shadow-xl text-sm`
- Position: `bottom-full left-1/2 -translate-x-1/2 mb-2` (appears above the trigger)
- Arrow: 8px CSS triangle (`border-b-4 border-l-4 border-r-4 border-transparent border-t-gray-900`) centered below tooltip box
- Wrapper: `relative inline-flex items-center` on the trigger container

### Tooltip content (exact copy)

```
Severity-Weighted Score

Each control contributes weight based on severity:
  Critical  ×4
  High      ×3
  Medium    ×2
  Low       ×1

Score = sum of passing weights ÷ sum of all weights × 100.
Controls with no monitored asset evidence are excluded.
```

### Tooltip visual layout

Title: `text-xs font-semibold text-white mb-2`

Weight table: four rows, two columns (severity name + `×N` badge):
- Severity name: `text-xs text-gray-300` in fixed `w-20` column
- Weight badge: `text-xs font-bold px-1.5 py-0.5 rounded` with severity color background:
  - Critical: `bg-red-600`
  - High: `bg-orange-500`
  - Medium: `bg-yellow-500 text-gray-900`
  - Low: `bg-blue-500`

Formula line: `text-xs text-gray-400 mt-2 border-t border-gray-600 pt-2`
Exclusion note: `text-xs text-gray-400 mt-1`

## 7. Loading / Error / Empty States

### Loading state

Displayed when `loading === true`. Replace the Score Summary Block and Framework rows with skeleton elements:

- Score Summary Block: `animate-pulse bg-gray-200 dark:bg-gray-700 rounded-lg h-20 w-full`
- Framework rows: 3 skeleton rows, each `animate-pulse h-10 bg-gray-100 dark:bg-gray-700/50 rounded mb-2`
- Panel header is rendered normally (not skeletonized) so the user sees "Compliance Score" immediately

### Error state

Displayed when `error === true`.

Copy:
- Heading: "Score unavailable"
- Body: "The compliance score could not be loaded. Refresh the page to try again."

Visual:
- `AlertTriangleIcon` (Lucide, `w-5 h-5 text-amber-500 mr-2`) inline with heading
- Container: `p-4 rounded-lg bg-amber-50 dark:bg-amber-900/20`
- Heading: `text-sm font-semibold text-amber-700 dark:text-amber-400`
- Body: `text-sm text-gray-600 dark:text-gray-400 mt-1`

### Empty state

Displayed when `data` is non-null but `data.frameworks.length === 0` AND `data.overall_score === 0`.

Copy:
- Heading: "No monitored controls yet"
- Body: "Upload evidence or configure asset compliance to see your score here."

Visual:
- `ShieldIcon` (Lucide, `w-8 h-8 text-gray-300 dark:text-gray-600`) centered
- Heading: `text-sm font-medium text-gray-500 dark:text-gray-400 mt-2`
- Body: `text-xs text-gray-400 dark:text-gray-500 mt-1`
- Container: `flex flex-col items-center justify-center py-8`

### Zero-score non-empty state

When `data.overall_score === 0` but frameworks exist (all controls failing): render the normal layout. The score number shows `0.0%` in `text-red-600`. This is a legitimate state, not an empty state.

## 8. Accessibility

| Requirement | Implementation |
|-------------|----------------|
| WCAG AA minimum text size | `text-xs` (12px) minimum — no `text-[Npx]` arbitrary sizes |
| Tooltip keyboard accessible | Trigger has `tabIndex={0}`, `onFocus`/`onBlur` shows tooltip; `role="tooltip"` on tooltip div; `aria-describedby` links trigger to tooltip |
| Framework accordion keyboard | Each row is a `<button>` element with `aria-expanded={expandedFramework === fw.framework_id}` and `aria-controls={fw.framework_id + '-detail'}` |
| Color not sole indicator | Score thresholds use both color AND the percentage number as the data signal; progress bar fill level is additional reinforcement |
| Loading state communicated | `aria-busy="true"` on the panel root during loading; skeleton items have `aria-hidden="true"` |
| Error state communicated | Error container has `role="alert"` so screen readers announce it immediately |
| Touch targets | Framework rows minimum `min-h-[44px]` for mobile; tooltip trigger `w-8 h-8` with padding around the `w-4 h-4` icon |
| Dark mode | All colors use paired `dark:` variants; no color is declared without its dark counterpart |

Icon usage: all Lucide icons used purely decoratively alongside text have `aria-hidden="true"`. The InfoIcon tooltip trigger is the sole icon with interactive semantics and uses `aria-label`.

## 9. API Contract Summary

### Request

```
GET /api/compliance/score
Authorization: Bearer {jwt}
```

No query parameters. Tenant is derived from JWT (`current_user.tenant_id`).

### Response shape

```typescript
interface FrameworkScore {
  framework_id: string;       // e.g. "soc2"
  framework_name: string;     // e.g. "SOC 2 Type II"
  short_name: string;         // e.g. "SOC 2"
  score: number;              // 0.0–100.0, one decimal
  passing: number;            // count of controls with weighted status = Compliant
  failing: number;            // count of controls with weighted status = Non-Compliant
  partial: number;            // count of controls with weighted status = Warning
  total_controls: number;     // controls with any asset_compliance record
}

interface ComplianceScorePayload {
  overall_score: number;          // 0.0–100.0, severity-weighted across all frameworks
  frameworks: FrameworkScore[];   // one entry per compliance framework
  computed_at: string;            // ISO 8601 UTC timestamp of last computation
  tenant_id: string;              // echoed from JWT for client-side debugging
}
```

### Error responses the frontend must handle

| HTTP status | Meaning | Frontend behavior |
|-------------|---------|-------------------|
| 200 | Success | Render data |
| 401 | Unauthenticated | `fetchComplianceScore` returns `null`; authFetch handles redirect |
| 403 | Forbidden | `fetchComplianceScore` returns `null`; show error state |
| 500 | Backend error | `fetchComplianceScore` returns `null`; show error state |
| Network failure | Offline / timeout | catch block returns `null`; show error state |

`fetchComplianceScore` always returns `ComplianceScorePayload | null`. The component treats `null` as error state.

### Computed-at display

The `computed_at` timestamp is shown in the panel footer (below the framework list) as:

`Score last computed: {relative time}` in `text-xs text-gray-400 dark:text-gray-500 p-4 pt-2`

Relative time format: use a simple inline helper — if within 60 seconds: "just now"; if within 60 minutes: "N min ago"; otherwise: `new Date(computed_at).toLocaleString()`. Do not import a date library; the inline helper is sufficient.

## 10. Open Questions

These questions are deferred to the planning phase. The UI-SPEC documents the default behavior this contract implements; the planner may override if decisions change.

| # | Question | Default this contract uses | Impact if overridden |
|---|----------|---------------------------|----------------------|
| OQ-1 | Should stale automated evidence count as Non-Compliant in the score? (RESEARCH.md Open Q #1) | Score uses recorded `status` only; staleness does not affect score. Tooltip copy states: "Stale evidence may affect your actual status." | If stale = failing: severity tooltip copy must add "Stale automated evidence counts as Non-Compliant" |
| OQ-2 | Are controls with no `asset_compliance` records excluded from the denominator? (RESEARCH.md Open Q #2) | Excluded; tooltip copy states: "Score covers controls with monitored asset evidence only." | If included as failing: overall score will be lower than current formula; tooltip copy changes |
| OQ-3 | How is severity mapped to controls with no `severity` DB field? (RESEARCH.md Open Q #3, Option A vs B) | Backend uses a static category-based lookup table — the frontend treats severity weighting as a backend concern; the tooltip always shows the weight table (Critical×4, High×3, Medium×2, Low×1) regardless of how the backend resolves severity | If Option B (DB field) is chosen: no frontend change needed; tooltip copy stays the same |
| OQ-4 | Should super admin see cross-tenant aggregate or a per-tenant selector? | Not in scope for Phase 9. Super admin sees the score for their own tenant_id (same as regular users, since `tenant_id` is `""` for super admin the backend skips caching). The panel shows whatever the API returns. | If cross-tenant view is needed: requires a tenant-picker dropdown upstream of the panel |
