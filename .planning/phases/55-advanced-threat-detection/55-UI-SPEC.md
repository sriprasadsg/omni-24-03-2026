# Phase 55 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Scope reminder:** this phase has **no new frontend surface**. All three requirements (INT-04 correlation, AUT-03 predictive containment, COMM-01 SOC/OCSF push) are locked in `55-CONTEXT.md` (D-01/D-02/D-03) and confirmed in `55-RESEARCH.md` to be pure backend extensions of `siem_engine.py`, `ueba_service.py` → `autonomous_remediation_service.remediate()`, and `webhook_service.py`. Per ROADMAP.md's own phase table, Phases 50-54 each carry a `**UI hint**:` line pointing at where their findings surface — Phase 55 carries **no such line**, and RESEARCH.md's Architectural Responsibility Map states explicitly: "Reuses Phase 53/54's approve/deny UI+endpoint unchanged; this phase adds a new `finding_type`, not a new UI surface."

This UI-SPEC exists to make that "no new UI" conclusion an explicit, checkable contract — not an assumption the planner/executor have to re-derive — and to document the one incidental existing-UI touchpoint this phase's new data will flow through unchanged.

## Component-Level Build Notes (for planner/executor — not a checker dimension, but load-bearing)

- **No frontend file in this phase's plan breakdown.** `55-CONTEXT.md`'s 4-plan breakdown (55-01 correlation, 55-02 predictive detection, 55-03 containment, 55-04 SOC integration) is entirely backend (`siem_engine.py`, `threat_intel_endpoints.py`, `ueba_service.py`, `remediation_playbook_service.py`, `autonomous_remediation_service.py`, `webhook_service.py`, `ocsf_endpoints.py`). The planner should not add a frontend task/plan for this phase unless a genuinely new requirement surfaces during planning that isn't in CONTEXT.md's locked scope — if that happens, re-run `/gsd-ui-phase 55` to extend this contract rather than inventing UI decisions inline.
- **Confirmed no-change touchpoint:** `components/nativeSecurity/RemediationQueueTab.tsx` (Phase 54) is the one existing UI surface this phase's new data (`finding_type="anomaly"`, and the `no_playbook` terminal status for non-dispatchable anomaly types) will flow through. Verified by direct code read: no enum-keyed color/label map exists for `findingType` or `status` in this file — both render as plain interpolated strings — so zero code changes are required there for this phase's new values to display correctly.
- **If a future phase (e.g. a "SOC/correlation dashboard" or "UEBA alert feed" UI) is later scoped,** it is out of THIS phase's boundary per `55-CONTEXT.md`'s scope fences and `55-RESEARCH.md`'s Don't-Hand-Roll table — treat it as a new phase requiring its own `/gsd-ui-phase` run, not a silent addition here.
