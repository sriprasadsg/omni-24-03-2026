<objective>
Fix two backend gaps that block Rust agent evidence parity.

GAP-1 (RUST-01): `agent_heartbeat_endpoints.py` currently imports `process_automated_evidence` via a transitive re-export through `compliance_endpoints.py`. Change to a direct import from `compliance_evidence_processor` to eliminate the fragile dependency.

GAP-2 + GAP-3 (RUST-02): `process_automated_evidence` does not accept or write `agent_type`. Extend the function signature with an optional `agent_type: str | None = None` trailing parameter, add `"agent_type": agent_type` to the `evidence_record` dict, and add `"agent_type": agent_type` to the `$set` block in the `asset_compliance` upsert. Update the heartbeat call-site to pass `agent_type=meta.get("agent_type")`.

RUST-03 is already satisfied — all 12 Rust check names are present in COMPLIANCE_CHECK_MAPPINGS. No mapping changes are needed.

Purpose: After this plan executes, a Rust agent heartbeat containing `meta.agent_type = "rust"` and `meta.compliance_enforcement` will produce `asset_compliance` records that include `agent_type: "rust"` at both the document level and inside each `evidence[]` array entry.

Output: Two modified backend files. No new files created.
</objective>
