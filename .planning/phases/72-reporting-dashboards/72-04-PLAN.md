  <behavior>
    - Total asset value equals the sum of `compute_book_value` results for the seeded assets that have both a purchase record and a model depreciation policy.
    - An asset with no depreciation policy is counted in the asset count but contributes nothing to the value sum, and is reported in a separate withoutPolicy count.
    - Status breakdown lists every lifecycle status in the enum's declared order (deployable, deployed, archived, retired, disposed, broken) including statuses with a zero count.
    - An asset document with no lifecycleStatus key counts as deployable.
    - Licence utilisation percent equals assigned seats over total seats across the tenant's licences, and a tenant whose licences total zero seats reports the no-data signal rather than a percentage.
    - The expiring-soon count uses `get_warranty_alert_window` and `compute_warranty_status`, and includes an asset whose daysToExpiry equals the window exactly.
    - The warranty timeline returns per-month expiry counts for the next twelve months.
    - The overdue count reports overdue audits from `_overdue_query` and overdue check-ins (deployed assets whose expectedReturnDate is in the past) as separate numbers plus a total.
    - Every KPI on an empty tenant returns its no-data signal, and no KPI returns a zero presented as a measurement.
    - Seeding a second tenant changes none of the first tenant's numbers.
  </behavior>
  <action>
Create `backend/itam_reporting_kpis.py` — a pure service module with no FastAPI import, matching the `itam_finance_service.py` split.

`async def compute_itam_kpis(db, tenant_id) -> dict` returning a dict with exactly four top-level KPI keys, each of which is an object carrying `hasData` (bool), the KPI's own values, and `drilldownReportKey` (the `PREBUILT_REPORTS` key its tile opens, per D-18):

- `assetValue` — `totalBookValueCents`, `assetCount`, `withoutPolicyCount`, and `statusBreakdown` (a list of `{status, label, count}` entries emitted in `itam_models.LifecycleStatus`'s declared member order, including zero-count statuses, with a missing `lifecycleStatus` counted as `DEFAULT_LIFECYCLE_STATUS`). Compute each asset's value by calling `itam_finance_service.compute_book_value` with the same input resolution `itam_finance_endpoints.get_asset_book_value` uses (policy from the batched `asset_models` lookup), catching `ValueError` per asset and counting it as without-policy rather than failing the whole KPI. `drilldownReportKey` is `asset_value`. `hasData` is false when the tenant has zero assets.
- `licenseUtilization` — `seatsTotal`, `seatsAssigned`, `seatsAvailable`, `utilizationPercent`. Count assigned seats with `db.license_assignments.count_documents({"licenseId": ...})` per licence, exactly as `itam_license_endpoints.list_licenses` does. `hasData` is false when there are no licences or when `seatsTotal` is zero — do not emit a zero or a hundred percent for an empty denominator. `drilldownReportKey` is `license_utilization`.
- `warrantyExpirations` — `alertWindowDays` (from `itam_finance_service.get_warranty_alert_window`), `expiringSoonCount` (assets whose `compute_warranty_status` returns the expiring status, so the boundary is inherited rather than restated), `expiredCount`, and `timeline` (a list of `{month, count}` entries for the next twelve months keyed by the computed `warrantyExpiresAt`). `hasData` is false when no asset in the tenant carries both a purchase date and a warranty length. `drilldownReportKey` is `warranty_expiring`.
- `overdue` — `overdueAuditCount` (documents matching `itam_lifecycle_endpoints._overdue_query(_audit_cutoff_iso())`, imported not re-derived), `overdueCheckinCount` (assets whose `lifecycleStatus` is deployed and whose `expectedReturnDate` is earlier than now), and `totalCount`. `hasData` is false when the tenant has zero assets. `drilldownReportKey` is `overdue_audits`.

All reads go through the tenant-isolated `db` handle; use batched `find` calls, never an aggregation join.

Create `backend/tests/test_itam_reporting_kpis.py` on the shared fixtures from `backend/tests/itam_reporting_test_support.py`, with one test per behavior above. Include an equality assertion between the KPI total and a directly-computed `compute_book_value` sum, and a boundary test seeding an asset whose `daysToExpiry` equals `alertWindowDays` exactly.
  </action>
