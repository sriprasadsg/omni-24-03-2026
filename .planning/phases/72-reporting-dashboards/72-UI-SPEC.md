# Phase 72 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none — no `components.json`/shadcn in this repo; hand-rolled Tailwind design system, consistently applied across all 10 existing `ITAMConsole.tsx` panels. Introducing shadcn now would fork the visual language mid-console; new Reports/KPI surfaces must match the established panels exactly, not a new library. |
| Preset | not applicable |
| Component library | none — plain Tailwind utility classes + a small shared `components/ui/Modal.tsx` for confirm dialogs (used by `CatalogPanel.tsx`'s delete flow; reuse verbatim for the delete-saved-report confirmation) |
| Icon library | Custom hand-drawn SVG icon set at `components/icons.tsx` (Lucide-style outline icons, 24×24 viewBox, `stroke="currentColor"`, `size` prop). Relevant existing icons to reuse: `BarChart3Icon`, `PieChartIcon`, `DollarSignIcon`, `DownloadIcon`, `FilterIcon`, `CalendarIcon`, `CalendarDaysIcon`, `ClockIcon`, `AlertTriangleIcon`, `SaveIcon`, `PlusIcon`, `TrashIcon`, `SearchIcon`. No new icon library. |
| Font | Outfit (sans-serif) — `tailwind.config.js` `theme.extend.fontFamily.sans`, applied project-wide |

## Spacing Scale

Declared values (must be multiples of 4) — matches the scale already in continuous use across `components/itam/*.tsx`:

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-label gaps (`gap-1`), inline badge padding |
| sm | 8px | Compact element spacing (`gap-2`), input vertical padding (`py-2`) |
| md | 16px | Default element spacing (`mb-4`, `p-4` card padding, `px-4` button padding) |
| lg | 24px | Section padding (`p-6` page container, `mb-6`) |
| xl | 32px | Layout gaps between major panel regions |
| 2xl | 48px | Major section breaks (rare in this console; not commonly needed at panel scale) |
| 3xl | 64px | Page-level spacing (not used inside the console shell — reserved for top-level page layout only) |

Exceptions: The existing header settings-gear button (`ITAMConsole.tsx`) uses `p-2` around an 18px icon (~34px effective touch target, under the 44px guideline) — this is a pre-existing project convention, not introduced by this phase, and is not to be "fixed" incidentally while building the Reports tab. New icon-only controls added in this phase (e.g. per-format export icon buttons) should follow the same `p-2` convention for visual consistency with the rest of the console rather than deviating to 44px, since mixing touch-target sizes within one nav/toolbar row would look inconsistent. If a genuinely new icon-only primary action is added, prefer pairing the icon with a visible text label (as the rest of this console already does — e.g. `<DownloadIcon size={14}/> Export PDF`) over an icon-only 44px target.

## Typography

Matches the scale already used in `FinancePanel.tsx` / `LicensesPanel.tsx` / `ITAMConsole.tsx` — 4 sizes, 2 weights, do not introduce new ones.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 14px (`text-sm`) | 400 regular | 1.5 |
| Label | 12px (`text-xs`) | 600 semibold (`font-semibold`) — labels, table headers, badges, meta text | 1.5 |
| Heading | 18px (`text-lg`) | 600 semibold (`font-semibold`) — panel/card section titles (e.g. "Purchase Record", "Reports") | 1.2 |
| Display | 24px (`text-2xl`) | 600 semibold (`font-semibold`) — console page title only (`ITAMConsole.tsx`'s `<h1>`); not reused inside the Reports tab itself | 1.2 |

Two weights only: 400 (regular, body copy, table cell values, input text) and 600 (semibold, everything emphasized — headings, buttons, labels, active states). Do not introduce `font-medium` (500) or `font-bold` (700/800) in new Phase 72 components even though a couple of older console elements (nav-tab labels) use `font-medium` — that is pre-existing and out of scope to touch.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#111827` (`bg-gray-900`) | Console page background, tab-panel background |
| Secondary (30%) | `#1f2937` (`bg-gray-800`) with `#374151` (`border-gray-700`) borders | Cards, the pre-built report list container, the custom-builder panel, table containers, empty-state boxes |
| Accent (10%) | tenant-brandable, default `#0891b2` (`cyan-600`/`cyan-500`) — read from `ItamSettings.branding.primaryColor` exactly like the rest of the console, never hardcoded past the existing `accent` variable | Reserved for: the active "Reports" nav-tab underline/border; primary buttons ("Create Custom Report", "Run Report", "Save Report", "Export PDF"/"Export Excel"/"Export CSV"); the KPI tile accent icon backgrounds; the primary/first series color in every recharts chart; inline text-link actions (e.g. a "View Report" link in a KPI drill-down). Never used for large fill areas or as a general text color. |
| Destructive | `#dc2626` (`text-red-400`/`bg-red-900/20`/`border-red-800`, following the exact `WARRANTY_COLOR`-style badge pattern already in `FinancePanel.tsx`) | The delete-saved-report action only; error toasts (via existing `showToast(..., 'error')`); "Overdue" / "Expired" status values inside report tables and KPI tiles |

Accent reserved for: active Reports tab indicator, primary action buttons (Create Custom Report / Run Report / Save Report / the three Export buttons), KPI tile accent icons, primary chart series color, inline text-link actions. Never the default text color, never a background fill larger than a button/badge/icon chip.

Existing semantic status colors (already established across the console, reuse verbatim — not new "second semantic colors," just continuation of the existing badge system with `/20` background opacity + `-800` border):
- Green (`text-green-500 bg-green-900/20 border-green-800`) — active license/good warranty/on-track KPI
- Amber (`text-amber-500 bg-amber-900/20 border-amber-800`) — expiring warranty, low-stock consumable, upcoming-expiration KPI
- Red (as Destructive row above) — expired warranty, overdue audit, overdue check-in
- Gray (`text-gray-400 bg-gray-800 border-gray-700`) — no data / not applicable

**Visual hierarchy / focal point (checker Dimension 2 recommendation):** On the Reports tab, the KPI tile row is the primary visual anchor on tab load (top of the panel, largest accent-icon elements, first thing the eye lands on). The two-section report list (pre-built reports + "Create Custom Report") sits below it as secondary content. Within the custom builder, the on-screen results preview table (D-06) is the focal point once a report is run — it should visually dominate over the filter-picker controls above it once results are populated.
