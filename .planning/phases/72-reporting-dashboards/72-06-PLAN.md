## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser UI → API | The builder composes report definitions the backend re-validates; the UI gate is defence in depth, never the authority. |
| API response → DOM | Report rows containing tenant-authored strings are rendered into the preview table. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-72-12 | Elevation of Privilege | Client-side field/operator selection | high | mitigate | The picker only offers fields from `GET /api/itam/reports/fields`, and the backend re-validates every field and operator against `FIELD_CATALOG` — a hand-crafted request gains nothing the UI could not already request. |
| T-72-13 | Tampering | Report row values rendered into the preview table | medium | mitigate | Values are rendered as React text children (escaped by default); no `dangerouslySetInnerHTML` is introduced anywhere in these components. |
| T-72-14 | Information Disclosure | Blob download URL left allocated in the page | low | accept | The download helper follows the existing `downloadComplianceReport` pattern already in use across this app; changing its lifecycle handling is out of scope for this phase. |
| T-72-SC | Tampering | npm/pip installs | low | accept | No package is installed by this plan; recharts and the existing icon set are already present. |
</threat_model>
