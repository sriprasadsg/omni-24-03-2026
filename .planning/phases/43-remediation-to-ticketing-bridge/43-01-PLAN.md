<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| ticketing_bridge → Jira/ServiceNow SaaS | admin-supplied `jira_url`/`snow_instance` used to build outbound httpx requests |
| background scheduler → compliance_remediation_tasks | request-context-free asyncio task reads/writes a tenant-isolated collection |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-43-01 | Tampering | ticket_provider/ticket_ref/ticket_url persistence | mitigate | fields written only via server-side `$set` inside `create_ticket_for_remediation_task`; never surfaced on a client PATCH model in this plan |
| T-43-02 | Information Disclosure | close-loop cross-tenant sweep | mitigate | resolve `tenant_id` from each task doc, call `get_ticketing_config(tenant_id)` and `update_task(..., {"tenantId": tenant_id})` per-task — never a blanket cross-tenant write |
| T-43-03 | Denial of Service | scheduler using get_database() fails closed silently | mitigate | scheduler functions take raw `db` param; source-level regression guard `raw_db_registration` asserts no `get_database` reference (Pitfall 1) |
| T-43-SNOW | Tampering | ServiceNow closed-state detection | accept | label-based display-value comparison; a heavily-customized non-English instance may use other terminal labels — documented v1 limitation per D-04 best-effort |
| T-43-SSRF | Tampering/SSRF | admin-supplied jira_url/snow_instance | accept | pre-existing exposure of `ticketing_service.py` reused unmodified; no new instance of the pattern introduced by this phase (RESEARCH Security Domain) |
</threat_model>
