# Phase 78 — UI Design Contract

> Visual and interaction contract for the one small frontend surface of Phase 78 (CONTEXT D-13, D-14): the existing ITAM **Total Asset Value** KPI tile and the Reports-tab behaviour that follows from the new tenant rule. Everything else in the phase is backend. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
> Locked inputs: 78-CONTEXT.md D-01..D-16, in particular D-04 (the tile figure drops for tenants with Disposed/Retired assets), D-10 (null, never 0), D-13 (400 when no tenant), D-14 (the tile fix and nothing wider). RESEARCH.md Pitfalls 5 and 12 and Open Questions 2 and 4 are resolved here as researcher decisions (R1..R10) and the planner treats them as decided unless the user overrules. No user was available for this run (autonomous mode).
> **Not designed here (Phase 80):** the Costs tab, coverage banner, shared currency formatting, export, any per-asset cost table. The cost API routes have no screen in this phase.
> Extends, does not replace: the existing ITAM console conventions (the cyan-accent, white/gray-800 rounded-xl tile and the Phase 72 KPI panel contract, `72-UI-SPEC` element E6). Mirror format and conventions of `86-UI-SPEC.md` and `85-UI-SPEC.md` for the sections below, but note that the ITAM console does **not** use the Spatial Glass `.card`/`Modal` shell for its own panels: it uses its own `bg-white dark:bg-gray-800 rounded-xl border border-gray-200 dark:border-gray-700` surfaces and `cyan-600` actions. ## Screens and States

### 1. Scope and routing

One component, two entry situations. No new route, tab, sidebar entry or feature switch.

| Viewer | ITAM Reports tab behaviour |
|--------|----------------------------|
| Tenant user (admin or any role with `view:itam`) | Tile and reports behave as today, scoped to their own tenant. No tenant prop effect (`tenantId` is their own and `needsTenant` is false). |
| Super Admin / Platform Owner **with a tenant selected** (`viewingTenantId` set via Tenant Management, View Tenant) | The KPI request and the two report calls send `X-Tenant-ID: {viewingTenantId}`. Figures are that tenant's only. Changing the selected tenant clears the old figures at once and reloads (R3). |
| Super Admin / Platform Owner **with no tenant selected** (`needsTenant`) | The four-tile grid is replaced by the Select-a-tenant block (section 3). No KPI request is sent. Pre-built Run buttons are disabled with a one-line note (section 5). |
| Platform Support (view:itam, cannot choose a tenant, D-15) | Not `needsTenant` on the client; the request is sent and the server answers 400. The panel recognises a rejection whose message starts with `Select a tenant` and shows the same Select block (R5). Billing never reaches the tab (403). |

`needsTenant` = `isSuperAdminView && !tenantId`, computed inside `ITAMConsole` from props it already receives; no new App prop for it.

**Visual anchor:** the KPI grid is the primary anchor of the Reports tab (72-UI-SPEC); the **Total Asset Value** tile is its first tile and its figure is the largest text on the tab. In the no-tenant case the Select block takes the grid's place at the same position so the page does not jump.

### 2. Total Asset Value tile states (D-10, D-14, D-04)

Anatomy is unchanged: icon chip, title `Total Asset Value`, the whole tile is one `<button>` that drills down to the `asset_value` report. Only the content under the title changes. Data fields used: `hasData`, `totalBookValueCents` (number or null), `assetCount` (every status, the pie total), `valuedCount`, `inScopeAssetCount` (new, optional, see Assumptions), `statusBreakdown`.

Let `valued = valuedCount ?? 0`, `inScope = inScopeAssetCount ?? assetCount`, `excluded = assetCount - inScope` (never negative).

| State | Condition | Contract |
|-------|-----------|----------|
| Loading | request in flight, including after a tenant change | Existing `Loading…` line (14px, `text-gray-600 dark:text-gray-400`). No figure, no stale numbers from another tenant. |
| No data | `hasData` false, or the request failed (non-400) | Existing: `No data yet` / `Add an asset from the Catalog tab to see this here.` Unchanged (the existing test 3 keeps passing). |
| Valued | `totalBookValueCents` is a number, `valued === inScope` | Figure `$5,000` (24/600, primary text, existing `formatCurrency`). Line `Valued 12 of 12 assets` (12/400 muted). Pie chart below, unchanged. |
| Partly valued | number, `valued < inScope` | Same as Valued; the line reads `Valued 10 of 12 assets`. The figure is the sum of the valued ones only, and the line beside it says so; no extra warning colour. |
| Not tracked | `totalBookValueCents` is null, `inScope > 0` | Figure **`Not tracked`** (24/600, `text-gray-500 dark:text-gray-400`) in the figure's place, never `$0`, never `$0.00`, never `—`. Line `Valued 0 of 12 assets`. Hint (12/400 muted) `Assets need a purchase price, a purchase date and an asset model with a useful life to be valued.` Pie chart below, unchanged. |
| Nothing active | `totalBookValueCents` null, `inScope === 0`, `assetCount > 0` (every asset is Disposed or Retired) | Figure `Not tracked`; line `No active assets` replaces the Valued line; the excluded line below still shows. Pie unchanged. |
| Excluded note | `excluded > 0`, in any of the numeric states | Extra 12/400 muted line under the Valued line: `3 disposed or retired assets not counted` (`1 disposed or retired asset not counted`). It explains why the figure is lower than before (D-04) and why the pie total (`assetCount`, every status, D-04) can be larger than `y`. Not shown when `excluded` is 0. |

Rules common to all numeric states:
- The old line `{assetCount} assets` is removed; the Valued line replaces it. `assetCount` is no longer shown as text; the pie still uses every status.
- Zero is never printed as the book-value figure. A genuine computed total of 0 cents with valued assets (everything depreciated to a 0 salvage) is a number and prints `$0`; the distinction is the server's `null` versus `0`, and the tile renders exactly what it is given.
- `Valued x of y assets`: `assets` is singular when `y === 1` (`Valued 1 of 1 asset`, `Valued 0 of 1 asset`).
- The figure, Valued line, excluded line and hint form one block with `id="itam-kpi-asset-value-summary"`; the tile button gets `aria-describedby` pointing to it, so the figure is announced even though the button keeps its existing `aria-label` (`Total Asset Value — view report`), which would otherwise hide it from screen readers.
- Number formatting is the existing `formatCurrency` (whole dollars, `$`, locale grouping). Fractions of a dollar are rounded for display only (the value on the wire is integer cents). Currency symbol and cents display are Phase 80 / COST-F2.
- The other three tiles (License Seat Utilization, Warranty Expirations, Overdue Audits & Check-ins) are unchanged in content.

### 3. Select a tenant state (D-13, D-14, D-17)

Shown in place of the whole four-tile grid, because all four tiles come from the one KPI request and the server answers it with 400 for the platform context. Surface: `div` with `bg-white dark:bg-gray-800 rounded-xl border border-gray-200 dark:border-gray-700 p-8 text-center mb-6`, `role="status"` (a state, not an error), no icon (the ITAM console's empty states have none).
- Heading (`h4`, 14/600 primary): `Select a tenant`
- Body (14/400, `text-gray-600 dark:text-gray-400`, `max-w-prose mx-auto`): `Asset values and reports cover one organization at a time. Open a tenant from Tenants, then come back to Reports.`
- Button, only when `onGoToTenants` is supplied: text button `Go to Tenants` (12/600, `text-cyan-600 dark:text-cyan-400`, underline on hover, `min-h-8` hit area via `py-2`), below the body with 8px gap. `App.tsx` supplies the handler only for users who hold `manage:tenants` (`handleSetCurrentView('tenantManagement')`), the same rule as the Autonomous Ops screen's `onGoToTenants`.
- No request is made while this state shows. When a tenant becomes selected the grid appears in the Loading state.
- The Platform Support case (section 1) shows this same block when the server's 400 message starts with `Select a tenant`; `Go to Tenants` is shown only if the handler is supplied.

### 4. Tenant change behaviour (R3)

When `tenantId` changes (including to `null`), `ItamKpiPanel` sets `data` to `null` and `failed` to false and `loading` to true **before** the new request is sent, and ignores a response that arrives after a newer change (the existing `cancelled` flag per effect run). The effect depends on `tenantId`. This guarantees a figure for tenant A is never shown under tenant B (the isolation point the whole phase protects). Same reset rule in `ReportsPanel` (section 5).

### 5. Reports tab behaviour that follows from D-13 (RESEARCH Open Q2, resolved R4)

The server's tenant rule makes the pre-built report run and export routes answer 400 without a tenant. The contract keeps this small:
- `runItamPrebuiltReport` and `generateItamReport` take an optional trailing `tenantId` and pass it to `authFetch` (`{ tenantId }`, which already sets `X-Tenant-ID`); `ReportsPanel` receives `tenantId` and passes it in `runPrebuilt`, the active-page runner and `handleExport`. No other report call changes.
- With a tenant selected: reports run and export for that tenant, exactly as for a tenant user. The existing toast pattern handles any failure and shows the server's detail (`itamThrow` already re-raises a string `detail`).
- With `needsTenant` (Super Admin, no tenant): under the `Pre-built Reports` heading, one line (12/400 muted, `role="status"`): `Select a tenant to run these reports. They cover one organization at a time.` Every pre-built `Run Report` button is `disabled` (`disabled:opacity-50 disabled:cursor-not-allowed`, the existing export-button pattern) and has `aria-describedby` pointing at that line. No second banner: the Select-a-tenant block directly above is the one explanation, and this line is the per-control reason the 86-UI-SPEC pattern requires. Saved custom reports and the report builder are untouched.
- The drill-down from a tile (`focusReportKey`) cannot fire in this state because the tiles are not rendered. If a stale `focusReportKey` ever runs and the server answers 400, the existing toast shows the server detail; no special handling.
- On a `tenantId` change `ReportsPanel` clears `result`, `activeKind`, `activeKey` and `page` so a report table from the previous tenant is never left on screen.

### 6. Out of scope (stated so nothing creeps in)

No Costs tab, no coverage banner, no per-asset cost table, no currency or FX choice, no export of cost data, no change to the Assets page, the Finance panel or the lifecycle pie. The API-key, tenant-isolation and 400/403 behaviours are server work and have no screen.

## Accessibility and Interaction Notes

- The tile stays one `<button>`; add `aria-describedby="itam-kpi-asset-value-summary"` so the figure and Valued line are announced alongside the existing `aria-label`. The figure `Not tracked` is real text (not an image or a CSS-only mark).
- The Select block is `role="status"` (polite): it explains an expected state, it is not an alert. `Go to Tenants` is a real `<button type="button">` with the global focus ring.
- Disabled Run buttons use the native `disabled` attribute plus `aria-describedby` to the visible reason line.
- No motion is added. Colour is never the only carrier of meaning (the `Not tracked` figure is words, the neutral gray only de-emphasises it).
- Touch target: unchanged for existing buttons; `Go to Tenants` has `py-2` so its hit area is at least 32px high.
- Security of rendered strings: every figure and count is a number formatted client-side; the only server string rendered is the existing report toast detail as plain text. No `dangerouslySetInnerHTML`.
- Idempotency: the tile request effect is guarded by the existing `cancelled` flag; a tenant change cancels the older request's result.
