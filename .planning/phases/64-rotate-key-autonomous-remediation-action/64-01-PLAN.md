<objective>
Prove the whole backend orchestration path for `rotate_key` end-to-end before a single line of agent Rust is written: an agent-shaped weak-SSH-key finding is ingested, routed to the new `rotate_key` playbook, and rendered into a fully-resolved agent instruction with a real fingerprint and a real authorized_keys path.

Purpose: RESEARCH.md's highest-confidence pitfall is that the YAML `match:` block is inert — `select_playbook()`'s hardcoded Python if/elif chain is the only real routing mechanism, so a plan that ships `rotate_key.yaml` alone produces a playbook that is never selected. A second, previously-unrecorded hazard was found while reading the shipped scanner: `vulnerability_scan.rs::secret_finding()` has emitted `playbook_ref: "rotate_key"` for `/etc/environment` secret findings since Phase 51 — routing on `playbook_ref` alone would dispatch a key rotation against `/etc/environment` with a null fingerprint. This plan closes both before anything downstream depends on them.

Output: `backend/playbooks/rotate_key.yaml`, the `ACTION_MAP` + `select_playbook()` edits, the `fingerprint` ingest field, and a hermetic wiring test that drives agent JSON -> ingest -> selection -> rendered dispatch params.
</objective>
