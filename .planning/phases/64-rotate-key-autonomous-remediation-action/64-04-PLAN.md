<objective>
Wire `rotate_key`'s already-proven rotation mechanics (plan 64-03) into the agent's instruction dispatcher, and fix the rollback playbook step shipped by plan 64-01, which references a finding field that is never populated and therefore cannot dispatch a working rollback.

Purpose: plan 64-03 built `rotate_in_place`/`rollback_rotation` as pure, hermetically-tested functions reachable from nothing. Plan 64-01 shipped a `rotate_key.yaml` playbook whose forward step already had nowhere to dispatch to (no `rotate_key` arm existed) and whose rollback step points at `restore_file` with a template variable (`finding.details.rotate_key_backup_path`) that no code anywhere in the ingest pipeline ever writes — confirmed by grep across `backend/*.py`. This plan closes both gaps: two new dispatch arms in `instructions.rs`, two new thin async wrapper functions in `remediation_actions.rs` (mirroring `restore_file`'s existing shape exactly), and a one-step correction to the rollback playbook YAML so it calls the arm that actually exists instead of one that was never reachable.

Output: `remediation_actions::rotate_key()` and `remediation_actions::rotate_key_rollback()`, two new `match` arms in `instructions.rs`, a corrected `rotate_key.yaml` rollback step, and an integration test proving both instruction shapes round-trip through the real dispatcher.
</objective>
