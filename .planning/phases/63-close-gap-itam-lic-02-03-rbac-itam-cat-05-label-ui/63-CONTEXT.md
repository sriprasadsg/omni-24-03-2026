<domain>
## Phase Boundary

Gap-closure phase against `.planning/milestones/v4.0-MILESTONE-AUDIT.md` (2026-08-11, status: gaps_found). Two independent, small, bounded fixes — no new capabilities, no new requirements, both features already fully specified and built on the backend during the v4.0 ITAM milestone (Phases 56-61):

1. **RBAC gap (ITAM-LIC-02/03, ITAM-UI-01):** `backend/itam_consumable_endpoints.py` and `backend/itam_component_endpoints.py` (both its `router` and `asset_components_router`) depend only on `get_current_user` — any authenticated user, any role, can hit them directly. All 7 sibling ITAM routers (catalog/asset/lifecycle/label/finance/license) correctly gate on `manage:assets` via `_require_itam_admin`. Fix: match the sibling pattern exactly.
2. **Unreachable UI gap (ITAM-CAT-05):** Phase 58 built and verified 3 offline label-generation routes (`GET /{asset_id}/label/qr`, `GET /{asset_id}/label/barcode`, `POST /labels/sheet`) with zero frontend callers — no Labels panel, no `apiService.ts` functions. Fix: wire a UI entry point into the existing `LifecyclePanel.tsx`.

</domain>

<decisions>
## Implementation Decisions

### Label UI Entry Point
- **D-01:** Add a "Label" action to the existing per-asset row action group in `components/itam/LifecyclePanel.tsx` (alongside the existing Check In / Check Out / Mark Audited text buttons, lines ~177-181) — not a new dedicated Labels tab/panel in `ITAMConsole.tsx`. Smallest change, matches the established per-row-action pattern exactly. — **Reversibility:** reversible — a UI placement choice; a dedicated tab could be added later without touching this decision's outcome.
- **D-02:** Clicking "Label" opens a small dropdown/menu with 3 items: "QR Code", "Barcode", "Label Sheet (this asset)" — each triggers its own direct download. One button, no extra modal component. — **Reversibility:** reversible.

### Single vs Bulk Scope
- **D-03:** This phase wires single-asset label generation only (QR, barcode, and a single-asset label sheet via the row menu). True multi-asset bulk printing (row checkboxes + a toolbar "Print Label Sheet (N selected)" button, fully exercising the backend's existing `MAX_LABEL_SHEET_ASSETS`-capped bulk capacity) is explicitly deferred — noted below under Deferred Ideas, not part of this phase's scope. — **Reversibility:** reversible — bulk selection can be added later as a pure UI addition; the backend endpoint is already bulk-capable and needs no changes either way.

### Download UX
- **D-04:** All 3 menu items trigger a direct browser download on click (matches the backend's existing `Content-Disposition: attachment` response headers) — no preview-first modal, no intermediate confirmation step. — **Reversibility:** reversible.

### RBAC Fix Scope
- **D-05:** Fix is scoped to exactly: swap `Depends(get_current_user)` → `Depends(_require_itam_admin)` (imported from `backend/itam_asset_endpoints.py`, same as the 7 sibling routers) on every route in `backend/itam_consumable_endpoints.py` and `backend/itam_component_endpoints.py` (both `router` and `asset_components_router`), plus a 403-for-non-admin regression test per router mirroring the existing sibling-router test pattern (e.g. `test_itam_license.py`'s RBAC test). — **Reversibility:** reversible.
- **D-06:** The milestone audit's separately-flagged tech debt — `manage:assets` (backend gate) vs `manage:itam`/`view:itam` (frontend nav gate) being distinct permission strings with no coupling test — stays out of scope for this phase. Not touched, not tested, left as tracked tech debt in `v4.0-MILESTONE-AUDIT.md`. — **Reversibility:** reversible — can be picked up in any future phase independently.

### Claude's Discretion (deferred to research/planning)
- Exact dropdown/menu implementation for D-02 — no existing dropdown/menu component exists anywhere in `components/` (confirmed via grep during discussion: zero `DropdownMenu`/`<Menu` matches, no `components/ui/*dropdown*` or `*menu*` files). Research/planning should decide between (a) a minimal local `useState`-toggled absolute-positioned panel (the standard lightweight React pattern for a one-off menu), or (b) a tiny 3-button inline group instead of a true dropdown, if that reads as more consistent with this codebase's existing lightweight row-action style than introducing a wholly new dropdown pattern for a single feature. Either satisfies D-02; pick whichever needs less new code.
- Whether `get_current_user` remains imported in `itam_consumable_endpoints.py`/`itam_component_endpoints.py` after the RBAC swap (only if still used elsewhere in either file, e.g. by a route this phase doesn't touch) — check during implementation, don't leave an unused import.
- Exact filename generated by the downloaded QR/barcode/sheet files in the frontend (the backend already sets `Content-Disposition` with a generated filename — frontend just needs to respect it, not invent its own).

</decisions>
