<objective>
Route the 365-day location-history retention decision (D-01) through the existing `/api/retention/*` module — the one CONTEXT.md D-01 refers to — by adding a real `cleanup_agent_location_history()` method AND wiring it into `run_cleanup()`, plus a `_POLICY_DEFAULTS` entry. Output: modified `retention_service.py` + `retention_endpoints.py`, and a real-cutoff integration test.

Retention-enforcement-trigger decision (locked by this plan, per D-01/RESEARCH § Retention Module Integration): match the existing module's precedent — **manual/admin-triggered enforcement via `POST /api/retention/run`**, no new background scheduler. An automatic sweep (raw `mongodb.db`, cloned from `compliance_remediation_sla_service`) is noted as a deferred follow-up, NOT built here — building it would be scope expansion beyond "route through the existing module."
</objective>
