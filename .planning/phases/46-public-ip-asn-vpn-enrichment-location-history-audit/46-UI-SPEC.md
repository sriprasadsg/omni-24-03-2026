# Phase 46 — UI Design Contract

> Visual and interaction contract for the GAUD-02 location-history timeline. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Scope lock:** The ONLY new frontend surface in this phase is the `AgentLocationHistory` panel (a read-only, append-only timeline of an agent's public-IP/geo changes) mounted in the agent detail view. No map, no charts, no geo-fence UI — those belong to Phases 47–49. Every design token below is inherited from the existing codebase (no new palette, no new font, no new component library); this document exists to lock the *specific* layout/copy/state contract for one panel, not to introduce new visual language.

## Color

Inherited from the existing slate/gray Tailwind palette — no new hex values introduced. This panel reuses the exact class strings from `EscalationHistoryPanel.tsx` and the existing amber "heuristic/caution" badge pattern already used for the `Quarantined` agent-status badge in `AgentList.tsx`.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `bg-white` / `dark:bg-gray-800` | Panel body background |
| Secondary (30%) | `bg-gray-100` / `dark:bg-gray-700/50` | Panel header (collapsed/expanded toggle bar) |
| Accent (10%) | `text-primary-500` / `dark:text-primary-400` | Reserved ONLY for the location-pin/globe icon in each row's leading position — never used elsewhere in this panel |
| Destructive | N/A | This panel has zero destructive actions (D-10: read-only, no edit/delete) — no destructive color token is used anywhere in this component |

**VPN/hosting heuristic badge color (specific, locked):** `bg-amber-100 text-amber-800 dark:bg-amber-900/50 dark:text-amber-300` — the exact existing "Quarantined" badge treatment from `AgentList.tsx`'s `statusInfo`. Muted amber, never red — this is a deliberate signal that the flag is a heuristic caution, not an alarm. **Never use `red`/`bg-red-*` for this badge under any circumstance** — that visual vocabulary is reserved elsewhere in this codebase for `Error` agent status and destructive actions, and using it here would misrepresent an unlicensed heuristic as an authoritative security detection.

Accent reserved for: the single leading `GlobeIcon` per timeline row. Nothing else in this panel uses accent color — badges use amber (heuristic caution), text uses gray/slate only.

|---------|------|

| Primary CTA | None — this is a read-only viewer panel with no primary action button. The only interaction is the expand/collapse toggle on the header row itself. |
| Empty state heading | None (single-line empty state, matches `EscalationHistoryPanel`'s pattern of no separate heading) |
| Empty state body | `No location changes recorded for this agent.` — italic, centered, `text-xs text-gray-400`, `px-4 py-6` |
| Error state | `Failed to load location history. Retry by collapsing and expanding this panel.` — `text-xs text-red-500`, `px-4 py-4` (this is the ONLY place red appears in this panel — a genuine fetch failure, not the VPN badge) |
| Loading state | No text — existing spinning-circle SVG clone (`animate-spin`, `text-gray-400`, `h-4 w-4`), centered, `py-4` |
| VPN/hosting badge label | `likely VPN/hosting` — lowercase-led, exact wording. **Never** "VPN detected", "Detected VPN", "VPN/Proxy Detected", or any phrasing implying authoritative detection (GSEC-01/D-09 constraint: this is a free heuristic feed, not a licensed anonymizer classification). |
| Dwell time format | Human-readable, largest-two-units only, computed client-side at read time (never stored per-row — see Behavior Contract below): `< 1 min` → `just arrived`; `< 1 hour` → `{N}m`; `< 1 day` → `{N}h {N}m`; `>= 1 day` → `{N}d {N}h`. Most recent (current) row is computed as `now - timestamp` and additionally suffixed with ` (ongoing)` — e.g. `2d 4h (ongoing)` — to signal this is the agent's current location, not a closed interval. |
| Destructive confirmation | N/A — no destructive action exists on this panel (D-10 lock: append-only, no edit/delete anywhere in the UI, matching the API having no PATCH/PUT/DELETE route) |
| Accessibility label (toggle) | `Expand location history panel` / `Collapse location history panel` — exact clone of `EscalationHistoryPanel`'s `aria-label` pattern, substituting "escalation" → "location" |

## Component Contract — `AgentLocationHistory.tsx`

### Mount Point (locked decision)

**Locked: embed inside `AgentOverviewTab.tsx`'s Overview tab**, NOT as a new seventh modal tab.

**Rationale:** D-08 says "same shape/placement as the existing `EscalationHistoryPanel` in `RemediationTaskModal`" — literally, that is a single collapsible panel embedded directly in a view, not a tab. `AgentDetailModal.tsx` is tab-based (`overview | runtime | compliance | health | software | patching | instructions`) while `RemediationTaskModal` (the D-08 reference) has no tabs at all — the closest honest translation of "same shape/placement" into a tabbed modal is: pick the single most relevant existing tab (Overview — where `agent.publicIp`/`agent.geo` conceptually live) and embed the panel there as a collapsible block, exactly like `EscalationHistoryPanel` is embedded directly in `RemediationTaskModal`'s single view. Adding a whole new tab for one panel would over-scope this phase and contradicts the "clone the panel, not the tab structure" instruction.

**Exact insertion point:** Directly after the existing `<dl>` block's final `DetailRow` (`Tenant`, ends at `AgentOverviewTab.tsx:210`) and before the `Performance Metrics` `pt-4 border-t` section (`AgentOverviewTab.tsx:213`). Wrap in the same `pt-4 border-t border-gray-200 dark:border-gray-700` spacing rhythm used by every other section in this tab, so the panel's outer margin is consistent with its siblings — but the panel's own internal chrome (header bar + body) must remain the `EscalationHistoryPanel` clone, not the `h3 + border-t` pattern used by "Performance Metrics"/"Remediation History" (those are a different, non-collapsible section style; D-08 specifically locks the collapsible-panel shape).

**Note (non-blocking, informational only):** `AgentOverviewTab.tsx` currently does not render `agent.publicIp`/`agent.geo` at all (those fields only appear on the `AgentList.tsx` card view today). This phase is not required to add them to the Overview tab — GAUD-02 only requires the history timeline. Flagging this as a pre-existing display gap for awareness, not a task for this phase.

### Layout / Structure

Identical two-part shape to `EscalationHistoryPanel.tsx`:

1. **Header bar** (always visible, clickable, `role="button"`, keyboard-operable via Enter/Space):
   - `flex items-center justify-between px-4 py-2 bg-gray-100 dark:bg-gray-700/50 rounded-t-md border border-gray-200 dark:border-gray-700`
   - Left: `HistoryIcon size={14}` + `Location History` (`text-sm font-semibold`) + `({N} locations)` (`text-xs font-normal text-gray-400`)
   - Right: `ChevronDownIcon size={14}`, rotates 180° when expanded (`transition-transform`)

2. **Body** (rendered only when expanded, lazy-fetched on first expand — never refetched on subsequent toggles within the same modal session):
   - `border border-t-0 border-gray-200 dark:border-gray-700 rounded-b-md divide-y divide-gray-100 dark:divide-gray-700/50 bg-white dark:bg-gray-800`
   - One of: loading spinner / error message / empty-state message / row list (mutually exclusive, exact same conditional structure as `EscalationHistoryPanel`)

### Single Row Anatomy (D-09 field set, locked order)

Each row: `px-4 py-3`, `flex items-start gap-2` (icon left, content right — clone of the escalation row shape):

```
[GlobeIcon 14px, text-primary-500/dark:text-primary-400, mt-0.5]
  Line 1:  🇺🇸 San Francisco, CA, United States          [likely VPN/hosting]  <- badge only if vpn_heuristic===true
           (text-xs font-semibold text-gray-800 dark:text-gray-200)  (badge: bg-amber-100 text-amber-800
                                                                       dark:bg-amber-900/50 dark:text-amber-300
                                                                       text-[11px] font-bold px-2 py-0.5
                                                                       rounded-full uppercase tracking-wide
                                                                       ml-2 inline-flex items-center gap-1,
                                                                       ships with a small WifiIcon size={10})
  Line 2:  203.0.113.42 · Jul 24, 2026 3:12 PM UTC · 2d 4h (ongoing)
           (text-xs text-gray-400 dark:text-gray-500 mt-0.5, IP segment in font-mono)
```

Field order (left to right / top to bottom), exactly per D-09: country flag + city/country → VPN/hosting badge (conditional) → public IP (monospace) → timestamp (UTC, same `toLocaleString` format as `formatEscalationTimestamp` in `EscalationHistoryPanel.tsx`) → dwell time.

- Flag: reuse `flagEmoji(geo.country_code)` from `AgentList.tsx` (already exported as a local const there — extract to a shared util e.g. `utils/geo.ts` if both files need it; do not duplicate the emoji math).
- City/country string: reuse `formatGeo(geo)` from `AgentList.tsx` (same extraction note).
- Public IP: `font-mono`, no truncation (IPv4/IPv6 both short enough to always fit at this width).
- No row is ever interactive (no click handler, no hover affordance beyond the default panel background) — D-10 read-only lock applies at the row level too, not just "no edit/delete button."

### States

| State | Trigger | Visual |
|-------|---------|--------|
| Collapsed (default) | Panel mounted, not yet expanded | Header bar only, `rounded-md` (no separate top/bottom radius since body is absent) |
| Loading | First expand, fetch in-flight | Body shows centered spinner only, `py-4`, no rows/header text change |
| Loaded — has entries | Fetch succeeded, `entries.length > 0` | Row list, sorted chronological ascending (oldest first, matches `EscalationHistoryPanel`'s `.sort("created_at", 1)` / `created_at ascending` convention) — most recent entry is the LAST row and carries the `(ongoing)` dwell suffix |
| Loaded — empty | Fetch succeeded, `entries.length === 0` | Centered italic empty-state copy, no header count change beyond `(0 locations)` |
| Error | Fetch threw/rejected | Left-aligned red error text, panel remains expanded so the user can read the message before retrying via collapse/expand |
| Fully offline agent, no `publicIp` ever recorded | `entries` empty AND agent has never had a `publicIp` | Same as "Loaded — empty" — no special-cased copy variant; do not invent a second empty-state message for this sub-case, it adds complexity GAUD-02 doesn't require |

### Behavior Contract (non-visual, load-bearing for the executor)

- **Read-only, always.** No button, menu, or context action anywhere in this component may write/edit/delete a location-history entry — there is no backend route to call even if one were added (D-10).
- **Lazy fetch on first expand only** (`fetched` boolean guard), exact clone of `EscalationHistoryPanel`'s `handleToggle` logic — do not fetch on mount, do not refetch on every re-expand.
- **Dwell time is computed client-side at render time, never trusted from a stored field** — for row `i` (ascending order), `dwell = timestamp(i+1) - timestamp(i)`; for the last row, `dwell = now - timestamp(last)` (research Pitfall 2). If the backend response ever includes a `dwell_seconds`-shaped field, ignore it — this is a deliberate anti-pattern guard, not an oversight.
- **VPN badge renders only when `entry.vpn_heuristic === true`** — absence of the field or `false` renders no badge at all (no "not VPN" negative-state badge; absence of a badge IS the negative state, keeping rows visually quiet for the common case).
