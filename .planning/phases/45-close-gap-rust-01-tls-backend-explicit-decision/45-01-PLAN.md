<objective>
Close the RUST-01 gap flagged by the v3.2 milestone audit (D-01): reqwest in `agent-install/omni-agent-rs/Cargo.toml` lists `native-tls` but leaves `default-features` ON, so reqwest's `default-tls = ["rustls"]` still compiles the full rustls/aws-lc-rs stack into the shipped `omni-agent-2.1.3-windows.exe` alongside native-tls. Make the TLS backend a single explicit choice (native-tls only), rebuild the 2.1.3 executable in place (no version bump per D-01 — 2.1.3 was never distributed), and prove rustls is gone via `strings`.

Purpose: Eliminate the implicit reqwest-internal `TlsBackend::default()` fallback that would silently flip to rustls if a future dep bump enables `http3`, and shrink the supply-chain/CVE surface by removing the dead rustls+aws-lc-rs crypto stack from every shipped endpoint.
Output: Fixed Cargo.toml (single TLS backend, documented) + rebuilt in-place 2.1.3 Windows exe with rustls excluded.
</objective>

| T-45-02 | Information Disclosure / supply chain | dead rustls + aws-lc-rs crypto stack compiled into shipped exe | mitigate | Exclude `default-tls`/rustls entirely so no unused-but-CVE-bearing crypto code ships to endpoints; proven absent via `strings` |
