Layer 1 — `backend/itam_label_service.py` (new, pure): module docstring stating this module holds the offline label-rendering primitives for ITAM-CAT-05 and deliberately imports neither FastAPI nor `database`, so every function is unit-testable without an app or a DB. Imports limited to `io`, `qrcode`. Define `QR_BOX_SIZE = 10` and `QR_BORDER = 4` as module constants (same values `mfa_service.generate_qr_base64` uses). Define `class LabelEncodingError(ValueError)` — the single typed error this module raises when a tag cannot be rendered, so the endpoint layer has one thing to catch and map to 400 rather than catching bare `Exception`. Define `generate_qr_png(asset_tag: str) -> bytes`: raise `LabelEncodingError` when `asset_tag` is falsy or is not a `str`; otherwise build `qrcode.QRCode(version=1, box_size=QR_BOX_SIZE, border=QR_BORDER)`, `add_data(asset_tag)` with the bare tag string exactly as given per D-02 (no URL prefix, no JSON wrapper, no tenant or asset id mixed in), `make(fit=True)`, `make_image(fill_color="black", back_color="white")`, save into a fresh `io.BytesIO` with `format="PNG"`, and return `buf.getvalue()`. Unlike `mfa_service.generate_qr_base64` this function must never swallow an exception and return an empty result — a failed render has to be visible to the caller, because a silently blank PNG would be printed and stuck on hardware.

Layer 2 — `backend/itam_label_endpoints.py` (new, router): module docstring following `itam_lifecycle_endpoints.py`'s precedent — state that this router shares the `/api/assets` prefix with `asset_endpoints.py`, `itam_asset_endpoints.py` and `itam_lifecycle_endpoints.py`; that its routes are `GET /{asset_id}/label/qr` (this plan), `GET /{asset_id}/label/barcode` and `POST /labels/sheet` (later plans); that all are multi-segment and none can be shadowed by or shadow `asset_endpoints.py`'s single-segment `GET /{asset_id}` under any registration order; and that it reuses `_require_itam_admin` from `itam_asset_endpoints` rather than redefining the manage:assets gate. Every `Content-Disposition` header this router emits must pass its tag through this helper — an `assetTag` is a caller-suppliable string (see `ManualAssetCreate.assetTag`), so an unfiltered tag reaching a response header is a response-splitting vector (T-58-05).

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client → `/api/assets/{asset_id}/label/qr` | Untrusted `asset_id` path parameter and an authenticated but not-yet-authorized caller cross here. |
| asset document → response header | `assetTag` is a caller-suppliable string (`ManualAssetCreate.assetTag`) that reaches a `Content-Disposition` header. |
| asset document → `qrcode` encoder | Caller-suppliable tag text reaches a third-party rendering library. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-58-01 | Information Disclosure | `_load_asset_for_label` in `itam_label_endpoints.py` | high | mitigate | Lookup goes only through `get_database()`'s `TenantIsolatedDatabase`, which injects the caller's `tenantId`; a cross-tenant id resolves to nothing and yields a 404 byte-identical to the unknown-id 404. Pinned by `TestQrLabelTenantIsolation`. |
| T-58-04 | Elevation of Privilege | `GET /{asset_id}/label/qr` | high | mitigate | `Depends(_require_itam_admin)` imported from `itam_asset_endpoints`, not redefined. Pinned by `TestQrLabelRbac` asserting 403 when `verify_permission` denies. |
| T-58-05 | Tampering | `Content-Disposition` header construction | high | mitigate | `_safe_filename_part` maps every character outside `[A-Za-z0-9._-]` to `_` and caps length at 64 before the tag enters the header, so a tag carrying header-control characters cannot split the response. Pinned by the filename test in `TestQrLabelTenantIsolation`. |
| T-58-02 | Denial of Service | `generate_qr_png` | medium | mitigate | An unencodable or empty tag raises the typed `LabelEncodingError`, which the route maps to 400 — a library error never bubbles out as an unhandled 500. Pinned by `TestQrPayloadFidelity` and `TestQrLabelMissingTag`. |
| T-58-06 | Information Disclosure | logging in `itam_label_endpoints.py` | low | accept | The route logs no asset field values; the module-level logger is used only for unexpected failures. Accepted without a dedicated test because no asset data is written to a log line on any path in this plan. |
