# Phase 12 — Plan 01: Agentic AI Service — Backend TDD

## Goal

Wire Claude (claude-sonnet-4-6) tool-calling into the agentic_poller → agentic-tasks backend path via a new `agentic_service.py` and `agentic_tasks_endpoints.py`. Tests are written RED first against the public contracts of both modules, then the implementation is written to make them pass (GREEN). No real Anthropic API is called in tests — `AsyncAnthropic.messages.create` is mocked throughout.

## Context

**What exists:**
- `backend/circuit_breaker.py` — `CircuitBreaker` class; `CircuitBreakerOpen` exception; pre-built `ai_breaker` at line 99 (separate key `"agentic_ai"` required per research)
- `backend/agent_tasks_endpoints.py` — primary pattern: `APIRouter(prefix="/api/agents")`, `verify_agent_key` Depends, `Body(...)`, `get_database()` inline
- `backend/tests/test_core_endpoints.py` — test pattern: synchronous `TestClient`, `_db()` / `_col()` helpers returning `MagicMock` + `AsyncMock`; no pytest-asyncio
- `backend/router_registry.py` line 136–151 — AI & Data Science section where new `_load()` call goes
- `backend/database.py` — `connect_to_mongo()` creates indexes after line 302; `TenantIsolatedCollection` auto-injects `tenantId` on writes

**What is missing (to be created):**
- `backend/agentic_service.py` — new file
- `backend/agentic_tasks_endpoints.py` — new file
- `backend/tests/test_agentic_ai.py` — new file
- `agent_ai_decisions` indexes in `database.py`
- Router registration line in `router_registry.py`

**Critical constraints:**
- `AnthropicProvider` in `ai_providers.py` is NOT modified (F-01)
- Circuit-breaker key must be `"agentic_ai"` not `"ai"` (avoids cross-contamination with `ai_breaker`)
- `_log_decision()` is async and called with `await` directly inside `AgenticService.run()` (not via BackgroundTasks) — keeps audit write in the same request cycle per AI-SPEC Section 4 State Management
- FastAPI route ordering: register `/decisions` and `/trigger` static suffixes BEFORE `/{task_id}/result` to prevent path collision (F-03 Pitfall 1)
- `TenantIsolatedCollection.insert_one()` auto-injects `tenantId`; do NOT set `doc["tenantId"]` manually (Pitfall 2)
- `tool_choice={"type": "any"}` (not `"auto"`) — guarantees `stop_reason="tool_use"` on Turn 1

**agentic_service.py** — implement in this exact order:

1. Imports: `copy`, `datetime`, `json`, `logging`, `os`, `uuid`, `asyncio`; from `anthropic` import `AsyncAnthropic`; from `anthropic.types` import `ToolUseBlock`; from `pydantic` import `BaseModel`, `field_validator`, `ValidationError`; from `typing` import `Literal`, `Callable`, `Awaitable`; from `circuit_breaker` import `CircuitBreaker`, `CircuitBreakerOpen`; from `database` import `get_database`.

2. Module-level logger: `logger = logging.getLogger(__name__)`.

3. `agentic_breaker = CircuitBreaker("agentic_ai", failure_threshold=3, recovery_timeout=60)` — key must be `"agentic_ai"` per research F-06 / AI-SPEC cross-contamination constraint.

4. `TOOLS: list[dict]` — copy the five tool dicts verbatim from AI-SPEC Section 3: `run_compliance_check`, `run_vulnerability_scan`, `run_threat_hunt`, `run_persistence_scan`, `collect_processes`. Each must have `name`, `description`, `input_schema` (JSON Schema object). Do not abbreviate.

5. `SYSTEM_PROMPT: str` — copy verbatim from AI-SPEC Section 3. Static string; no f-string interpolation.

6. `AgenticDecision(BaseModel)` — Pydantic model with fields: `tool_name: Literal["run_compliance_check", "run_vulnerability_scan", "run_threat_hunt", "run_persistence_scan", "collect_processes"]`; `agent_id: str`; `framework: Literal["CIS", "NIST", "ISO27001"] | None = None`; `severity_threshold: Literal["low", "medium", "high", "critical"] | None = None`; `hunt_profile: Literal["lateral_movement", "credential_access", "persistence", "exfiltration"] | None = None`; `include_network: bool = False`. Add `@field_validator("agent_id")` that rejects empty/whitespace strings.

7. `TOOL_REGISTRY: dict[str, Callable[..., Awaitable[dict]]]` — maps each of the five tool names to a private async dispatcher. Each dispatcher writes an `agent_instructions` document to MongoDB (via `get_database().agent_instructions.insert_one`) with `type` set to the tool name and `payload` containing the tool input kwargs, then returns `{"status": "queued", "tool": tool_name}`. This enqueues the capability for the Rust agent to pick up on its next instruction poll cycle (the same channel as `agent_tasks_endpoints.py` uses).

8. `def truncate_security_context(ctx: dict, max_findings: int = 20) -> dict` — implement per AI-SPEC Section 4b.4: deepcopy ctx; sort `ctx["findings"]` by `severity_score` descending, keep top `max_findings`; keep top 30 `processes`; keep top 5 `alerts`; strip `raw_evidence` and `pcap_base64` keys from each finding; if `estimate_tokens(c) > 3000` log warning and reduce to `{"agent_id": ..., "findings": c["findings"][:10]}`.

9. `def estimate_tokens(obj: dict) -> int` — return `len(json.dumps(obj)) // 4`.

10. `async def decide_and_execute(agent_id: str, security_context: dict, client: AsyncAnthropic) -> dict` — implement the two-turn loop per AI-SPEC Section 3 entry point pattern:
    - Turn 1: `await client.messages.create(model="claude-sonnet-4-6", max_tokens=1024, temperature=0, system=SYSTEM_PROMPT, tools=TOOLS, tool_choice={"type": "any"}, messages=[{"role": "user", "content": user_message}])`. Assert `stop_reason == "tool_use"` else raise `RuntimeError`.
    - Extract `ToolUseBlock` from `response.content` where `b.type == "tool_use"`.
    - Build `raw_input = {**tool_use_block.input, "tool_name": tool_use_block.name}`.
    - Validate: `decision = AgenticDecision.model_validate(raw_input)` — on `ValidationError`, log at WARNING and raise `ValueError` (triggers fallback at caller).
    - Guard: if `decision.tool_name not in TOOL_REGISTRY` raise `ValueError`.
    - Execute: `tool_result = await TOOL_REGISTRY[decision.tool_name](**decision.model_dump(exclude={"tool_name"}, exclude_none=True))`.
    - Turn 2: send tool_result back, get rationale text. Use `tool_use_block.id` exactly for the `tool_use_id` in the `tool_result` content block.
    - Return dict with `tool_name`, `tool_input`, `tool_result`, `rationale`, `tool_use_id`, `source="agentic_ai"`.

11. `async def _rule_based_fallback(agent_id: str, security_context: dict) -> dict` — select `collect_processes` as the default safe fallback tool, call its dispatcher, return dict with `tool_name="collect_processes"`, `tool_input={"agent_id": agent_id}`, `rationale="rule_based_fallback"`, `source="rule_based_fallback"`.

12. `class AgenticService` — `__init__(self, api_key: str)` creates `self._client = AsyncAnthropic(api_key=api_key, max_retries=2, timeout=30.0)`. `async def run(self, agent_id: str, security_context: dict) -> dict`: generate `decision_id = str(uuid.uuid4())`, `started_at = datetime.datetime.utcnow()`, call `truncate_security_context()`, then `async with agentic_breaker: result = await decide_and_execute(...)`. On `CircuitBreakerOpen` or any other `Exception`, log at WARNING/ERROR, call `await _rule_based_fallback(...)`, set `result["source"] = "rule_based_fallback"`. Always call `await self._log_decision(decision_id, agent_id, result, started_at)` before returning `result`. `async def _log_decision(self, decision_id, agent_id, result, started_at)`: get db, construct doc with all required fields (`_id`, `agent_id`, `tool_name`, `tool_input`, `rationale`, `model="claude-sonnet-4-6"`, `started_at`, `completed_at`, `source`), call `await db.agent_ai_decisions.insert_one(doc)` in try/except — on exception log `"AUDIT WRITE FAILURE"` at ERROR level; never re-raise from `_log_decision`.

13. Module-level singleton: `_service: AgenticService | None = None` and `def get_agentic_service() -> AgenticService` that reads `ANTHROPIC_API_KEY` from env (raises `RuntimeError` if unset), creates and caches `_service`.

**agentic_tasks_endpoints.py** — create with:

Router: `APIRouter(prefix="/api/agents", tags=["Agentic AI"])`.

Route ordering (CRITICAL — static suffixes before parameterized):
1. `GET /{agent_id}/agentic-tasks` — `verify_agent_key` Depends. Inline: get db, look up the agent's pending agentic task (query `agent_tasks` where `agent_id=agent_id` and `status="pending"` and `type` in the five tool names). If none pending, assemble `security_context` from db (`findings`, `alerts`, `processes` via `find().to_list()`), call `svc = get_agentic_service(); result = await svc.run(agent_id, security_context)`, create an `agent_tasks` document with `id=str(uuid.uuid4())`, `type=result["tool_name"]`, `agent_id=agent_id`, `status="pending"`, and return `[{"id": task_doc_id, "type": result["tool_name"], "context": result.get("tool_input", {})}]`. If db unavailable return `[]`.
2. `GET /{agent_id}/agentic-tasks/decisions` — `get_current_user` Depends. Query `agent_ai_decisions` sorted by `started_at` desc, limit 50, return `{"decisions": [...]}`.
3. `POST /{agent_id}/agentic-tasks/trigger` — `get_current_user` Depends. Assemble security_context, call `svc.run()`, return result dict.
4. `POST /{agent_id}/agentic-tasks/{task_id}/result` — `verify_agent_key` Depends, `result: Dict[str, Any] = Body(...)`. Update `agent_ai_decisions` where `_id` matches the decision linked to this task, set `result` and `result_at` fields. Return `{"status": "ok"}`.

<threat_model>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Rust agent → GET /agentic-tasks | Agent-authenticated (verify_agent_key); agent_id in path must match token's tenant context |
| Rust agent → POST /agentic-tasks/{task_id}/result | Agent-authenticated; task_id must belong to the same tenant |
| Backend → Anthropic API | Outbound TLS; API key in env var, never in logs or responses |
| Agent-supplied security context → LLM system prompt | Dynamic data is placed only in the user message JSON block, never interpolated into SYSTEM_PROMPT |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation |
|-----------|----------|-----------|-------------|------------|
| T-12-01 | Tampering | SYSTEM_PROMPT + user message | mitigate | Dynamic agent context (process names, file paths, alert titles) placed in user message JSON only; SYSTEM_PROMPT is a module-level string constant with no f-string interpolation — per AI-SPEC Section 4b.3 |
| T-12-02 | Tampering | TOOL_REGISTRY dispatch | mitigate | `AgenticDecision.model_validate()` enforces Literal enum on tool_name before dispatch; `tool_name not in TOOL_REGISTRY` guard raises ValueError as second layer |
| T-12-03 | Repudiation | agent_ai_decisions write | mitigate | `_log_decision()` logs at ERROR on write failure and never suppresses silently; `"AUDIT WRITE FAILURE"` in log message is grep-able for alerting |
| T-12-04 | Elevation of Privilege | GET /agentic-tasks | mitigate | `verify_agent_key` Depends on all Rust-agent-facing endpoints; agent can only fetch tasks for its own agent_id (enforced by token's tenant scope) |
| T-12-05 | Information Disclosure | agent_ai_decisions tenant isolation | mitigate | `TenantIsolatedCollection` auto-injects tenantId on all writes; `_log_decision()` does NOT manually set tenantId to avoid double-injection (Pitfall 2 from RESEARCH.md) |
| T-12-06 | Denial of Service | Anthropic API latency / outage | mitigate | `CircuitBreaker("agentic_ai", failure_threshold=3, recovery_timeout=60)` opens after 3 consecutive failures; rule-based fallback serves the polling agent without blocking |
| T-12-SC | Tampering | (no new package installs in Phase 12) | accept | anthropic 0.111.0 already installed and verified; no new pip installs required |
