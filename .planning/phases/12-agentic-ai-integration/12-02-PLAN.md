# Phase 12 — Plan 02: Eval Harness and Arize Phoenix Tracing

## Goal

Equip the agentic AI path (built in Plan 01) with two observability layers:

1. **Arize Phoenix tracing** — `AnthropicInstrumentor().instrument()` called once at startup auto-traces every `AsyncAnthropic.messages.create()` call with token counts, latency, and content. Wired into `app_startup.py` as `init_agentic_tracing()`, wrapped in try/except so a missing Phoenix server does not abort startup.

2. **Promptfoo eval harness** — a `promptfooconfig.yaml` that defines the Phase 12 provider (claude-sonnet-4-6 + SYSTEM_PROMPT + TOOLS) and 5 reference test fixtures covering the 5 critical-path tool selections. Each fixture asserts the expected `tool_name`. The config can run locally against a live key or be skipped in CI via `PROMPTFOO_SKIP_EVAL=1`.

This plan depends on 12-01 completing successfully. The new files do not modify any of Plan 01's source files (no wave conflict).

**backend/app_startup.py** — add `init_agentic_tracing()` as a new module-level function. Place it before `run_startup_services()`:

```python
def init_agentic_tracing() -> None:
    """Wire Arize Phoenix OpenTelemetry tracing for AsyncAnthropic calls.

    Called once at startup. If Phoenix is unreachable or packages are missing,
    logs a warning and returns — never raises to the caller.
    """
    try:
        from opentelemetry import trace
        from opentelemetry.sdk.trace import TracerProvider
        from opentelemetry.sdk.trace.export import BatchSpanProcessor
        from opentelemetry.exporter.otlp.proto.http.trace_exporter import OTLPSpanExporter
        from openinference.instrumentation.anthropic import AnthropicInstrumentor

        endpoint = os.getenv("PHOENIX_OTLP_ENDPOINT", "http://localhost:4317")
        provider = TracerProvider()
        provider.add_span_processor(
            BatchSpanProcessor(OTLPSpanExporter(endpoint=endpoint))
        )
        trace.set_tracer_provider(provider)
        AnthropicInstrumentor().instrument()
        logger.info("[AgenticTracing] Phoenix tracing active at %s", endpoint)
    except ImportError:
        logger.warning(
            "[AgenticTracing] openinference-instrumentation-anthropic not installed — "
            "agentic LLM calls will not be traced. Run: pip install arize-phoenix "
            "openinference-instrumentation-anthropic opentelemetry-exporter-otlp-proto-http"
        )
    except Exception as exc:
        logger.warning("[AgenticTracing] Failed to initialise tracing: %s", exc)
```

Then call `init_agentic_tracing()` inside `run_startup_services()`, after any existing startup calls, inside its own try/except block matching the pattern already in `run_startup_services()`:

```python
try:
    init_agentic_tracing()
except Exception as exc:
    logger.warning("[Startup] Agentic tracing init failed (non-fatal): %s", exc)
```

Do NOT import `opentelemetry` or `openinference` at module level — keep them inside the function body so that missing packages do not prevent the module from loading in environments where the tracing dependencies are not installed.

Write each fixture with a plausible signal that clearly warrants the expected tool:

- **no_recent_processes.json** — `processes` is empty, `last_compliance_run` and `last_vuln_scan` both within 12h, `findings` empty, `alerts` empty, `last_process_snapshot` set to 25 hours ago. Expected: `collect_processes`.

Use `datetime.utcnow() - timedelta(hours=N)` values at the time of writing, formatted as ISO8601 strings. Hardcode specific UTC timestamps so the fixtures are stable (not time-relative).

**promptfooconfig.yaml** — create at `.planning/phases/12-agentic-ai-integration/promptfooconfig.yaml`:

The config must define:
1. `providers` — one entry for `anthropic:claude-sonnet-4-6` with model parameters matching Phase 12: `temperature: 0`, `max_tokens: 1024`. Supply the SYSTEM_PROMPT inline under `config.systemPrompt`. Supply all 5 TOOLS definitions inline under `config.tools`. Set `config.tool_choice: {type: any}`.

2. `prompts` — one template string that formats the user message: `"Security context for agent {{agent_id}}:\n{{security_context_json}}\n\nSelect the most impactful security tool to run now."` where `{{agent_id}}` and `{{security_context_json}}` are injected from each test's `vars`.

3. `defaultTest.assert` — a JavaScript assertion that checks the response tool name:
   ```yaml
   - type: javascript
     value: |
       const VALID_TOOLS = [
         'run_compliance_check', 'run_vulnerability_scan',
         'run_threat_hunt', 'run_persistence_scan', 'collect_processes'
       ];
       const toolName = output?.tool_use?.name || output?.content?.find?.(b => b.type === 'tool_use')?.name;
       return VALID_TOOLS.includes(toolName);
     threshold: 1.0
   ```

4. `tests` — 5 entries, one per fixture, each with:
   - `description`: human-readable name
   - `vars.agent_id`: `"agt-fixture-01"` (or matching fixture agent_id)
   - `vars.security_context_json`: loaded inline as a YAML block scalar (use `|` block) with the fixture JSON content embedded, OR reference the fixture file path
   - `assert`: specific check that `output` contains the expected `tool_name`:
     ```yaml
     - type: javascript
       value: |
         const toolName = output?.tool_use?.name
           || output?.content?.find?.(b => b.type === 'tool_use')?.name;
         return toolName === '{{expected_tool}}';
     ```
   - `metadata.expected_tool`: the expected tool name string

5. `commandLineOptions` — set `failureThreshold: 0.85` so CI fails if fewer than 85% of tests pass.

Include a comment block at the top of the YAML explaining:
- How to run locally: `npx promptfoo eval --config .planning/phases/12-agentic-ai-integration/promptfooconfig.yaml`
- How to skip in CI without an API key: `PROMPTFOO_SKIP_EVAL=1 npx promptfoo eval ...` or add a CI condition checking for `ANTHROPIC_API_KEY`
- The reference dataset size target (28 examples per AI-SPEC Section 5); these 5 are the critical-path subset
