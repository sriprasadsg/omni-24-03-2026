<objective>
Implement the background SLA sweep that turns a breached due_date into an auto-escalation with zero operator action: compute status per task, tier the escalation_level (D-04), persist the SLA fields on the task, append an immutable entry to the new `remediation_escalations` collection, and notify the resolved assignee plus all tenant admins in-app (D-03). Register the scheduler in `app_startup.py` using raw `mongodb.db`.

Purpose: This delivers SLA-01's "breach triggers an escalation notification without operator action" and Success Criterion 2. It is the single highest-pitfall surface in the phase (raw-db requirement, assignee resolution, tenant-admin lookup).
Output: `run_sla_pass()` + `start_remediation_sla_scheduler()` + escalation/notification helpers in the service file; the scheduler wired into startup.
</objective>

| background task → db | Sweep runs with no tenant contextvar; must extract tenantId per-doc and use raw db |
| task.assignee (free text) → notification recipient | Untrusted free-text field must be resolved to a real user before use as a recipient |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-44-03 | Tampering | sweep processing a malformed doc with no tenantId | mitigate | `if not tenant_id: continue` before any escalation/notification logic |
| T-44-04 | Spoofing | notification recipient injection via unresolved/agent-type assignee free-text | mitigate | resolve assignee against db.users (email→id→username) before send_alert; skip assignee on agent-type/unresolved, never pass raw free-text as an email |
| T-44-05 | Information Disclosure | escalation dispatched against wrong tenant's task | mitigate | all $set/insert/admin-lookup scoped by the per-doc extracted tenantId |
| T-44-SC | Tampering | dependency installs | accept | this phase installs no packages |
</threat_model>
