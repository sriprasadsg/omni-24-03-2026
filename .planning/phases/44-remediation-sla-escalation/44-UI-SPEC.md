# Phase 44 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Scope reminder:** this phase makes exactly two frontend additions to already-styled, existing components — no new page, no new design tokens. Everything below is either cloned verbatim from an existing pattern or a minimal, prescriptive extension of one.

1. `components/RemediationDashboard.tsx` — new `SLA` column + colored status pill in the existing task table (clone `STATUS_COLORS` pattern, lines 9-14 / 191-194).
2. `components/RemediationTaskModal.tsx` — new "Escalation History" panel (clone `components/ChainOfCustodyPanel.tsx`'s lazy-expand-on-toggle structure), rendered only when editing an existing task, placed after the Ticketing block and before the footer buttons.
3. (Discretionary, only if planner confirms a Settings surface is in scope) — a small "Remediation SLA" threshold field, cloned verbatim from `components/EvidenceSettings.tsx` (Phase 7 / STALE-02).

### Second semantic system — SLA status badge (clone `STATUS_COLORS` verbatim, same shape, new key set)

| `sla_status` value | Classes (light / dark) |
|---|---|
| `ok` | `bg-green-100 text-green-800` / `dark:bg-green-900/30 dark:text-green-400` (identical to existing `resolved`) |
| `at_risk` | `bg-yellow-100 text-yellow-800` / `dark:bg-yellow-900/30 dark:text-yellow-400` (identical to existing `in_progress`) |
| `breached` | `bg-red-100 text-red-800` / `dark:bg-red-900/30 dark:text-red-400` (identical to existing `open`) |
| `none` / missing (no `due_date`, or field absent on legacy pre-migration tasks) | `bg-gray-100 text-gray-500` / `dark:bg-gray-700 dark:text-gray-400` (identical to existing `dismissed`) — never crash or render a blank cell for a task missing `sla_status` |

Badge markup: `<span className="px-2 py-0.5 text-xs font-semibold rounded-full {SLA_COLORS[sla_status] ?? SLA_COLORS.none}">{sla_status.replace('_', ' ')}</span>` — byte-for-byte structural clone of `RemediationDashboard.tsx:192`'s existing status badge, new `SLA_COLORS` map placed directly beside `STATUS_COLORS` (same file, same declaration style, lines 9-14).

Table column: add a `SLA` header cell (`<th className="p-4 font-semibold text-xs text-gray-500 uppercase tracking-wider">SLA</th>`) positioned between the existing `Status` and `Actions` columns; update the empty-state `colSpan={6}` to `colSpan={7}`.

Escalation tier display (D-04): shown as **plain text**, not a second colored pill, inside the escalation history panel only — `Tier {escalation_level}` prefixing each entry's label line (e.g. `Tier 2 escalation`). Do not introduce a third badge/chip color system into this modal; a plain-text tier label keeps the panel visually subordinate to the SLA badge (the one true colored-status signal) per the existing codebase's restraint around badge proliferation (only `STATUS_COLORS` and the ticket-provider pill exist today in this exact file).
