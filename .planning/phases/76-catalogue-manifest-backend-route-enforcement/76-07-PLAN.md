<slice_rules>
1. Per router object (each `_load(app, module, attr)` call): if all its routes are user-authenticated and none is self-service or app-shell, add one MOUNTS entry; otherwise add route-level dependencies=[Depends(catalogue_guard(...))] to each user route and catalogue_exempt(reason) to each self-service/app-shell route. Never wrap public (REVIEWED_UNAUTHENTICATED), agent-only or get_current_user_or_agent routes (D-02).
2. Guard values come from the manifest owner of each route path (resolved read/write); auth is the dependency the router's routes already use.
3. Existing guards stay exactly as they are; the catalogue guard is additive (PROH-76-01).
4. Exemptions are only for routes acting on the caller's own records or app-shell reads every signed-in user needs; data reused by another view is NOT an exemption reason (note it in the SUMMARY as a Phase 77 UX item).
5. shared/catalogue-access.json is read-only here; a mapping you disagree with goes into the SUMMARY under "Manifest corrections for 76-11", and you guard to the manifest as written.
6. After guarding, run the full backend suite; fix a red test only by giving its principal a role that holds the permission, editing only the failing test function; a failure caused by another wave-3 plan's routes is recorded, not fixed.
7. No service restarts, deploys, or writes to the live omni_platform database.
</slice_rules>
