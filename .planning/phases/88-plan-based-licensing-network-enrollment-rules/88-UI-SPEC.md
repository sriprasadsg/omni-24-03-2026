## Spacing Scale

Inherited unchanged from 81/87: 4, 8, 16, 24, 32, 48 (64 unused).

| Token | Tailwind | Usage in this phase |
|-------|----------|---------------------|
| xs 4px | `1` | Gap between a field and its helper line, marker to label |
| sm 8px | `2` | Gap between buttons, between stacked helper lines |
| md 16px | `4` | Gap between form rows and between blocks inside a modal or card |
| lg 24px | `6` | Card padding in new partner/modal blocks, section gaps |
| xl 32px | `8` | not used |
| 2xl 48px | `12` | not used |

Exceptions (all multiples of 4):
- Consequential controls (`Save {plan} plan` in the Plans dialog, `Save plan`, `Extend trial`, `Create Tenant`, `Save Changes`, partner form and Create customer submits) are `min-h-10` (40px, `px-4`), the 87 control height.
- Row and inline text buttons (`Use plan number`, `Plan and trial`, `Restore`, `Show`/`Hide` toggles) are `min-h-8` (32px hit area, `px-2`), as 87 declares for row actions.
- New buttons and the range field inside the Pending panel's dense 12px table are `min-h-8` (32px): the table's rows are 12px text, so the 40px control would break the row rhythm. Declared exception; the panel's existing `btn` (24px) is legacy and is left as is.
- Inherited: 12px (`3`) for checkbox-label gaps, field padding (`px-3`) and helper-to-field gaps, because every host file already uses it. 20px (`p-5`, `gap-5`) on the card shell in `AgentsDashboard` and `PendingAgentsPanel`, so `TenantPlanCard` matches its neighbours; new elements in new files use the declared scale.
- No half-steps (`0.5`, `1.5`, `2.5`) in new or changed elements (violations are listed as gaps G-04, G-05).

Opened by the secondary `Plans` button beside `Add New Tenant` in Tenant Management. `Modal size="4xl"`, title `Plans`, footer `Close` only, `closeOnBackdrop={false}` (edits are lost otherwise; G-10). Body `space-y-4`.

One section per plan in the order Free, Pro, Enterprise, Custom (`bg-gray-50 dark:bg-gray-700/50 rounded-lg border p-4`, `aria-label="{plan} plan"`):

- Free, Pro, Enterprise: field `Seats` (number, whole 0 to 1,000,000, `min-h-10`), Free only: field `Trial days` (whole 1 to 365); a `Screens ({n} of {total})` disclosure (`<details>`; collapsed by default) holding the screen checklist; `Save {plan} plan` (visible label with the plan name, e.g. `Save Pro plan`, so the three buttons in one dialog are told apart by sight as well as by assistive tech; `min-h-10`, accent, pending `Saving...`) enabled only when something changed; inline status to its right.
- Screen checklist: use `PartnerScreenPicker mode="ceiling"` (same groups, parent rule, `Select all screens` / `Clear all screens`, count, Overview shown ticked and disabled with `Always included`), so the plan lists obey the same parent rule and Overview rule as every other list in the product (G-09). Inside the disclosure it scrolls (`max-h-72 overflow-y-auto`).
- Live effect line under `Seats`, shown only while the number differs from the saved one (12/400, `aria-live="polite"`, linked by `aria-describedby`): `Applies at once to every tenant on {plan} that has no seat override ({n} on this plan). - Custom: no inputs. 14/400: `Set per tenant by contract` and 12/400 muted `Choose the seats and screens for each Custom tenant in Manage Tenant.`

Validation (inline, on save, `role="alert"`, 14/400 red; the field keeps its value): `Seats must be a whole number from 0 to 1,000,000.` / `Trial days must be a whole number from 1 to 365.` Server answers are shown in the same slot (S1 table in Copywriting). A refusal keeps every edit.

Success: `Saved. {n} tenant(s) updated.` (`1 tenant`, `0 tenants`), section resets to the saved values, `role="status"` green.

### S7. Moved agents list (88-14, new; LIC-06; D-37, D-38, D-43)

`PendingMovedAgents` (platform deciders only). **It must render even when the pending list is empty:** an agent is retired because a hold was approved, so right after an approval nobody is waiting and the panel's own empty-state early return would hide the very list (decided; changes the panel's early return to `if no data: nothing; if no agents and not canDecide: nothing; if no agents and canDecide: only the moved list`). ## Accessibility and Interaction Notes

- Focus: the global `:focus-visible` ring only; `Modal` handles trap, restore and Esc. After a refetch focus stays where it was and is never left on a removed node (a restored or approved row's button disappears: focus moves to the panel heading).
- Live regions: errors `role="alert"`; saved lines, the Extend and Use plan number results and the `No plan ticked` line `role="status"`; effect lines under fields `aria-live="polite"`.
- Reasons for disabled controls are never `title` only: greyed screen boxes point `aria-describedby` at one visible shared note, `Allow network` without an address at its helper.
- Buttons name their target where a page has many: `Allow network for {hostname}`, `Approve move of {hostname}`, `Restore {hostname} in {tenantName}`, `Change plan and trial for {customer}`. Where a page has several identical actions the visible label carries the target (`Save {plan} plan`). Visible labels stay as in the Copywriting Contract; the Plans dialog's `Save` to `Save {plan} plan` change means the 88-12 tests that look for a bare `Save` button must be updated with the fix for G-23.
- Forms: every field has a visible `<label>`; helper and error text linked with `aria-describedby`; number fields use `inputMode="numeric"`.
- Text fit: no `truncate` on any name, hostname, address or organization.
- Idempotency: every save, extend, approve and restore button is disabled while its request is pending.
- Server strings render as React text only; no `dangerouslySetInnerHTML`.
- D-36 review rule for the executor and UI auditor: on any tenant-facing view (the Agents screen as a tenant admin) no string, `title`, `aria-label` or toast contains another organization's name; only a response that carries `crossTenant` may produce one, and only platform readers receive it.
