<objective>
Close UAT gap G-88-5 (minor, test 5). When the Super Admin refuses a bad network range in Agents > Agents waiting for approval, the refusal must tell the person deciding, in plain words, why the range was refused. It must name the limit (/24 for IPv4, /48 for IPv6) or the address the computer enrolled from, and never the API request field name.

Purpose: LIC-05 and D-42 let the decider widen an allowed network to a bounded range. The panel shows the server's refusal verbatim (88-UI-SPEC line 360), so the server text is what the decider reads. Today it starts with the request field name and, for a /8, leaves out that the range must contain the address. Fixing the server wording fixes the screen. No UI change is needed.

Output: reworded refusals in backend/network_rules.py validate_widen, plus tests that pin each refusal's exact text, the absence of the field name and the 422 route answer.
</objective>
