# Phase 24 — UI Design Contract

> Visual and interaction contract for `IacContainerDashboard.tsx` (IaC Scanner + Container Scanner). Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none — no `components.json` found; project has 150+ existing dashboards, all hand-built on plain Tailwind utility classes with no component library. Introducing shadcn for a single phase would fragment an already-large, consistent codebase convention. Decision made without prompting per Auto Mode (reasonable-call bias): **do not initialize shadcn.** |
| Component library | none (plain Tailwind utilities, no Radix/Base UI primitives) |
| Icon library | `lucide-react` for in-page icons (matches `CloudChecksScanner.tsx`, and the existing draft `IacContainerDashboard.tsx`); local `./icons` module (hand-rolled SVG set) for the Sidebar nav icon only — `FileCodeIcon` is already locked there per CONTEXT.md |
| Font | `Outfit` (`fontFamily.sans` in `tailwind.config.js`) — inherited from `<body>`/`font-sans` on the app shell (`App.tsx` root div `font-sans`). **Do not** hardcode a different font-family (the existing draft's inline `fontFamily: 'Inter, sans-serif'` is a deviation — see Known Deviation below) |

**Known deviation flagged for correction:** `components/IacContainerDashboard.tsx` already exists on disk (pre-built ahead of Phase 24 execution) but uses a completely different visual language than every sibling dashboard referenced in CONTEXT.md — full-bleed inline `style={{}}` objects, a dark-only `#040812` background, `Inter` font override, and a neon/glass color scheme borrowed from a different, unrelated cluster of dashboards (`IaCSecurityDashboard.tsx`, `APISecurityDashboard.tsx`, etc.). This does **not** match `ProgramsDashboard.tsx` or `CloudAccountsDashboard.tsx` — the two components CONTEXT.md explicitly names as the reference pattern for this phase (nav wiring + history-list layout) — nor `CloudChecksScanner.tsx`, the closest functional sibling (a results-table + severity-badge scanner UI in the same Security section). This UI-SPEC's contract below follows the **Tailwind utility, light/dark-themeable** house style used by those three siblings, not the pre-existing draft's inline-style dark theme. The executor should restyle the existing draft's markup/logic (which is functionally complete and matches the plan's tab/table/history shape) to Tailwind classes per this contract, rather than keep the inline-style theme or write a new component from scratch.

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-label gaps (`gap-1`), badge internal padding |
| sm | 8px | Compact stacking (`gap-2`), form control gaps |
| md | 12px | Table cell padding (`px-4 py-3` uses 12–16px mix), compact card padding — this is the codebase's dominant "compact" unit (Tailwind `p-3`/`gap-3`), used pervasively in `CloudChecksScanner.tsx`/`ProgramsDashboard.tsx`/`CloudAccountsDashboard.tsx`; kept as a declared token rather than fought, since it is 4px-aligned (3×4) |
| lg | 16px | Card/section padding (`p-4`), default block spacing |
| xl | 24px | Section-to-section gaps (`gap-6`), page header margin-bottom |
| 2xl | 32px | Page-level top padding on wide viewports |

Exceptions: none — all values used are 4px multiples; no arbitrary values (e.g. no `text-[10px]`-style magic numbers per UI-01 precedent).

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body / table cell | 12px (`text-xs`) | 400 regular | 1.5 (Tailwind default leading for `text-xs`) |
| Label / input / button | 14px (`text-sm`) | 400 regular (inputs, plain labels) / 600 semibold (buttons, badges) | 1.4 |
| Section heading (card title, tab label) | 14px (`text-sm`) | 600 semibold | 1.3 |
| Page title | 20px (`text-xl`) | 700 bold — **exception, see below** | 1.2 |

Declared weights: **400 (regular)** for body/inputs, **600 (semibold)** for labels/buttons/badges/section headings.

Exception: the page `<h2>` title ("IaC & Container Security") should use `font-semibold` (600) at `text-xl` (20px) to match `CloudChecksScanner.tsx`'s `<h2 className="text-xl font-semibold ...">` pattern exactly — do not introduce a third weight (700/900) as the pre-existing draft's inline styles do (`fontWeight: 900`). Two weights total across the whole component: 400 and 600.

## Layout & Interaction Notes (component-specific, supplementing the template)

- **Tabs:** 2 tabs — "IaC Scanner" / "Container Scanner" — rendered as `border-b-2` underline tabs exactly like `CloudChecksScanner.tsx`'s `results`/`library` tabs (`px-4 py-2 text-sm font-medium border-b-2 -mb-px`, active = `border-blue-500 text-blue-600 dark:text-blue-400`, inactive = `border-transparent text-gray-500`). This satisfies the CONTEXT.md-locked 2-tab layout without the pre-existing draft's rounded-pill/glow tab treatment.
- **IaC Scanner tab layout:** two-column grid (`grid grid-cols-1 lg:grid-cols-2 gap-6`) — left column is the code-input card (filename/type `<select>` + `<textarea>` paste box, primary per CONTEXT.md; file upload input styled as a secondary/stretch affordance, smaller and less visually prominent than the textarea, per CONTEXT.md's "file upload as a stretch enhancement"); right column is the results-table card. Below both, full-width (`col-span-2`), the scan-history list card.
- **Results table (IaC):** columns Check / Severity / Status / Line / Message, in that order, rows sorted severity-first (critical → high → medium → low) matching sibling dashboards per CONTEXT.md — this is a client-side or server-side sort, either is acceptable, but the contract is the **visual order**, not the sort implementation. Status column uses the PASS/FAIL icon+badge pair above, not colored text alone (icon carries meaning for colorblind users, matching `CloudChecksScanner.tsx`'s `CheckCircle`/`XCircle` pattern).
- **Container Scanner tab layout:** single-column stacked cards — image-name input + Scan button row, a 4-up stat-tile row (Total / Critical / High / Medium counts, styled like `CloudChecksScanner.tsx`'s summary tiles: `bg-white dark:bg-gray-800 rounded-xl border p-4`), then the vulnerabilities table (columns: CVE/Package/Severity/Installed/Fixed/Title), then the scan-history list.
- **History list (both tabs):** a simple vertical list of rows below the form — `CloudAccountsDashboard.tsx`'s pattern (compact `text-xs`/`text-[10px]`-free rows, each showing the scan target, key counts, and a relative timestamp), not a separate History tab. This is explicitly locked in CONTEXT.md.
- **Loading state:** spinner only (Tailwind `animate-spin` border-circle, matching `CloudChecksScanner.tsx`'s `<div className="w-8 h-8 border-4 border-primary-500 border-t-transparent rounded-full animate-spin" />` — swap `border-primary-500` for `border-blue-500` per this phase's accent color) — centered in the results/vuln-table area while a scan is in flight. No skeleton screens.
- **Error state:** an inline banner above the tab content (`bg-red-50 dark:bg-red-900/20 text-red-700 dark:text-red-400 rounded-lg p-3 text-sm`), populated from the bound `catch (e: any)` error message — not a toast, not a silent console-only failure (this is the corrected pattern from the session's WR-01 fixes, per CONTEXT.md).
- **RBAC:** the whole dashboard content area is gated on `view:cloud_security`; a scan-config settings affordance (if surfaced in the UI at all — the plan does not require a dedicated scan-config panel in the tab UI, only the two API endpoints) is gated on `manage:settings`. If no scan-config UI is built in this phase, no additional gate is needed beyond the page-level `view:cloud_security` check already enforced by the Sidebar's `permission` prop.
