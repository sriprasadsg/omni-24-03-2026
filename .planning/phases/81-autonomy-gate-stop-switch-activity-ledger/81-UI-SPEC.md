# Phase 81 — UI Design Contract

> Visual and interaction contract for the Autonomous Ops screen and the app-wide stop banner. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
> Scope is D-22 only: (1) a new **Autonomous Ops** screen in the sidebar `automation` group (read-only activity list in six states, shadow rows labelled as a simulation, status readout, Stop and Resume, Platform Support read-only cross-tenant view); (2) an **app-wide stop banner** (D-15). Out of scope: approve/deny/undo buttons (Phase 83), level picker, shadow lift, never-touch editor (API-only here), digest/stats/export (Phase 86).
> Locked inputs: 81-CONTEXT.md D-01..D-24 (especially D-04, D-08, D-10..D-15, D-22, D-23, D-24a). Nothing here re-opens them.
> Scope of new infrastructure: no new component library, no new tokens. Built from the primitives and Spatial Glass tokens already in the repo (verified by reading `design-system/omni-agent-2030/MASTER.md`, `tailwind.config.js`, `index.css`, `components/Modal.tsx`, `components/NoAccessPanel.tsx`, `components/ConfirmationModal.tsx`, `components/ui/skeleton.tsx`, `components/icons.tsx`, `components/AgentsDashboard.tsx`, `contexts/UserContext.tsx`, `App.tsx` shell region).

## Spacing Scale

Declared values (multiples of 4), as the Tailwind steps the executor must use:

| Token | Value | Tailwind | Usage in this phase |
|-------|-------|----------|---------------------|
| xs | 4px | `1` | Icon-to-text gap inside chips, chip padding-y |
| sm | 8px | `2` | Gap between chips and text, gap between stacked banners, filter pill gap, chip padding-x |
| md | 16px | `4` | Table cell padding (`px-4 py-4`), banner padding, gap between status readout cells, button gaps |
| lg | 24px | `6` | Status card padding, gap between page sections, dialog body gaps |
| xl | 32px | `8` | Empty-state card padding |
| 2xl | 48px | `12` | Empty-state icon circle diameter, vertical breathing room above the empty state |
| 3xl | 64px | `16` | Not used |

Exceptions:
- Filter pills use `px-3` (12px, a multiple of 4) so eight pills fit one row at 1280px; height `min-h-8` (32px).
- Stop and Resume buttons are `min-h-10` (40px) with `px-4`: braking is the one control that must be easy to hit (D-11, D-14).
- No `py-1.5`, `mb-0.5` or other half-steps in new elements.

Exactly four sizes and two weights for everything new in this phase.

| Role | Size | Weight | Line Height | Tailwind |

## Screens and States

### 1. Sidebar entry and routing

- Catalogue entry (manifest, not new chrome): `view: autonomousOps`, label `Autonomous Ops`, group `automation`, permission `view:autonomous_ops`. Sidebar icon: `ShieldZapIcon` 20px via `SIDEBAR_PRESENTATION.autonomousOps` (choose a different glyph if the `autopilot` entry already uses it; the two screens must be distinguishable at a glance).
- Access gate, switched-off and no-access states are Phase 77's `NoAccessPanel`; this screen adds no variant. D-23: a tenant whose screen is not ticked never reaches it.
- Screen mount: breadcrumb is supplied by `Header`; the screen renders its own page title (section 3).

### 2. App-wide stop banner (D-15)

Where: inside the shell column in `App.tsx`, directly above `<Header>` (the column at ~line 1958; the red "Backend connection lost" bar is `fixed` and unrelated). In normal flow, `shrink-0`, so it pushes content down and never covers the header.

Who sees it: only when `hasPermission('view:autonomous_ops')` is true and a stop is active at the viewer's scope. Not shown to anyone else, never mounted for them, and no fetch is made for them.

Data: one shared poller on `GET /api/autonomous-ops/status`: immediately on mount, every 30 s while the tab is visible (pause when hidden), on window focus, and immediately after any Stop or Resume. A failed poll keeps the last known state and shows nothing (the banner never reports its own fetch errors); a first-load failure shows no banner.

Layout, per active stop (up to two stacked, platform first, `gap-2`):
`flex items-start gap-4 rounded-2xl border p-4` using the amber warning classes, `role="status"` (polite live region: it announces when it appears), not dismissible (a stop never clears itself, D-14, so hiding it would misstate the system).
- Left: `AlertOctagonIcon` 20px, `aria-hidden`, `shrink-0`.
- Middle (`min-w-0`, column, `gap-1`): title 14/600; detail 14/400 `break-words`, clamped to 2 lines (`line-clamp-2`) with the full text in `title`.
- Right: text button `View details` (14/600, `underline underline-offset-2`, not accent; amber-900 / dark amber-100). Hidden when the current view is already `autonomousOps`.
- Under 640px the button wraps below the text, left-aligned.

Copy: see Copywriting Contract. Two active stops (platform plus organization): two banners, platform first.

### 3. Autonomous Ops screen

Where: `<main>` content, width follows the other Spatial Glass screens; vertical rhythm `space-y-6` (24px).

Page header (flex, wraps; `gap-4`):
- Left: `h1` Display 30/600 `Autonomous Ops`; under it a 14/400 muted subtitle (see Copywriting).
- Right: scope chip (neutral outline chip, `Viewing {tenant name}` or `Platform`; Platform Support also gets a neutral outline chip `Read-only` with `EyeIcon` 12px) and a secondary `Refresh` button (`RefreshCwIcon` 16px left; secondary classes: `border border-gray-300 dark:border-gray-600 bg-white dark:bg-gray-800 text-gray-700 dark:text-gray-200 hover:bg-gray-50 dark:hover:bg-gray-700 rounded-lg px-4 py-2 text-sm font-semibold`). Pending: `disabled`, label `Refreshing...`, icon `animate-spin` (global reduced-motion rule applies).

Scope rules (reuse the existing tenant context, no new switcher):
- Tenant Admin, Security Analyst, Incident Responder, Analyst: always their own tenant; scope chip shows the tenant name.
- Super Admin and Platform Support use the existing tenant context (`viewingTenantId`, entered from Tenants, left with the sidebar `Back to Tenants`). With a tenant selected: that tenant, chip `Viewing {tenant name}`. Super Admin with no tenant selected: platform scope (section 3c). Platform Support with no tenant selected: the `Select an organization` empty state (section 3f).
- Platform Support is read-only everywhere (D-08): no Stop, no Resume, chip `Read-only`.

#### 3a. Status card (readout and controls)

Container: `.card p-6`, column `gap-6`. Three blocks.

1. Readout: a `dl`, `grid grid-cols-1 sm:grid-cols-2 xl:grid-cols-4 gap-4`. Each cell: `dt` 12/400 muted label, `dd` value as a chip or 14/600 text, then a 12/400 muted helper line (`break-words`).

| Cell | Label | Value (chip or text) | Helper line |
|------|-------|----------------------|-------------|
| Level | `Current level` | `Off`, `Suggest only` or `Automatic within limits` (neutral outline chip) | Off: `Nothing is decided or recorded.` Suggest only: `Autonomous Ops suggests actions. Every action needs your approval.` Automatic within limits: `Low-risk actions run on their own and can be undone. Riskier actions need your approval.` |
| Maximum | `Highest level allowed` | same three values | `Set by a platform administrator.` |
| Shadow | `Shadow mode` | `On: simulation only` or `Off: actions are live` (Simulation chip styling when on, neutral outline chip when off) | On: `Autonomous Ops records what it would have done. Nothing is carried out.` followed, when the deployment-wide setting forces it, by `Set for the whole deployment.` otherwise `Set for this organization.` Off: `Actions allowed by the level above are carried out.` |
| Stop | `Stop` | `Not stopped` (neutral outline chip, `CheckCircleIcon`) or `Stopped` (amber chip, `PauseCircleIcon`) | Stopped: `Stopped by {name} on {date}.` then `Reason: {reason}` or `No reason was given.` |

   Conditional notices (full width under the grid, `rounded-lg border p-4 text-sm` with `InfoIcon` or `AlertTriangleIcon` 16px, `break-words`):
   - Level lowered by the circuit breaker (status carries a previous level): amber block, `Lowered from {previous level} after several automatic actions in a row were undone or failed. A person with manage access can restore it.` (D-18).
   - Level could not be read (treated as Suggest, GATE-02): blue info block, `This organization's setting couldn't be read, so it is treated as Suggest only. Every action needs approval.`
   - Platform organization (D-04): blue info block, `Autonomous Ops is not available for the platform organization.` Level and Maximum both show `Off`; Stop controls are not rendered.
   - Not ticked for this tenant (Super Admin or Platform Support viewing it; D-23): blue info block, `This screen isn't switched on for this organization, so nothing is decided or recorded for it.`

2. Controls row (`flex flex-wrap items-center gap-4`, left-aligned; sits under a `border-t border-gray-200 dark:border-white/10 pt-6` divider). Shown only to a viewer who can act; hidden entirely for Platform Support and when the scope is the platform organization.
   - Not stopped, viewer holds `control:autonomous_ops` (or Super Admin): red button `Stop automatic actions` (`AlertOctagonIcon` 16px left; `min-h-10 px-4 text-sm font-semibold text-white bg-red-600 hover:bg-red-700 rounded-lg`). Helper to its right, 12/400 muted: `Takes effect right away. Undo still works.` (`aria-describedby` on the button).
   - Stopped, viewer may clear it (holds `manage:autonomous_ops` for a tenant stop; Super Admin for any stop, D-11): primary button `Resume automatic actions` (`PlayCircleIcon` 16px left; `bg-primary-600 hover:bg-primary-700 text-white`, same size). The Stop button is not rendered at the same time (same slot, no layout shift).
   - Stopped, viewer may not clear it: no button; one 14/400 muted line: tenant stop pressed by a person without manage: `Only an administrator with manage access can resume this.`; stop pressed by a Super Admin or platform-wide stop: `Only a platform administrator can resume this.`
   - Buttons are `disabled` with the pending label while a request is in flight; repeated clicks are ignored.
   - Status could not be loaded: Stop stays available to holders (braking must not depend on a read); Resume is `disabled` until the status loads.

3. Platform-wide stop (only for holders of `control:platform_autonomous_ops`, that is Super Admin): a second row below the controls row, same `border-t pt-6` divider, subheading 14/600 `Platform-wide stop`, one line of 12/400 muted text, and the same pattern: red `Stop all organizations` when clear, primary `Resume all organizations` when active. Shown when the Super Admin is in platform scope or inside a tenant (the platform stop is global either way).

Status card states:
| State | Contract |
|-------|----------|
| Loading | Four readout cells as `h-16` skeleton blocks (`rounded-lg`, `animate-pulse`), controls row as one `h-10 w-56` skeleton; `aria-busy="true"` on the card. |
| Populated | As above. |
| Error | The card shows one red error block (`AlertTriangleIcon`, `role="alert"`): `Couldn't load the current status.` plus, for control holders, ` Stop is still available.` and a `Try again` text button (14/600). Controls row per rule above. |

#### 3b. Activity section

Header row (`flex flex-wrap items-center justify-between gap-4`): `h2` Heading 18/600 `Activity`; right: 12/400 muted `Newest first`.

Filters: a `role="group"` with `aria-label="Filter activity by state"`, `flex flex-wrap gap-2`, eight buttons with `aria-pressed`: `All`, `Pending`, `Done`, `Undone`, `Failed`, `Refused`, `Suggested`, `Simulation`. Each pill: `min-h-8 px-3 text-xs font-semibold rounded-full border`, unselected neutral (`border-gray-300 text-gray-700 dark:border-white/10 dark:text-gray-200 hover:bg-gray-50 dark:hover:bg-white/[0.06]`), selected = accent (Color list item 2). When the first page returns a `counts` object, append a `tabular-nums` count after the label inside the pill (`Pending 2`); a missing `counts` object omits the number (no zeros guessed). Default selection: `All`. Changing the filter refetches from the first page and keeps the scroll position of the page. Filter state is not persisted in the URL.

List surface: `.card overflow-hidden`.

Table (viewport `xl` = 1280px and wider): `<table class="w-full text-sm">` with an `sr-only` `<caption>` `Autonomous Ops activity`, `<th scope="col">` headers, `divide-y divide-gray-200 dark:divide-white/10`, cells `px-4 py-4 align-top`. Five columns:

| Column | Width | Content |
|--------|-------|---------|
| State | `w-40` (160px) | State chip (or Simulation chip, or Stop/Resume control chip), then the time under it: `<time dateTime>` 12/400 muted, relative under 24 hours (`12 min ago`) else absolute (`Oct 25, 2026, 14:32`), full local timestamp in `title`. |
| What ran | `w-56` (224px) | Action label 14/600 (server-supplied display label, e.g. `Block IP address`); under it 12/400 muted `Automatic` or `Needs approval`. |
| Why (the rule) | flexible, min 240px | Reason text 14/400, wraps (`break-words`, no clamp); under it the rule id in `font-mono` 12/400 muted. |
| Target | `w-48` (192px) | Host name 14/600 (`break-words`); under it the specific target (IP address, file path or service name) in `font-mono` 12/400 muted (`break-all`). |
| Result | flexible, min 200px | Result text 14/400 (`break-words`). For Failed rows the failure reason is part of the result text. |

Stacked cards (below `xl`): each row is a `p-4` block inside the card, separated by `divide-y`: top line = state chip left, time right (12/400 muted); then action label 14/600 and its `Automatic` / `Needs approval` line; then a `dl` with 12/400 muted labels `Why`, `Target`, `Result` over the same values as the table cells (`gap-2`).

Simulation rows (ACTV-03, always unmistakable):
- The state chip is replaced by the Simulation chip (dashed border, flask icon, text `Simulation`).
- The row gets a left rule: `border-l-2 border-dashed border-gray-400 dark:border-gray-500` and its Result cell reads `Nothing was done. This is what would have happened: {would-have-done text}.`; the action label stays as the action that would have run.
- Simulation rows appear under `All` and `Simulation` only; they belong to none of the six state filters.

Control rows (stop and resume events, D-15 "an Activity entry"): neutral Stop (amber) or Resume (neutral) chip; What ran = `Stop pressed` / `Stop cleared` (platform: `Platform-wide stop pressed` / `Platform-wide stop cleared`); Why = the typed reason, or `No reason was given.`; Target = `All automatic actions` (organization) or `Every organization` (platform); Result = `Stopped by {name}.` / `Resumed by {name}.`. They appear under `All` only and are not counted in the six state filters (assumption A3).

Row ordering: newest first. Pending rows are not pinned. Read-only: rows have no click target, no row actions and no hover action menu in this phase (approve, deny and undo arrive in Phase 83, which will add an Actions column).

Pagination: cursor-based, 25 rows per page. Under the last row, a centered `Load more` secondary button (same classes as `Refresh`, `min-h-10`); pending label `Loading...`. Under it, 12/400 muted `Showing {n} actions` (or `Showing {n} of {total} actions` when the active filter's count is known). No `Load more` and no footer count when the last page is reached and there are 0 rows. A failed page load keeps loaded rows and shows, under the list, a red 14/400 line with `role="alert"` `Couldn't load more activity. Try again.` and `Try again` button.

#### 3e. Stop and Resume dialogs

Both use `Modal size="md"` with `showClose={false}` (so the first focusable element is the reason field, not the close icon), `closeOnBackdrop={false}` (a typed reason is never lost by a stray click), Esc closes (inherited). Footer: `Cancel` (secondary) left, confirm right. Body is a column with `gap-4`.

Stop dialog (tenant):
- Title (18/600): `Stop automatic actions?`
- Body (14/400): `This stops new automatic decisions for {tenant name} right away. Actions already queued for agents are held back and will not run. Approval requests can't be approved until you resume, and they keep their 24-hour clock. Undo still works.`
- Field: label 14/600 `Reason (optional)`; `textarea` 3 rows, `maxLength` 500; helper 12/400 muted `Shown in the banner and the activity list.`; character count `{n}/500` 12/400 muted right-aligned, `tabular-nums`. Focus lands here on open. `Ctrl+Enter` / `Cmd+Enter` submits (braking must be fast).
- Confirm: red `Stop automatic actions` (pending: `Stopping...`, disabled; Cancel stays enabled).
- Success: close, `showToast('Automatic actions stopped.', 'success')`, refetch status and activity.
- Failure: dialog stays open, reason preserved, red block above the footer (`rounded-lg border border-red-200 bg-red-50 text-red-700 dark:border-red-900/50 dark:bg-red-900/20 dark:text-red-300 p-4 text-sm`, `AlertTriangleIcon`, `role="alert"`): `Couldn't stop automatic actions: {server message}. Try again. If it keeps failing, ask a platform administrator to use the platform-wide stop.` Fallback when no message: `Couldn't stop automatic actions. Check your connection and try again.`
- Already stopped by someone else (409): close, `showToast('Automatic actions were already stopped by {name}.', 'info')`, refetch.

Resume dialog (tenant):
- Title: `Resume automatic actions?`
- Context block (`rounded-lg bg-gray-50 dark:bg-white/[0.04] border border-gray-200 dark:border-white/10 p-4`, 14/400): `Stopped by {name} on {date}.` and `Reason: {reason}` (or `No reason was given.`).
- Body (14/400): `Actions that were held back during the stop were cancelled and will not run. New decisions can start again{shadow clause}.` Shadow clause when shadow mode is on: ` in shadow mode, so nothing is carried out`; otherwise omitted.

## Accessibility and Interaction Notes

- Focus: rely on the global `:focus-visible` ring (MASTER); the empty-state heading and dialog textarea take focus on open (dialogs via `showClose={false}`). The page `h1` is not auto-focused (the shell skip link handles it).
- Banner: `role="status"`; icon `aria-hidden`; the text is the accessible name. The `View details` control is a real `<button>`.
- Filters: `<button aria-pressed>` inside a labelled group; the selected pill is distinguished by fill and `aria-pressed`, not colour alone.
- Table: real `<table>` with caption and `scope` headers; stacked cards use `dl`. Chips carry text, so state is never colour-only; Simulation also carries the dashed border and the row rule.
- Live regions: errors use `role="alert"`; the polling refresh is silent (no announcement, no spinner); the banner announces only when it appears.
- Motion: spin and pulse are covered by the global `prefers-reduced-motion` rule (`index.css`); add no inline transitions that bypass it. Chips and buttons have no entrance animation.
- Contrast: 12px chip text on its tint must meet 4.5:1 in both themes (the amber-800, green-800, blue-800, red-700 pairs above are chosen for it); `text-gray-500` is allowed only on `.card` surfaces.
- Touch targets: Stop and Resume 40px high; filter pills 32px; `Refresh` and `Load more` `min-h-10`.
- Text fit: no `truncate` on the data columns (names, rules, reasons and paths must be readable in full); only the sidebar label truncates (existing behaviour). Long words and paths use `break-words` / `break-all`.
- Security of rendered strings: every server string (reason, target, result, names) is rendered as React text; no `dangerouslySetInnerHTML`, no link-ification of target or reason text.
- Idempotency: double-clicking Stop or Resume sends one request (button disabled on first click).
