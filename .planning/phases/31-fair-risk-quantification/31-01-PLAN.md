<objective>
Add the backend FAIR (Factor Analysis of Information Risk) quantitative layer to the risk register: a synchronous, numpy-vectorized Monte Carlo over LEF (Loss Event Frequency) x LM (Loss Magnitude) triangular distributions, exposed as a new optional endpoint on the existing tenant-scoped risk API. FAIR is strictly additive and parallel to the existing qualitative likelihood x impact `risk_score` — no reconciliation, no auto-suggestion, no new dependency (numpy/pandas already installed and used synchronously in-repo, e.g. `xai_service.py`).

Purpose: Deliver FAIR-01's entire server surface — validated inputs, the Monte Carlo core, tenant-safe persistence, and the full pytest suite — so the Wave-2 frontend has a proven contract to call.
Output: `run_fair_simulation()` + `attach_fair_results()` in `risk_service.py`, a validated `FairInputs` model + `POST /{risk_id}/fair-simulation` route in `risk_endpoints.py`, and `backend/tests/test_risk_fair_simulation.py`.
</objective>

|----------|-------------|
| client -> FAIR-simulation API | Untrusted LEF/LM min/likely/max floats and an iterations count cross here into a synchronous numpy computation |
| tenant -> shared db.risks collection | One physical risks collection stores every tenant's risks; the tenantId filter on the lookup is the only thing preventing cross-tenant read/write of FAIR results |
