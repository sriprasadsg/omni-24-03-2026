# Phase 82 — UI Design Contract

> Visual and interaction contract for the Super Admin **Platform health** panel on the Autonomous Ops screen, the two app-wide health banners, the retention count review with Confirm, platform-health rows in the Activity list, and two small notices on the tenant Retention Policy screen. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
> Locked inputs: 82-CONTEXT.md D-01..D-26 (screen decisions D-05, D-11, D-18..D-26). Nothing here re-opens them. Visual details the context left open are recorded as researcher defaults (section "Assumptions Recorded", IDs H1..H16; H12 is user-confirmed as D-25).
> Extends, does not replace, `81-UI-SPEC.md`: tokens, type scale, spacing scale, chip anatomy, banner anatomy, empty-state card, `Modal` conventions and the state vocabulary are inherited as written. Only deltas are declared here.
> New infrastructure: none. No new library, no new token, no new colour. Built from the primitives named in 81-UI-SPEC and the files read for this contract: `components/AutonomousOpsActivity.tsx`, `AutonomousOpsActivityList.tsx`, `AutonomousOpsStatusCard.tsx`, `AutonomousOpsStopBanner.tsx`, `AutonomousOpsStopDialog.tsx`, `contexts/AutonomousOpsStatusContext.tsx`, `services/autonomousOpsApi.ts`, `components/StatTile.tsx`, `components/RetentionPolicyDashboard.tsx`, `components/Modal.tsx`, `components/icons.tsx`, `shared/autonomous-ops-banned-terms.json`.

## Color

Inherited from 81-UI-SPEC: dominant `--bg-main`, secondary `.card` surface, accent `primary-600`, destructive `red-600`, amber warning, blue info, neutral text.

New health vocabulary reuses the Phase 81 chip tones; no tone is added:

| Tone | Source chip (81-UI-SPEC) | Meaning in Phase 82 |
|------|--------------------------|---------------------|
| GREEN | Done | Healthy, valid, delivered, deleting nightly |
| BLUE | Suggested | Notice (first rung of a threshold ladder), informational states |
| AMBER | Pending | Warning, in progress, waiting for a person |
| RED | Failed | Down, gave up, critical, delivery failed |
| NEUTRAL | Undone | Settled/quiet facts (Paged, Not tested) |
| OUTLINE | Refused / `OUTLINE_CHIP` | Static facts and "no data" (Unknown, Expected off, Not installed) |

**Severity ladder** (one rule for certificates, disk fullness and disk forecast, so the panel reads the same everywhere and matches the suggested PagerDuty mapping in 82-CONTEXT "Claude's Discretion"):

| Rung | Certificate | Disk used | Disk forecast (full within) | Tone | Chip text |
|------|-------------|-----------|-----------------------------|------|-----------|
| Clear | more than 30 days | under 80% | more than 14 days or none | GREEN | `OK` |
| 1 | 30 or 14 days left | 80% to under 90% | 14 days | BLUE | `Notice` |
| 2 | 7 days left | 90% to under 95% | 7 days | AMBER | `Warning` |
| 3 | 1 day left or expired | 95% and above | 1 day | RED | `Critical` |

Certificate days left are "at most" thresholds (30, 14, 7, 1 days). A section's header chip shows the worst rung among its entries.

Accent reserved for (the Phase 81 list stands; Phase 82 adds exactly one entry):
1. Phase 81 items 1 to 4 unchanged.
5. The `Platform health` filter pill when selected (same selected-pill classes as the other filters).

Accent is NOT used for: `Send test alert` (secondary button), `Confirm deletion` (red, destructive), the install-checklist link (underlined body text), the disk meter, any health chip, either health banner.

Destructive red is additionally used for: the `Confirm deletion` button and dialog confirm (it deletes records that cannot be restored, D-15), `Down`/`Gave up`/`Critical`/`Silent`/`Not working` chips, and the watchdog-silent banner (default H5).

Meaning never relies on colour alone: every chip has an icon (12px, `aria-hidden`) and visible text; the disk meter shows the percentage as text and carries tick marks.

## Screens and States

### 1. Placement on the Autonomous Ops screen

Super Admin in **platform scope** (no tenant selected) sees, top to bottom: page header, status card (Phase 81), **Platform health section (new)**, Activity section. Nothing in the section is rendered for any other viewer: no placeholder, no heading, no fetch (D-22). In tenant scope (Super Admin viewing a tenant) the section is not rendered either (D-20 is platform scope). Platform Support never sees it (default H2: Platform Support has no platform scope on this screen; it keeps the `Select an organization` card).

**Visual anchor (focal point).** The primary anchor of the Platform health section, and of the Autonomous Ops screen below the status card, is the **watchdog status row and services grid** (section 3): it is the first block in the section, carries the only per-service state chips, and answers "is the platform healthy right now?" before anything else. Hierarchy rules that follow from it: the watchdog and services card is first in reading order and is not collapsible; no other card in the section uses a larger heading, a stronger border or a filled background than this one (all cards share the `.card` surface); the certificate, disk, on-call and retention cards are subordinate, read after it, and are never placed above it. **When the watchdog-silent banner is active (section 2) it outranks the anchor**: the red banner sits at the top of the viewport above the header, and the red `Silent` chip and red block in the watchdog row repeat the same message in place, so the screen has exactly one dominant alarm. The no-working-channel banner (amber) does not outrank the anchor; it is a standing warning above the page and the on-call card carries the detail.

The section is `<section aria-labelledby="platform-health-title" id="platform-health">` with `space-y-6`. The `h2` has `tabIndex={-1}` so a banner's `View details` can move focus to it.

Section header (`flex flex-wrap items-center justify-between gap-4`): left `h2` Heading 18/600 `Platform health`; right 12/400 muted `Updated {HH:MM}` (24-hour local time, full timestamp in `title`). The page-level `Refresh` button also refreshes this section (it increments the existing `refreshSignal`). One 14/400 muted subtitle under the h2: `Services, certificates, disk and alerting for the platform server, checked every minute by the watchdog.`

Data: one fetch for the section's full document on mount, every 30 s while the tab is visible, on focus, on `Refresh`, and every 5 s while a test alert is pending (section 7). Background polls show no skeleton and no spinner. The two banners read only a small summary carried on the existing shared status poller (section 2), so the banner and the section never disagree and no second long-lived poller is created.

Section states:

| State | Contract |
|-------|----------|
| Loading (first load) | One `.card p-6` skeleton per block (`h-16` readout skeletons, `rounded-lg`, `animate-pulse`), `aria-busy="true"` on the section. |
| Populated | Blocks 3 to 7 below. |
| Error (first load) | A single `.card` with a red block (`AlertTriangleIcon`, `role="alert"`): `Couldn't load platform health. Check your connection and try again.` and a `Reload platform health` text button. The retention card is independent and still renders if its own fetch succeeded. |
| Error (background poll) | Keeps the last data; shows nothing new (matches the banner rule). The `Updated` time stops advancing, which is the only trace. |
| Watchdog not installed | Section 3. |
| Watchdog silent | Section 3. |

### 2. App-wide health banners (D-05, D-22)

Where: the same shell slot as the Phase 81 stop banner (directly above `<Header>`, in normal flow, `shrink-0`). `AutonomousOpsStopBanner` renders stop banners first (platform, then organization), then at most **one** health banner beneath them. The stack is at most 3. Each is a sibling `OneBanner` anatomy from 81 (`flex flex-wrap items-start gap-4 rounded-2xl border p-4`, icon 20px `aria-hidden`, title 14/600, detail 14/400 `line-clamp-2` with full text in `title`, text button `View details` 14/600 underlined).

Who sees them: only a viewer holding `control:platform_autonomous_ops` (Super Admin). Never mounted for anyone else, never fetched for anyone else. Not dismissible (they describe a standing condition; same rationale as a stop).

Data: the shared status poller already returns the platform status for Super Admin; Phase 82 adds a compact `health` summary to that payload: `{ watchdog: 'not_installed' | 'running' | 'silent', lastSeenAt, channel: 'working' | 'untested' | 'none' | 'failing', channelError }`.

Arming rules (D-24, default H6): no health banner at all while `watchdog = 'not_installed'`. The dead-man alarm and the channel banner both arm only after the first heartbeat ever arrived.

Which banner (priority, only one shown):
1. `watchdog = 'silent'` shows the **watchdog-silent banner** (red). While it shows, the channel banner is suppressed, because channel status reported by a silent watchdog is stale.
2. Else `channel` in `none` or `failing` shows the **no-working-channel banner** (amber).
3. Else nothing. `untested` shows no banner (rule from 82-CONTEXT Claude's Discretion: "no channel configured, or last test or delivery failed").

| Banner | Colour | Icon | Role | Title | Detail |
|--------|--------|------|------|-------|--------|
| Watchdog silent | red error block: `border-red-200 bg-red-50 text-red-700`, dark `border-red-400/25 bg-red-400/10 text-red-300` | `AlertOctagonIcon` | `alert` | `The watchdog has gone silent.` | `Last seen {HH:MM}. Services are not being checked or restarted, and no on-call pages can be sent, until it reports again.` |
| No working channel, none | amber warning (81 classes) | `AlertTriangleIcon` | `status` | `No working on-call channel.` | `Nobody will be paged if a service fails. Set up a channel on the server, then send a test alert.` |
| No working channel, failing | amber warning | `AlertTriangleIcon` | `status` | `No working on-call channel.` | `The last alert couldn't be delivered: {error}. Nobody will be paged until a test alert succeeds.` |

Link: `View details`. It is hidden only when the viewer is already on the Autonomous Ops screen **in platform scope** (where the section is on screen). From a tenant scope or any other screen it navigates to `autonomousOps` in platform scope (clearing `viewingTenantId`; default H7) and moves focus to `#platform-health-title`.

The watchdog-silent alarm also creates one **in-app notification** (D-05) through the existing notification mechanism: title `The watchdog has gone silent`, body = the banner detail. One notification per silence episode, not per poll.

Banner states: before the first successful poll nothing renders; a failed poll keeps the last state and shows nothing (inherited).

### 3. Watchdog and services card

Container: `.card p-6`, column `gap-6`. Two blocks.

**Block 3a: Watchdog status row** (`flex flex-wrap items-center justify-between gap-4`): left a `dl` cell: `dt` 12/400 `Watchdog`, `dd` the status chip; right 12/400 muted helper line.

| Watchdog state | Chip | Helper line | Extra |
|----------------|------|-------------|-------|
| Running | `Running` (GREEN) | `Last seen {relative}.` using `formatWhen`, full local timestamp in `title`; run cadence note `Checks run every minute.` | none |
| Silent | `Silent` (RED) | `Last seen {relative}.` | Red block below the row (`role="alert"`): `The watchdog has not reported since {HH:MM}. Services are not being checked or restarted, and no on-call pages can be sent. Check the timer on the server:` followed by `omni-watchdog.timer` in `font-mono`. |
| Not installed (D-24) | `Not installed` (OUTLINE) | `The watchdog has never reported on this server.` | Blue info block (`InfoIcon`): `Watchdog not installed. Service, certificate, disk and alert-channel status appear here once it is installed and reports. Installing it is a step on the server.` followed by the checklist link (below). |

Install-checklist link (default H8): the status payload carries `installChecklist: { path, url }`. If `url` is present: a text link `View install checklist` (14/600, underline, `ExternalLinkIcon` 12px, `target="_blank" rel="noopener noreferrer"`). If `url` is null (the app does not serve repo files): the same label as plain 14/600 text followed by `path` in `font-mono` 12/400 (`break-all`). Never an accent colour. The link also appears under the Silent block and under the "Not set up" channel state.

Stop interplay notice (D-11), shown above the services grid when applicable (`rounded-lg border p-4 text-sm`, `PauseCircleIcon` 16px, amber): `Restarts are paused because automatic actions are stopped for the whole platform. Checks, warnings and pages continue.` Variants by `stopSource`: `database` uses the line above; `cache` appends ` The database can't be reached, so the watchdog is using the last stop state it saw.`; `file` replaces the sentence with `Restarts are paused by a STOP file on the server. Checks, warnings and pages continue.`

**Block 3b: Services** (under a `border-t border-gray-200 dark:border-white/10 pt-6` divider): `dl`, `grid grid-cols-1 sm:grid-cols-2 xl:grid-cols-4 gap-4`. Four cells in the fixed order MongoDB, Backend, nginx, Ollama (MongoDB first because it is restarted first, D-09). Each cell: `dt` the service name in `font-mono` 12/400 muted (`mongod`, `omni-backend`, `nginx`, `ollama`) with a plain 14/600 display name above it (`MongoDB`, `Backend`, `nginx`, `Ollama`); `dd` the state chip; then two 12/400 muted helper lines (`break-words`): line 1 state detail, line 2 restart budget.

| Service state | Chip | Line 1 | Line 2 |
|---------------|------|--------|--------|
| Healthy | `Healthy` | `Checked {relative}.` | `Restarts used: {n} of 3 in the last 30 minutes.` (omit when 0) plus, when a budget is re-arming, `Restart budget back in {m} min.` |
| Failed one check | `Checking` | `1 failed check. Counted as down after 2 in a row.` | budget line |
| Down, restarts available | `Down` | `Down since {HH:MM}. Restart {k} of 3 {at HH:MM / waiting {m} min}.` | budget line |
| Restart in progress | `Restarting` | `Restart {k} of 3 started {HH:MM}.` | budget line |
| Gave up (D-07, D-08) | `Gave up` | `Restarted 3 times in 30 minutes. Not restarting again. On-call was paged at {HH:MM}.` | `Restart budget returns after 1 hour healthy.` |
| Restarts paused by stop | the state chip stays (`Down`) | `Restarts paused: automatic actions are stopped.` | budget line |
| Waiting on MongoDB (D-09) | `Down` | `Waiting for MongoDB to be healthy first.` | budget line |
| Ollama, expected off | `Expected off` | `Not installed on this server. The watchdog never starts it.` | none |
| Ollama running while expected off | `Running` (BLUE `Notice` tone, `InfoIcon`) | `Running, but not expected on this server. Not managed.` | none |
| Watchdog silent or not installed | `Unknown` (every cell) | `Last known: {state} at {HH:MM}.` or `No reading yet.` | none |

Service-name helper text always shows the unit in mono so an operator can copy it. A missing field renders `—`.

### 4. Certificate card (HEAL-03, D-13) and Disk card (HEAL-02, D-14)

Both sit in one row: `grid grid-cols-1 xl:grid-cols-2 gap-6`; each a `.card p-6` with column `gap-4`. Each has a 14/600 subheading (`Certificates`, `Disk`) with the worst rung chip at the right of the header row.

**Certificates.** One entry per watched file, soonest expiry first, `divide-y` between entries, no truncation. Entry: path `font-mono` 12/400 `break-all`; 14/600 expiry date (`Jan 15, 2029`) with 14/400 `in {n} days` (`expired {n} days ago`, `expires today`, `expires tomorrow`); the ladder chip. The default entry (`/etc/nginx/ssl/omni.crt`) also carries the `Pinned by agents` chip.
- Always-present note (12/400 muted, under the list; default H9): `Agents pin the nginx certificate. Replacing it needs an agent update first, so plan the swap before it expires. The platform never renews certificates.`
- Unreadable file: AMBER `Warning` chip with `Can't read this file.` instead of a date.
- Watchdog silent or not installed: entries show `Unknown` and `Last known expiry {date}.` or `No reading yet.`
- Empty (no certificates watched): cannot occur (the nginx certificate is always watched); if the payload is empty render `No certificates are being watched.`.

**Disk.** One entry per measured filesystem (at least the one holding `/` and the MongoDB data directory; the same disk appears once, listing both paths). Entry:
- Mount point `font-mono` 12/400; 14/600 `{n}% used`; 12/400 muted `{free} free of {total}` (GB with one decimal).
- Meter: `role="meter"` `aria-valuemin=0 aria-valuemax=100 aria-valuenow={n}` `aria-label="Disk used"`; track `h-2 rounded-full bg-gray-200 dark:bg-white/10`, fill coloured by rung (GREEN `bg-green-600`, BLUE `bg-blue-600`, AMBER `bg-amber-500`, RED `bg-red-600`), three hairline ticks at 80, 90 and 95 percent. The ladder chip sits to the right of the percent.
- Forecast line (14/400): `Forecast: full in about {n} days at the last 7 days of growth.` with its own ladder chip (14, 7, 1 days). Alternatives: `Usage is not growing. No forecast.`; `Not enough readings for a forecast yet.` (fewer than 7 days of history, neutral muted text, no chip).
- Footer note (12/400 muted): `Nothing is deleted automatically to free space. Free space yourself.`
- Watchdog silent or not installed: `Unknown` chip and `Last known: {n}% used at {HH:MM}.` or `No reading yet.`

### 5. On-call channel card (HEAL-04, D-01..D-05, D-21, D-22)

`.card p-6`, column `gap-4`. Subheading 14/600 `On-call alerting`. `dl`, `grid grid-cols-1 sm:grid-cols-3 gap-4`:

| Cell | Label | Value | Helper |
|------|-------|-------|--------|
| Channel | `Channel` | 14/600 `PagerDuty`, `Webhook`, or the chip `Not set up` | Not set up: `Set up a channel in the on-call file on the server, then send a test alert.` plus the install-checklist link. Configured: `Held on the server. The platform never sees the key.` |
| Status | `Status` | `Working` / `Not working` / `Not tested` chip | Working: `Last delivered {HH:MM}.` Not working: `Last attempt {HH:MM}: {error}` (`break-words`, server text capped at 300 characters). Not tested: `No alert has been sent yet. Send a test alert.` |
| External heartbeat | `External heartbeat` | 14/600 `Configured` or `Not configured` | Not configured: `Without it, nobody is paged if the watchdog or the whole server goes down. The install checklist recommends setting it up.` |

The key, routing key, webhook URL and heartbeat URL are never displayed, never sent to the browser and never logged in an Activity row. The panel shows only the channel type and booleans.

**Send test alert** (controls row under a `border-t pt-6` divider; shown to `control:platform_autonomous_ops` only): secondary-style button, `SendIcon` 16px, `min-h-10 px-4`, label `Send test alert`, `aria-describedby` on the helper.

Helper under the button, 12/400 muted: `The watchdog sends it within about a minute.`

Test state machine (state comes from the server so it survives a reload; the result line is a polite live region, `role="status"`):

| State | Button | Result line |
|-------|--------|-------------|
| Idle, never tested | enabled | none |
| Requesting (POST in flight) | disabled, label `Requesting...` | none |
| Requested, waiting for the watchdog | disabled, label `Waiting for the watchdog...`, `RefreshCwIcon` `animate-spin` | `Test requested at {HH:MM}. The watchdog sends it within about a minute.` Section polls every 5 s. |
| No answer after 90 seconds (default H10) | enabled, label `Send test alert` | amber line (`AlertTriangleIcon`): `The watchdog hasn't picked up the test request yet. Check that it is running.` |
| Delivered | enabled | green line (`CheckCircleIcon`): `Sent at {HH:MM}, delivered.` |
| Failed | enabled | red line (`XCircleIcon`, `role="alert"`): `Sent at {HH:MM}, not delivered: {error}` |
| Request failed (POST error) | enabled | red line (`role="alert"`): `Couldn't request a test alert: {server message}. Try again.` Fallback: `Couldn't request a test alert. Check your connection and try again.` |
| Watchdog not installed | disabled | helper replaced by `Install the watchdog first.` plus the checklist link |
| Watchdog silent | enabled | blue line: `The watchdog is silent, so a test can't be sent until it reports again.` and the button is `disabled` |

### 7. Confirm deletion dialog

**Amendment 2026-10-31 (gap plan 82-17):** the approved text kept `Keep waiting` live while the confirm request was in flight. `Keep waiting` is specified to leave every row waiting with nothing deleted, which is false once the request has been sent, so it is now disabled and Esc is off until the answer arrives (UI audit Fix 3).

## Accessibility and Interaction Notes

- Focus: global `:focus-visible` ring only. The Confirm dialog focuses its checkbox first (`showClose={false}`); a banner's `View details` moves focus to `#platform-health-title` (`tabIndex={-1}`) after navigation.
- Live regions: the watchdog-silent banner is `role="alert"` (appears once, urgent); the no-channel banner and the test-result line are `role="status"`; polling refresh is silent; errors are `role="alert"`. The test-result line does not re-announce on each 5 s poll (announce on state change only).
- Meters: disk uses `role="meter"` with `aria-valuenow` and a label; the numeric percent is always visible text, ticks are decorative.
- Chips carry icon plus text; the severity ladder is never colour-only.
- Tables: real `<table>` with caption and `scope` headers at `xl`; `dl` stacked cards below; right-aligned numeric column with `tabular-nums`.
- Times: `<time dateTime>`; clock times `HH:MM` in 24-hour local time (matches `formatStopDate`), retention schedule shown in UTC with the local time in `title`.
- Motion: only `animate-spin` and `animate-pulse` (both covered by the global reduced-motion rule); no entrance animation on banners, chips or the meter fill.
- Touch targets: `Send test alert`, `Confirm deletion`, `Load more rows` `min-h-10`; filter pills 32px.
- Text fit: no `truncate` on data (names, paths, errors, units). Paths, units and errors use `break-all` / `break-words`; server error text is capped by the server at 300 characters and rendered in full.
- Security of rendered strings: every string from the watchdog or the server (errors, paths, host names, reasons, tenant names) is rendered as React text; no `dangerouslySetInnerHTML`, no link-ification. The on-call key, routing key, webhook URL and heartbeat URL are never present in any API response the UI consumes. The install-checklist `url` is rendered only when it is a same-origin or `https:` URL (otherwise the path text is shown).
- Idempotency: `Send test alert`, `Confirm deletion` and `Load more rows` send one request per click (disabled while pending).
- Visibility: all Phase 82 surfaces are driven by `hasPermission('control:platform_autonomous_ops')` (the Phase 81 platform permission); a control the viewer cannot use is not rendered (inherited rule). The client never infers who may act.
