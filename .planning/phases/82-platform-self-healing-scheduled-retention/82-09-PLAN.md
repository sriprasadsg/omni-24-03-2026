<objective>
Build the one scheduled retention job (D-15): a type registry of the eight routine data types, a per-(tenant, type) gate that counts first and deletes only after a Super Admin confirms (D-18, D-19), bounded `_id` batches with pauses (D-17), a 02:00 UTC catch-up schedule under a distributed lock, and the removal of the separate telemetry loop it replaces.

Purpose: HEAL-06 - retention runs per tenant in bounded batches, never touches audit evidence or decision records, and its first run is a count the operator confirms.
Output: `retention_gate.py`, `retention_job.py`, migration 027, loop wiring and two test modules. The manual route, the review/confirm API and the Activity rows follow in 82-10.
</objective>
