<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| watchdog -> PagerDuty / webhook / heartbeat URL (internet) | Pages leave the VM over HTTPS with the routing key or webhook URL |
| backend outbox -> watchdog sender | Message text from the backend is forwarded but never treated as a command |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-82-16 | Information Disclosure | routing key, webhook URL, heartbeat URL | high | mitigate | Read only from oncall.env; never in logs, events, the sync body or results; test asserts no secret string in any posted body |
| T-82-17 | Spoofing | PagerDuty and webhook endpoints | medium | mitigate | Default verified SSL context for every https call; structural check that paging.py never builds an unverified context |
| T-82-18 | Denial of Service | alert storm / duplicate pages | high | mitigate | Grouped trigger per run, stable dedup_key, sent flag persisted before and after sending, 500-id delivered memory, at most 10 sends per run (PROH-82-08) |
| T-82-19 | Tampering | stale outbox messages paging much later | low | mitigate | Outbox TTL 24 h on the backend (82-07); delivered ids remembered so a lost acknowledgement never re-pages |
</threat_model>
