<objective>
Build the stdlib-only watchdog as a small package under `deploy/omni-watchdog/`: configuration and state handling, the four service checks with the D-06 debounce, and the sync client with its offline spool and the three-source stop (D-11). One run of `run_once` checks every service and reports to the backend through the contract frozen in 82-RESEARCH Pattern 3 (the backend side is 82-01). Restarts (82-03), warnings (82-04) and paging (82-05) plug into this run.

Purpose: HEAL-01 needs a checker that runs outside the backend every minute and still works when the backend's virtualenv, the backend or MongoDB is broken; HEAL-05's dead-man switch needs its heartbeat.
Output: the entry script, a package of six modules (each under 500 lines) and the shared watchdog test support with two test modules.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| /etc/omni-watchdog (root-owned) -> watchdog process | Config, token and on-call secrets are read-only to the watchdog |
| backend HTTP responses -> watchdog decisions | Stop state and later outbox/test requests arrive from a process the watchdog does not trust for commands |
| /var/lib/omni-watchdog (watchdog-owned) | State and spool; the backend user must not be able to edit them |
