<objective>
Freeze and build the backend side of the watchdog contract: one token-authenticated loopback endpoint that receives the watchdog's heartbeat, status snapshot and events (82-RESEARCH Pattern 3), stores watchdog events as `kind: "platform_health"` rows in the Autonomous Ops ledger at platform scope, renders their text server-side from a closed vocabulary, and guards every tenant and Platform Support view against them (D-23, Pitfalls 3 and 4).

Purpose: HEAL-07 needs watchdog events in the Activity view at platform scope only; HEAL-05 needs a channel the watchdog can report through when it holds the on-call key and the backend never does (D-01, D-04). Every later backend plan (82-07, 82-08, 82-10) and the watchdog's sync client (82-02) build on the shapes fixed here.
Output: the ingest router, `selfheal.py`, `health_messages.py`, `ledger.record_platform_health`, the leak guard in `views.py`, migration 025 and three test modules.
</objective>

Frozen sync contract (82-RESEARCH Pattern 3, field names verbatim; 82-02 implements the client side from the same text):
- Request `POST /api/internal/watchdog/sync`, header `Authorization: Bearer <token>`, body `{v: 1, host, sentAt, services: {<id>: {state, since, failedChecks, restartsInWindow, nextRestartAt, budgetReturnsAt, pagedAt, waitingOn, detail}}, certs: [...], disks: [...], oncall: {type, heartbeatConfigured, last}, stop: {effective, source}, events: [{id, at, kind, severity, target, params}], delivered: [...]}`.

- `POST /api/internal/watchdog/results` body `{v: 1, delivered: [...], testResult: {id, ok, error, at} | null}` answers `{ok: true}` (82-07 acts on its contents).
- WATCHDOG_EVENT_KINDS = service_down, service_recovered, restart, restart_skipped, gave_up, budget_rearmed, unexpected_running, cert_warning, disk_warning, disk_forecast, page_sent, page_resolved, page_failed, test_alert, state_reset. BACKEND_EVENT_KINDS = watchdog_silent, watchdog_back, retention_run, retention_confirmed (written by the backend only, never accepted from the watchdog).
- Event params keys (closed set, all optional): target, rung, daysLeft, notAfter, usedPct, forecastDays, attempt, seconds, ok, error, incident, channel, requestId, records, tenants, by, mode, minutes. Unknown keys are dropped. retention_run uses mode counted|deleted to pick "Counted {n} records across {t} organizations. Deleted nothing." or "Deleted {n} records across {t} organizations."; watchdog_silent uses minutes.
- healthChip per kind: service_down critical; service_recovered healthy; restart healthy when ok else critical; restart_skipped skipped; gave_up critical; budget_rearmed healthy; unexpected_running notice; cert_warning, disk_warning, disk_forecast by rung (1 notice, 2 warning, 3 critical); page_sent and page_resolved paged; page_failed critical; test_alert healthy when ok else critical; state_reset warning; watchdog_silent critical; watchdog_back healthy; retention_run healthy when ok else critical; retention_confirmed notice.
- Rule ids (font-mono in the UI): service-down, service-recovered, restart-budget, service-unexpected, cert-expiry-30d, cert-expiry-14d, cert-expiry-7d, cert-expiry-1d, disk-80, disk-90, disk-95, disk-forecast-14d, disk-forecast-7d, disk-forecast-1d, oncall-page, oncall-test, watchdog-heartbeat, state-reset, retention-run, retention-confirm.
