<objective>
Add the DOC-02 backend surface on top of plan 28-01: electronic signature capture on approved documents, and a signed-PDF export proving who signed and when.

Scope boundary (deliberate, per Resolved Decision 1): this is a lightweight ESIGN Act / UETA baseline e-signature — typed full name (re-entered to demonstrate intent) + an explicit consent checkbox + server-derived IP, user-agent, timestamp, and JWT identity. It is intentionally NOT a real e-signature provider integration (DocuSign / HelloSign) and NOT cryptographic/PKI signing. This baseline satisfies the four ESIGN/UETA requirements (intent to sign, consent to transact electronically, association of the signature with the record and signer, retention) at a fraction of the cost, reusing the codebase's existing BAA-sign + cookie-consent-capture precedents. This scope is a decision, not an oversight.

Purpose: closes DOC-02. Signatures append to the signatures[] array that 28-01 initialized (Resolved Decision 5 — an array from the start, so 1-to-N signers need no migration).

Output: sign endpoint + capture, signed-PDF export function + endpoint, and passing DOC-02 tests.
</objective>
