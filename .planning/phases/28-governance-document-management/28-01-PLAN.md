<objective>
Build the DOC-01 backend surface: versioned governance (policy/procedure) documents with a draft to pending_approval to approved to published state machine, where the approval step delegates entirely to the existing generic approval_service.py engine rather than a new one.

Purpose: policy_endpoints.py is unrelated automation-rule CRUD (confirmed — Pitfall 5), so governance documents are genuinely new surface. This plan establishes the collection, service, router, and DOC-01 test coverage that plan 28-02 (e-signature + signed-PDF) and plan 28-03 (dashboard) build on.

Scope boundary (deliberate, per Resolved Decisions): the approval workflow is a single fixed-role step (approvers = any tenant user holding manage:compliance), not per-tenant-configurable multi-step (Resolved Decision 3). The approval_service.py engine supports multi-step natively if ever needed — this phase simply does not configure it that way. A distinct published state is gated behind approved (Resolved Decision 4), since governance documents often need a scheduled effective date rather than approval == publish.

Output: governance_document_service.py, governance_document_endpoints.py, router registration, and a passing DOC-01 test suite.
</objective>
