<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser → settings PATCH | Threshold value entered by user; server re-validates (client clamp is convenience only) |
| browser → CoC fetch | Panel only fetches/renders for users the server authorizes; client permission gate is defense-in-depth |

## STRIDE Threat Register

| ID | Threat | Severity | Mitigation |
|----|--------|----------|------------|
| T-07-10 | CoC panel shown to unauthorized user (Information Disclosure) | High | Panel mounted only behind `hasPermission('view:audit_log')`; the 07-02 GET endpoint independently enforces tenant scope, so a client bypass still returns only the caller's tenant data (defense-in-depth). |
| T-07-11 | Wrong permission string disables the panel for all users (availability/correctness) | Med | Use `'view:audit_log'` (verified in types.ts line 205); `'audit:read'` is explicitly forbidden and grep-gated to 0 in FrameworkDetail.tsx. |
| T-07-12 | Threshold client clamp bypassed via devtools (Tampering) | Low | Client clamp to 1-365 is convenience only; the server enforces `Field(ge=1, le=365)` → 422 (07-02). |
| T-07-13 | XSS via rendered snapshot JSON (Tampering/Injection) | Med | Snapshot is rendered as text inside `<pre>{JSON.stringify(...)}</pre>` (React escapes by default); no `dangerouslySetInnerHTML`. |
</threat_model>
