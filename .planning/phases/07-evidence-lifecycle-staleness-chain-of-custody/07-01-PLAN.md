<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| caller → evidence_coc | Snapshot dicts and tenant_id passed by endpoint code; tenant already authenticated upstream |
| helper → MongoDB | Index creation and CoC insert cross into the data store |

## STRIDE Threat Register

| ID | Threat | Severity | Mitigation |
|----|--------|----------|------------|
| T-07-01 | CoC log tampering (Tampering) — entries altered or removed after write | High | `evidence_coc.py` exposes only `insert_one`; no update/delete helper exists. No mutation API is created. |
| T-07-02 | CoC append failure breaks the user-facing evidence operation (Denial of Service) | Med | `_append_coc_entry` is fire-and-forget: it swallows and logs exceptions, returning None so the parent mutation still succeeds. |
| T-07-03 | Cross-tenant CoC reads via missing index/scan (Information Disclosure) | Med | Compound index `(evidenceId, tenantId)` and `(tenantId, timestamp)` enforce tenant-scoped lookups for the 07-02 read endpoints; no scan of the whole collection. |
| T-07-04 | Wrong tenantId on audit record via double injection (Tampering) | Med | Raw Motor `db._db.evidence_audit_log` is used so `TenantIsolatedCollection` does not auto-inject a conflicting `tenantId`; the value is set explicitly. |
</threat_model>
