<objective>
Fix the pre-existing credential field-mapping bug that blocks CSPM-01/02/03 end-to-end (D-04 HARD BLOCKER), add provider-specific credential fields to the connect-account form, and surface the SIMULATED badge plus the three new providers in the cloud checks dashboard.

Purpose: Today `apiService.addCloudAccount()` posts `{name, credentials}` while the backend reads `{account_name, credentials_ref: string}` and silently discards the rest — so NO account registered through this form has ever stored real credentials, for any provider (RESEARCH Pitfall 4). The modal also never collects credentials into `onSave` at all. Until this is fixed, a scan has nothing to decrypt and every finding stays simulated. Separately, neither CSPM dashboard renders the `result.simulated` flag the backend already computes (ROADMAP success criterion 4: simulated data must be clearly labeled), and `CloudChecksScanner.tsx` hardcodes its provider icon map and filter dropdowns to `['aws','azure','gcp']`.

Output: corrected `addCloudAccount`, provider-conditional credential fields in `AddCloudAccountModal.tsx`, a SIMULATED badge and extended provider lists in `CloudChecksScanner.tsx`.
</objective>
