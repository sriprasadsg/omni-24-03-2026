<objective>
Add a real, account-scoped CSPM findings-ingest function to each of the three ingest modules — cloned from the proven `mongodb_atlas_ingest.py` template — that calls the live provider SDK and writes documents into `cloud_findings`. This is the "real, not simulated/stub data" half of CSPM-01/02/03 (RESEARCH Pitfall 2).

Purpose: `run_checks()` never calls a cloud API — it only evaluates what is already in `cloud_findings`. Without these functions every check stays `simulated: true`. Per D-01, findings are written to `cloud_findings` ONLY (single source of truth, no dual-write to `security_events`) — this plan realizes D-01's "retarget the write destination" intent additively. Each new function follows Pattern 4 (RESEARCH): it is ADDED alongside the existing 2-arg SIEM `poll_*` functions (which still write `security_events` and are live call sites for `cloud_integrations_endpoints.py`) — the existing functions' signature and write target MUST NOT change (Pitfall 3).

Output: `poll_oci_cspm_findings`, `poll_cloudflare_cspm_findings`, `poll_alibaba_cspm_findings` (V2 SDK), each `(config, account_id, tenant_id) -> int` writing `cloud_findings`, plus their unit tests.
</objective>
