<objective>
Close CR-03 (gap 1 of 84-VERIFICATION.md, PTCH-04 "halts ... only on a real failure and without harming the host"): `systemctl show` of a unit that does not exist exits 0 with ActiveState=inactive, which classify_systemd reads as Stopped, so a tenant-wide watched list fails the services signal of every host without that service and the ring is halted and reverted.

Key decision KD-84-G2: a unit that is not installed (LoadState not-found) or masked is reported with a new additive token `absent`, and the backend judges it against the host's pre-change baseline. The orchestrator suggested mapping it to `unknown`; that was not taken because `unknown` reads as no data, and missing data halts the ring after the soak (PTCH-02) and the halt reverts the ring (D-14) - the same harm to a healthy host under a different reason. `absent` keeps "missing data halts" intact for services that exist but do not report. Baseline rule (plan check, key_links): `absent` is dropped from the host's wanted list only when the host also reported it absent before the change; a watched service that was present before the change (any state but absent) and reads absent after it fails the services signal, because the patch itself may have removed, masked or deleted it; with no pre-change record, absent is no data. The baseline is the latest service_state block the host reported when its install was queued, recorded on the rollout host row (the same place reboots.record_baseline keeps the restart baseline). This plan runs after 84-27 because it adds one call to dispatcher.send and installs._send, which 84-23 and 84-27 change. Reversibility: costly - the token ships in agent 2.1.17, which is still unpublished, so it can change freely until the user publishes it (no version bump in this round).

Output: agent change with tests, contract token, pre-change baseline recorded at dispatch, backend signal rule with tests.
