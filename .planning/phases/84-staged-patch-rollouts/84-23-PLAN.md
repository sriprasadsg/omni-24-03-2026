<objective>
Close CR-01 and CR-02 (gap 2 of 84-VERIFICATION.md, PTCH-06 "one approval per stage" and "a rollout never hangs without an approval line"), plus WR-01 on the same code path.

Key decision KD-84-G1 (CR-02, within D-07 and PTCH-06): **Suggest raises approval lines.** A rollout row the gate records as `suggested` is treated exactly like `awaiting_approval`: it becomes the ring's Install (or Reboot) line with its own Approve and Deny. Rationale: a person has to approve it either way, so "one approval per stage" still holds, and the circuit breaker or unreadable settings can drop a tenant to Suggest in the middle of a running ring, which a Start-time refusal could never unwedge. Start keeps refusing only `off` (unchanged). Reversibility: reversible (server code only, no stored-shape change, no published contract).

Purpose: no rollout can sit at "installing" forever with no card and no way out because the gate did not dispatch a row.
Output: fixed canary branch, Suggest-aware lines and cards, dispatcher stores job and instruction ids, breaker ignores not-delivered rollout rows, a new test file.
</objective>
