<objective>
Close the two privilege-escalation paths the role-set decisions exposed: bundle assignment becomes
super-admin only (D-06, cross-tenant write through the isolation-exempt `tenants` collection), and
role assignment gets a ceiling — nobody assigns a role above their own or changes their own role
(D-18 refined by D-20, made workable for ITAM by D-21).

Purpose: user CRUD is gated by `manage:assets`, so today an `itam_admin` can create or promote a
user — including itself — to `admin`/`Tenant Admin`, which after D-01 carries `manage:rbac` and
`control:remote_access`. Only `super_admin` is blocked. Both findings came from code reading; each
fix ships with a regression test that fails on the pre-fix code.

Output: `backend/role_assignment.py` (the shared helper Plan 05 reuses for LDAP/SAML), guarded
bundle routes, a guarded `user_endpoints.py`, and the caller x target matrix test.
</objective>
