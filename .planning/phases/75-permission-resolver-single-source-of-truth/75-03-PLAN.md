<objective>
Replace the hardcoded three-role `GET /api/roles` stub with a real, gated role list computed by the
same resolver as `/me`, and make the frontend fail closed: an empty server permission list means no
catalogue access, with no fallback to the role list, and the cached role list never leaks to the
next user of the same tab.

Purpose: SC4 requires the ITAM roles to appear in an admin's role list. Today the stub returns an
"Admin" role whose permissions are "all", and `App.tsx` falls back to that list whenever
`currentUser.permissions` is empty — the fail-open path that hid the empty-ITAM-permissions bug
(D-17). D-15/D-16/D-26 define the new list, its gate and the cache hygiene.

Output: a real `backend/role_endpoints.py`, `utils/permissions.ts`, a slimmer permissions memo in
`App.tsx`, cache rules in `services/apiService.ts`, and tests on both sides.
</objective>
