<objective>
Collapse the three drifting permission sources into one table (`backend/rbac_defaults.py`) and one
async resolver (`rbac_service.effective_permissions`), deliver it through `/login` and `/me`, and
make `verify_permission` and `RBACService` enforce through the same resolver.

Purpose: today an ITAM-role user logs in with an empty permission list because `/login` and `/me`
return only a role document's permissions and no ITAM document exists; `/login` also cannot see a
tenant-scoped document at all because it runs with no tenant context. Enforcement
(`verify_permission`), `RBACService`, and delivery each compute a different set. This plan makes
the set one fact, answered by one function, so Phases 76 and 77 can rely on it (ACC-01, ACC-02).

Output: `backend/rbac_defaults.py`, the resolver pair in `backend/rbac_service.py`, a delegating
`verify_permission`, `/login` and `/me` wired to the resolver, the shared in-memory test store, and
three test files proving SC1, SC2, the table contents and enforcement parity.
</objective>
