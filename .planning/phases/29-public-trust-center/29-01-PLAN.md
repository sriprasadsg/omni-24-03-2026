<objective>
Retrofit the in-memory `TrustService` singleton onto two tenant-scoped Mongo collections (`trust_profiles`, `trust_access_requests`), repoint the existing authenticated admin routes at the async DB-backed service without changing their auth model, and add opaque `trust_slug` (auto-generated) + optional `trust_domain` fields on the `tenants` document so later plans can resolve a public request to a tenant. Also stand up the phase test scaffold (Wave 0) that every TRUST-01/02/03 assertion will build on.

Purpose: TRUST-01 requires trust data to persist across restarts; the current `self.profile`/`self.requests` state resets every boot. TRUST-03's custom-domain resolution needs a settable `trust_domain` and a stable `trust_slug` to key on.
Output: DB-backed `trust_service.py`, awaited admin routes in `trust_endpoints.py`, and `backend/tests/test_trust_center.py` with green persistence/tenant/admin_auth suites.
</objective>
