## Summary

Phase 13 adds AI-generated narrative sections to the scheduled compliance PDF reports already delivered by Phase 10. The narrative service is a thin stateless Python module (`compliance_narrative_service.py`) that builds sanitised prompts from compliance data and delegates to the already-wired `ai_service.generate_text` — no new framework, no new dependency, no new LLM client.

The key architectural insight from reading the source code is that there are **two separate PDF paths** in the scheduled reports system, and Phase 13 must wire into exactly the right one. The `_build_pdf` path (generic reportlab, used when no `framework_id` is set) is the target for AI narrative injection; the `_generate_pdf_for_schedule` path (which delegates to `compliance_reporting_pdf._generate_pdf`) is the richer per-framework compliance report and is **not** modified in Phase 13 — it generates its own PDF independently.

The `_generate_report` function is the single integration point: it collects data from MongoDB and returns a `data` dict that is later passed to `_build_pdf`. Narrative strings must be added to `data` inside `_generate_report` before that dict is returned, so `_build_pdf` can embed them.

**Primary recommendation:** Create `compliance_narrative_service.py` with `generate_executive_summary` and `generate_framework_narrative` (both async), wire both calls into `_generate_report`'s `compliance_summary` branch, modify `_build_pdf` to render the narrative text before the metrics table, and add the `narrative_generation_logs` collection for failure tracking.

### Two PDF Paths — Critical Distinction

This is the most important architectural finding for the planner:

**Path A — Generic PDF via `_build_pdf`** (target for Phase 13 AI narrative injection):
- Triggered when: `fmt == "pdf"` AND (`framework_id is None` OR `report_type not in ("compliance_summary", "custom_framework")`)
- Code: `pdf_bytes = _build_pdf(report_data)` in `_deliver_report`
- Output: Simple reportlab PDF with title, generated_at, metrics table
- Phase 13 action: Add narrative `Paragraph` to `story` before the metrics `Table`
- `report_data` flows from `_generate_report` → `_deliver_report` → `_build_pdf`

**Path B — Rich compliance PDF via `_generate_pdf_for_schedule`** (NOT modified in Phase 13):
- Triggered when: `fmt == "pdf"` AND `framework_id is set` AND `report_type in ("compliance_summary", "custom_framework")`
- Code: `pdf_bytes = await _generate_pdf_for_schedule(schedule, tenant_id, framework_id=framework_id)` 
- Output: Full compliance report with asset summary, control details, status colouring
- Phase 13 action: None — this path generates its own PDF independently of `report_data`
- Future phases could inject narratives here, but that requires modifying `compliance_reporting_pdf._generate_pdf`

### Anti-Patterns to Avoid

- **asyncio.run() inside an async function:** `_generate_report` is `async def` — calling `asyncio.run(generate_executive_summary(...))` inside it raises `RuntimeError: This event loop is already running`. Always `await` instead.
- **Embedding raw MongoDB strings in prompts without sanitisation:** `db.compliance_frameworks` name field and control name fields are user-supplied. Pass through `_sanitise()` before prompt interpolation.
- **Adding `ai_executive_summary` and `ai_framework_narratives` to the metrics table:** These must be in the `skip` set in `_build_pdf`, otherwise they will appear as raw dict entries in the table alongside "Open Alerts", "Asset Count", etc.
- **Modifying `compliance_reporting_pdf._generate_pdf`:** Phase 13 only modifies `_build_pdf` (Path A). The rich per-framework PDF (Path B) is out of scope.
- **Raising exceptions on narrative failure:** `generate_text` failures must return static fallback strings. No exception propagates to `_generate_report` (AI-06).
- **Using `ai_service.generate_text` with `provider=` kwarg:** Don't pass a provider — let the singleton's configured provider handle it. The `provider` param is for internal routing only.

## Don't Hand-Roll

| Problem | Don't Build | Use Instead | Why |
|---------|-------------|-------------|-----|
| LLM call + retry + circuit breaker | Custom AsyncAnthropic client with retry loop | `ai_service.generate_text` | Already has 3-retry backoff, circuit breaker, guardrail scan, provider switching |
| Input sanitisation | Custom HTML/XML escaper | `_sanitise()` in `compliance_narrative_service` (strip `<>{}\[]\\`) | Removes XML-breaking chars before prompt embedding |
| Output validation | Manual string checks | `NarrativeOutput.from_raw(raw)` with Pydantic `field_validator` | Validates non-empty, no error prefix, word count ≤ 250 atomically |
| Word truncation | Custom word-count splitter | `_trim_to_words(text, limit)` in `compliance_narrative_service` | Two-line function: `" ".join(text.split()[:limit])` |
| PDF generation | Custom PDF byte stream | `reportlab.platypus.Paragraph + SimpleDocTemplate` (already in `_build_pdf`) | Already handles layout, fonts, tables |
| Production tracing | Custom logging spans | Arize Phoenix (already wired in `app_startup.py`) | All `generate_text` calls with `source=` tag appear as named spans automatically |

**Key insight:** Phase 13 is a thin wiring layer. Every hard problem (retry, circuit breaking, guardrails, PDF layout, tracing) is already solved. The only new code is prompt construction + fallback logic.

## Common Pitfalls

### Pitfall 1: Wrong PDF Path
**What goes wrong:** Narrative text is added to `data` in `_generate_report`, but when `framework_id` is set, `_deliver_report` takes Path B (`_generate_pdf_for_schedule`) which never reads `data` — it calls `compliance_reporting_pdf._generate_pdf` independently. The narrative is generated but silently discarded.
**Why it happens:** Two distinct PDF paths share the same code entry point (`_deliver_report`) with a branch on `framework_id`.
**How to avoid:** Phase 13 only targets `_build_pdf` (Path A). Narrative generation should be gated: only add narrative calls to `_generate_report` when `report_type == "compliance_summary"` AND the caller will use Path A (i.e., no `framework_id` is set). Alternatively, always generate narratives and accept that Path B ignores them — the AI-SPEC integration pattern injects into `_generate_report` unconditionally for `compliance_summary`, relying on `_build_pdf` to render them.
**Warning signs:** Tests show narrative text returned but PDF does not contain it.

### Pitfall 2: Missing top_failing_controls in _generate_report
**What goes wrong:** `_generate_report` currently returns `data["frameworks"] = [{name, score}]` but does NOT populate `data["top_failing_controls"]`. Narrative functions receive an empty `failing_controls` list and produce generic text that fails the D1 (fidelity) eval dimension.
**Why it happens:** The Phase 10 implementation only needed framework names and scores for the report — failing controls were not needed for the metrics table.
**How to avoid:** Add a query for failing controls inside the `compliance_summary` branch of `_generate_report`. The exact query depends on the collection/field names used by `compliance_score_endpoints.py` — check that file for the authoritative aggregation pattern.
**Warning signs:** Promptfoo D1 eval fails; narrative text says "No failing controls recorded" when controls are actually failing.

### Pitfall 3: NarrativeOutput Validation Blocking Delivery
**What goes wrong:** `NarrativeOutput.from_raw(result)` raises `ValidationError` and the exception propagates to `_generate_report`, which propagates to `_deliver_report`, which logs a failure delivery — violating AI-06.
**Why it happens:** `ValidationError` is a non-`Exception` base in some Pydantic v1 configurations, but in Pydantic v2 it IS a subclass of `ValueError` which is a subclass of `Exception`. If `_validated_narrative` re-raises, delivery is blocked.
**How to avoid:** Catch `ValidationError` in `_validated_narrative`, log at WARNING, return the static fallback string. Never re-raise. The test for this is: mock `generate_text` to return an over-word-count string and assert the returned value is the fallback, not an exception.
**Warning signs:** Delivery logs show `failure` status when `generate_text` succeeds but returns verbose output.

### Pitfall 4: ai_executive_summary in Metrics Table
**What goes wrong:** `_build_pdf` iterates `report_data.items()` to build the `rows` list. If `ai_executive_summary` is not in the `skip` set, it appears as a metrics table row: `["Ai Executive Summary", "SOC 2 compliance at 85%..."]` — a paragraph of text crammed into a table cell.
**Why it happens:** The `skip` set was defined before Phase 13 fields exist. Easy to forget to update it.
**How to avoid:** Add `"ai_executive_summary"` and `"ai_framework_narratives"` to the `skip` set at the top of `_build_pdf`. Verify with a test that mocks `_build_pdf` and checks the story does not contain a Table row with the narrative key.
**Warning signs:** PDF renders with a weird metrics row containing multi-sentence prose.

### Pitfall 5: test_compliance_narrative_service.py Import Fails Before Implementation
**What goes wrong:** The test file imports `from compliance_narrative_service import generate_executive_summary` at the top level. If the file doesn't exist, ALL tests in the file fail with `ImportError` — this is actually the intended RED state for TDD.
**Why it happens:** TDD pattern requires tests to fail before implementation.
**How to avoid:** Document clearly in the plan that Task 1 (write tests) produces RED, Task 2 (implement service) produces GREEN. The 8 test classes must be written to import lazily (inside the test method) or the import must be deferred — review the Phase 12 test pattern where imports are inside test methods.
**Warning signs:** Conftest import errors that cascade to break other test files.

### generate_text Call — Correct Pattern

```python
# Source: ai_service.py lines 205-210, AI-SPEC Section 3
# compliance_narrative_service.py

import logging
import re
from pydantic import BaseModel, field_validator, ValidationError

from ai_service import ai_service   # module-level IncidentAnalyzer singleton (line 500)

logger = logging.getLogger(__name__)

_UNSAFE = re.compile(r"[<>{}\[\]\\]")

def _sanitise(v: str, max_len: int = 200) -> str:
    return _UNSAFE.sub("", str(v)).strip()[:max_len]

def _trim_to_words(text: str, limit: int) -> str:
    words = text.split()
    return " ".join(words[:limit]) if len(words) > limit else text

class NarrativeOutput(BaseModel):
    text: str
    word_count: int

    @field_validator("text")
    @classmethod
    def text_not_empty(cls, v: str) -> str:
        v = v.strip()
        if not v:
            raise ValueError("narrative text must not be empty")
        if v.startswith(("BLOCKED:", "Error:")):
            raise ValueError(f"LLM returned error string: {v[:80]}")
        return v

    @field_validator("word_count")
    @classmethod
    def within_budget(cls, v: int) -> int:
        if v > 250:
            raise ValueError(f"narrative exceeds word budget: {v} words")
        return v

    @classmethod
    def from_raw(cls, raw: str) -> "NarrativeOutput":
        words = raw.split()
        return cls(text=raw.strip(), word_count=len(words))

def _validated_narrative(raw: str, fallback: str) -> str:
    try:
        output = NarrativeOutput.from_raw(raw)
        return output.text
    except ValidationError as exc:
        logger.warning("[NarrativeService] Pydantic validation failed: %s", exc)
        return fallback

async def generate_executive_summary(
    framework_name: str,
    score: float,
    failing_controls: list[str],
    period: str,
) -> str:
    safe_fw = _sanitise(framework_name)
    safe_controls = [_sanitise(c, 80) for c in failing_controls[:5]]
    controls_block = "\n".join(f"- {c}" for c in safe_controls) or "- None recorded"
    fallback = (
        f"This report presents the {safe_fw} compliance posture for the reporting period. "
        f"The overall compliance score is {score:.1f}%. "
        "Detailed findings are available in the per-framework section below."
    )
    system_part = (
        "You are a compliance analyst writing an executive summary for a PDF report. "
        "Write in clear, non-technical prose suitable for a C-level audience. "
        "Do not invent control names, scores, or findings not present in the data below. "
        "Respond with the summary text only — no preamble, no markdown, no bullet points."
    )
    user_part = (
        f"<compliance_data>\nFramework: {safe_fw}\nCompliance score: {score:.1f}%\n"
        f"Reporting period: {period}\nTop failing controls:\n{controls_block}\n"
        "</compliance_data>\n\nWrite an executive summary of no more than 150 words."
    )
    result = await ai_service.generate_text(
        f"{system_part}\n\n{user_part}", source="compliance_narrative"
    )
    if result.startswith(("BLOCKED:", "Error:")):
        logger.warning("[NarrativeService] generate_text failed: %s", result)
        return fallback
    trimmed = _trim_to_words(result.strip(), 150)
    return _validated_narrative(trimmed, fallback)
```
