<objective>
Close two verified data-integrity / DoS findings in the bulk evidence upload endpoint, both located in `backend/compliance_bulk_evidence_endpoints.py`:

- SEC-01 — Replace the spoofable `sum(i.file_size for i in zf.infolist())` total-size pre-check with a cross-entry accumulator (`total_actual_bytes`) that counts actual decompressed bytes inside the existing bounded chunk-read loop.
- SEC-02 — Add a compensating `delete_many` DB rollback (scoped by collected inserted IDs) when the commit loop throws mid-batch, so a partial batch failure never leaves orphaned `control_evidence` records.

Purpose: A holder of a valid JWT could craft a zip with `file_size=0` entries to bypass the 200 MB guard and force up to ~1.25 GB of decompression (SEC-01); and a mid-batch insert failure currently leaves DB records pointing at deleted disk files (SEC-02). Both are real findings from the Phase 8 code review.

Output: An updated endpoint that bounds total decompression by real bytes and rolls back partial DB commits, plus three new/updated tests proving both behaviors.
</objective>
