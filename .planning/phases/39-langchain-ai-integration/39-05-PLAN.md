<objective>
Build the shared agent substrate every surface migration (39-06..09) depends on: the tenant-scoped retrieval and evidence @tool factories (closing tenant_id over the closure, never model-supplied — the structural mitigation for Critical Failure Mode #1 cross-tenant leakage), the versioned prompt constants, and the online guardrail hooks that wrap every agent ainvoke (AI-SPEC Section 6). This is the connective tissue that keeps the four create_agent call sites DRY and keeps the tenant-isolation + guardrail invariants in one place instead of four.

Purpose: One tool factory, one guardrail hook set, one prompt registry, one decision-log writer — so the four agent plans wire behavior, not re-derive it, and the tenant-closure + guardrail + audit-log rules cannot drift per surface.
Output: tools/retrieval.py, tools/evidence.py, prompts.py, guardrails.py, decision_log.py, and hermetic unit tests.

## Decision: agent_ai_decisions schema reconciliation (RESEARCH Pitfall D — Claude's Discretion per CONTEXT.md)

**Chosen: Option (a) — same collection, new surface-discriminated document shape.** Phase 39 decision records are written into the existing `agent_ai_decisions` collection (not a new collection) as a NEW document shape: `{_id, surface: "auditor"|"chat"|"questionnaire"|"narrative", source: "langchain", tenantId (auto-injected), model_provenance, prompt_version, control_id/question_id/thread_id (surface-specific ref), outcome (e.g. pass|fail|insufficient_evidence|blocked), citation_validation (pass|blocked), started_at, completed_at}`. No `agent_id` or `tool_name` field is set on Phase 39 docs.

Rationale (verified against the code this session):
1. **No existing reader breaks by construction.** The only read path, `GET /{agent_id}/agentic-tasks/decisions` (`agentic_tasks_endpoints.py:127`), filters `{"agent_id": agent_id}` — Phase 39 docs carry no `agent_id`, so they can never appear in that endpoint's results. The only other touch points are `update_one({"_id": decision_id})` correlation calls keyed to agentic-task decision IDs.
2. **The collection is already the AI-03 audit log with the right properties**: per-tenant `tenantId` auto-injection via TenantIsolatedCollection, a `(source, started_at)` index (`database.py:317-319`) that directly serves "all langchain decisions" queries, a `(tenantId, started_at)` index for per-tenant defensibility queries, and deliberately NO TTL (SOC 2 CC6.1 — audit records not auto-purged). A second collection would need all of this re-created and would fragment the auditor-facing "show me the AI decision log" story AI-SPEC Section 1b/7 depends on.
3. The existing `source` field/index already anticipates multiple writer families (`source: "agentic_ai"` today) — `source: "langchain"` plus the `surface` discriminator is an extension along an existing axis, not a shape collision.

This resolves AI-SPEC Section 7's "trace attributes feed agent_ai_decisions" claim concretely: the same attributes stamped on Phoenix spans (tenant, surface, PROMPT_VERSION, model_provenance) are persisted per decision via `log_ai_decision`, called by all four agents (39-06..09).
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| model → retrieval tool args | If tenant_id were a tool parameter, a prompt-injected doc could redirect retrieval to another tenant |
| retrieved evidence → agent output | Injection instructions embedded in evidence must not reach the system prompt or bypass output scan |
| agent output → user/persistence | Cross-tenant identifiers in output are a confidentiality incident, not a quality bug |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-39-05-A | Elevation of Privilege | Tenant filter as model-supplied tool arg | mitigate | tenant_id closed over in factory; test asserts args schema exposes only query; grep-gate forbids get_tenant_id in tool bodies |
| T-39-05-B | Information Disclosure | Cross-tenant identifier in agent output | mitigate | cross_tenant_output_scan blocks + flags as security incident (Section 6 block+page) |
| T-39-05-C | Tampering | Prompt injection via retrieved evidence | mitigate | evidence arrives as tool output, never interpolated into system prompt (Section 4b) |
| T-39-05-D | Repudiation | AI decision without a defensible audit record (AI-03) | mitigate | log_ai_decision persists surface-discriminated decisions to agent_ai_decisions (no TTL, tenant-scoped); never-raise contract so audit failure is logged loudly, never silently dropped |
</threat_model>
