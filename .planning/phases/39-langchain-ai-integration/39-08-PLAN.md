<objective>
Migrate the questionnaire auto-answer surface onto create_agent with the citation-required CitedAnswer structured output, replacing the hand-rolled JSON-extraction path, while preserving the exact Mongo document shape, the `draft_answer_for_question` contract, and — critically — the RAG-02 human-approval gate (drafts always land `pending_review`, never auto-submit). This surface produces contractual representations to third parties, so answer honesty and the human gate are load-bearing (Critical Failure Mode #4).

Purpose: Collapse the bespoke JSON parser onto one framework-managed structured-output mechanism with mandatory citations, without changing the reviewer/frontend contract or weakening the approval gate.
Output: agents/questionnaire.py, the questionnaire_answer_draft_service.py shim, and agent unit tests.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| LLM draft → questionnaire_answer_drafts | Draft untrusted until schema-validated + citation-resolved; must never auto-submit |
| draft → external recipient | Any draft reaching a prospect without human approval is a contractual misrepresentation |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-39-08-A | Tampering | Over-claiming answer with no evidence (Failure Mode 4) | mitigate | CitedAnswer grounded_or_flagged + validate_citations; low-confidence -> insufficient_evidence |
| T-39-08-B | Elevation of Privilege | Draft auto-advancing to submitted | mitigate | Shim always writes pending_review; grep-gate forbids "submitted"; RAG-02 gate in endpoint unchanged |
| T-39-08-C | Information Disclosure | Cross-tenant evidence in a draft | mitigate | Tenant-closed retrieval tool + cross_tenant_output_scan |
</threat_model>
