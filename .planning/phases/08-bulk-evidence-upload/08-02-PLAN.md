<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser → FormData POST | Zip file bytes and manifest JSON travel to the backend endpoint; all validation is server-side |
| manifest JSON file → client state | User-provided JSON file is parsed client-side (structural check only); server performs authoritative validation |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-08-FE-01 | Tampering | Content-Type header injection on FormData | mitigate | No explicit Content-Type header set on FormData POST (per T-02-07); browser sets correct multipart boundary automatically |
| T-08-FE-02 | Spoofing | Client-side manifest validation bypass | accept | Client validates JSON structure only; all security-relevant validation (extension, magic, size, tenant) is server-side; no bypass is possible at the protocol level |
| T-08-FE-03 | Information Disclosure | Error details from 422 response displayed to user | accept | Error details (filename + validation reason) are safe to display to the uploading user; they contain no server-side secrets |
| T-08-FE-04 | DoS | Large manifest JSON file parsed in browser | mitigate | Manifest entries > 50 are rejected by the server with a 400 before processing; client-side structural parse is synchronous and fast for the 50-entry max |
| T-08-SC | Tampering | npm/pip/cargo installs | accept | No new packages; all UI uses existing Tailwind + Lucide React + React stdlib |
</threat_model>
