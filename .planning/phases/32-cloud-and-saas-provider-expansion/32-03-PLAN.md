<objective>
Deliver PROV-03: GitHub, Okta, Google Workspace, Slack, and Jira gain native, catalogued posture checks (id/severity/remediation/frameworks) — not just free-text evidence rows. The live HTTP data collection already exists and runs in production (Phase 14's pull_*_evidence()), each item already computing status pass/fail/no-data. This plan adds a thin reshaping layer in a NEW file (saas_integration_service.py is exactly at the 500-line cap) that reuses pull_all_evidence() and maps each evidence item's existing status onto a matching catalog check, writing cloud_check_results-shaped documents to a new tenant-scoped saas_check_results collection.

Purpose: Bring the five OAuth SaaS providers to structural parity with the CLOUD_CHECKS/IAC_CHECKS catalog contract, without duplicating or re-fetching any vendor API call.
Output: saas_posture_checks_service.py (catalogs + run_posture_checks), saas_posture_checks_endpoints.py (router), its registration in router_registry.py, and test_saas_posture_checks.py.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client → /api/saas/posture-checks | connection_id crosses here; must be tenant-scoped before any read/write |
| run_posture_checks → pull_all_evidence | the evidence.status is the single source of truth reshaped into check results |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-32-05 | Tampering (compliance-signal integrity) | run_posture_checks status mapping | high | mitigate | Pure reshaping of pull_*_evidence()'s already-computed status; unit test asserts evidence.status=='fail' always yields result=='FAIL' for every mapped check — no independent re-derivation logic exists to drift |
| T-32-AC | Information Disclosure / Access Control (V4) | saas_check_results reads/writes + connection lookup | high | mitigate | Every query tenant-scoped (tenantId in upsert key and connection lookup); cross-tenant connection access returns 404, matching saas_integration_endpoints isolation |
| T-32-DUP | Denial of Service | vendor API rate limits | low | accept | run_posture_checks reuses the single pull_all_evidence call rather than re-fetching, so it adds zero incremental API volume |
</threat_model>
