<objective>
Deliver PROV-02's user-confirmed real-findings ingestion (RESEARCH Open Question #2, resolved: real findings ingestion). M365 (Microsoft Graph secureScores, auth via the already-resolvable msal) and MongoDB Atlas (Admin API via requests.auth.HTTPDigestAuth, zero new deps) become the FIRST providers whose checks evaluate against real polled findings written to cloud_findings. Two new ingest modules mirror the azure_defender_ingest.py never-raise contract but write to cloud_findings (keyed by accountId+tenantId) instead of security_events. scan_account() is hooked to run the matching ingest before run_checks(), so the Plan 32-02 simulated provenance flag flips to false for these two providers.

Purpose: Break the "every check always PASSes against an empty cloud_findings" precedent for exactly these two providers, without disturbing the existing catalog-only providers (whose behavior Plan 32-02 already proved unchanged).
Output: m365_ingest.py, mongodb_atlas_ingest.py, the scan_account() dispatch hook, and test_cloud_findings_ingest.py.
</objective>
