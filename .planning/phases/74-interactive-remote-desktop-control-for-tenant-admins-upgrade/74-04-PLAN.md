  <action>
Create `agent/capabilities/consent_ui.py` as the Python counterpart of `consent_ui.rs`. Match the
Rust module's public vocabulary so the two agents behave identically: `request_consent`,
`show_stop_bar`, `hide_stop_bar`, `stop_requested`, and a decision vocabulary of the same three
words the Rust side writes to its decision file.

Guard the pywin32 imports at module scope with `platform.system() == "Windows"`, following the
`winreg` guard at the top of `remote_access.py`, so importing this module on a Linux dev box or in
the test run does not raise. On non-Windows every public function returns the same
no-interactive-desktop failure shape.

The session-injection sequence is `win32ts.WTSGetActiveConsoleSessionId`, then
`win32ts.WTSQueryUserToken`, then `win32security.DuplicateTokenEx`, then
`win32profile.CreateEnvironmentBlock`, then `win32process.CreateProcessAsUser` with a
`STARTUPINFO` whose `lpDesktop` is set to the default window station and desktop. A session id of
`0xFFFFFFFF` is the no-interactive-user sentinel and returns the refusal immediately, before any
spawn is attempted — the same sentinel the Rust agent and `heartbeat.rs` both already use, so
D-02 behaves identically on both trees.

RESEARCH.md flags this composed sequence as cited-from-docs rather than executed (Assumptions Log
A1): `win32profile.CreateEnvironmentBlock`'s argument order and pywin32's `STARTUPINFO` wrapper
have known divergences from the raw C API. Build it defensively — wrap the sequence so a failure
at any step returns a typed spawn-failure carrying the failing call's name rather than a bare
traceback, and close every handle in a `finally`. Do not import `pyautogui`, `pynput`, or any
other automation library; do not use `win32api.keybd_event` or `mouse_event`, which Microsoft
superseded with `SendInput`.

Reuse the two PowerShell WinForms scripts from `consent_ui.rs` rather than designing new ones —
same 440x240 consent dialog and same 360x48 stop bar, same hex colors, same Segoe UI point sizes,
same copy strings, same wrap-the-identity and ellipsis-the-bar-name rules, same 60-second timeout.
The endpoint user must not be able to tell which agent implementation is installed.

Pass the requester identity through a per-session JSON config file written to the agent's data
directory and hand the script only that path. The identity strings are untrusted tenant-user input
crossing into a process spawn; interpolating them into the PowerShell command line would be an
injection on the endpoint. Delete the config file and the decision file after reading, whatever
the outcome.

Persist no consent state across sessions — no allow-list, no remembered tenant, no cached
decision. D-04 requires a fresh prompt every session, and the way that cannot regress is for no
such storage to exist.
  </action>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| backend instruction payload → Python agent | Requester identity strings cross into a SYSTEM-privileged service process |
| tunnel WebSocket → `on_message` | Attacker-influenced JSON frames enter the agent for the first time on this tree |
