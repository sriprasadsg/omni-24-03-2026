<objective>
Build the endpoint half of the consent contract on the canonical Rust agent: a real Accept/Decline
dialog that appears on the logged-in user's desktop from a Session-0 service, a persistent
revocable stop-control bar, and an input replayer that will not call `SendInput` until Accept has
actually been observed.

Purpose: D-01 calls the consent prompt "a hard gate — the RBAC permission alone does not grant
control", and D-09 exists because consent that cannot be revoked mid-session is not consent.
Both promises live entirely in this plan; the backend and browser can only report what the
endpoint decides.

Output: `consent_ui.rs`, and the input path in `remote_access.rs` finished and gated.
</objective>

Finish the input path in `desktop_stream_run` and gate it.

Sequence for a control-mode session, before the input read task begins accepting anything:
  1. Call `consent_ui::request_consent` with the `requester_name`, `requester_email`, and
     `tenant_name` fields Plan 02 added to the instruction payload, and a 60-second timeout — the
     UI-SPEC's default, adopted here as the planner's decision rather than left open.
  2. On `ConsentError::NoInteractiveSession`, send an error frame carrying `"reason":"no_interactive_desktop"`
     with the UI-SPEC's D-02 message and return. Do not reuse the existing view-mode 0x0-screen-bounds
     string verbatim: RESEARCH.md Pitfall 4 is that the dashboard currently cannot tell offline from
     wrong-OS from no-session apart, and the discriminant is what fixes it.
  3. On `ConsentDecision::Decline` or `Timeout`, send a `control_state` frame with state `ended` and
     a reason of `consent_declined` or `consent_timeout`, then return.
  4. On `ConsentDecision::Accept`, POST the decision to `POST /api/remote/session/{session_id}/consent`
     with the `X-Tenant-Key` header carrying the registration key, so the audit trail learns the
     decision from the tunnel-authenticated agent rather than from the browser. Report Decline and
     Timeout to the same route before returning in step 3. Treat a failed POST as non-fatal for the
     session but log it — a lost audit record must not silently become a lost control session, and
     the reverse is worse.
  5. Call `consent_ui::show_stop_bar`, send a `control_state` frame with state `active`, and only
     then let the input read task start replaying.

Hold the accepted state in a value the read task consults before every single `SendInput` call, not
once at task start. Between two frames the endpoint user may have clicked Stop Control, and a gate
checked only at startup would keep injecting input after revocation. Check `consent_ui::stop_requested`
on the same path; when it becomes true, send a `control_state` frame with state `ended` and reason
`endpoint_stop`, call `hide_stop_bar`, and end the session.

Complete `control_input_replay` to cover every INTEGRATE row in COVERAGE.md: absolute mousemove as
built in Plan 01, left/right/middle button down and up, `XDOWN`/`XUP` for buttons 3 and 4, vertical
`WHEEL` and horizontal `HWHEEL`, key down and key up by virtual-key code, `KEYEVENTF_EXTENDEDKEY`
for the extended set, and `KEYEVENTF_UNICODE` with the UTF-16 code unit in `wScan` when the frame
carries a unicode value and a virtual-key code of zero. Omitting the extended-key flag silently
breaks arrows and Delete, and omitting the Unicode path types wrong characters on any keyboard
layout the endpoint does not share with the admin — both are the exact half-integration the coverage
matrix exists to prevent. Write no key-combination blocklist: D-05 forbids one, and Windows already
refuses to let `SendInput` synthesize the Secure Attention Sequence.

Add a replay rate ceiling: cap `SendInput` calls at a fixed number per second per session and drop
excess frames rather than buffering them. A frame flood must degrade to dropped input, never to
unbounded memory or an unresponsive endpoint.

On any exit from the read loop — tunnel close, read error, or stop — call `hide_stop_bar` and clear
the accepted state before returning, so a reconnect starts from no-consent. That is D-12: the
session is over, and the next attempt asks again.

Extend the `#[cfg(test)] mod tests` with parse and gate coverage that runs on Linux: every INTEGRATE
kind parses, the rejection cases hold, and a small state helper representing the consent gate refuses
to authorise replay until it has been set to accepted and refuses again once stop has been signalled.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
