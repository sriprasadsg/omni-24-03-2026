# Phase 61 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none — declined (see rationale below) |
| Preset | not applicable |
| Component library | none (plain Tailwind + this repo's own `components/ui/Modal.tsx`) |
| Icon library | `components/icons.tsx` — local hand-rolled stroke-icon module (lucide-style paths, no runtime dependency on the `lucide-react` package for these components) |
| Font | Outfit (`fontFamily.sans`, `tailwind.config.js`) |

**shadcn gate outcome:** `components.json` is absent from the repo, and no phase across 60 prior phases has ever introduced shadcn — every console/dashboard in this codebase (including the exact clone target for this phase, `components/NativeSecurityConsole.tsx`) is plain Tailwind utility classes over a hand-rolled dark theme. 61-RESEARCH.md's own Package Legitimacy Audit confirms **zero new npm packages** are needed for this phase. Introducing shadcn now would fork the design language for one console against 60+ phases of established precedent, and would contradict the phase's own "clone verbatim" recommendation. Declined; this contract codifies the existing de facto design system instead.

## Spacing Scale

Declared values (must be multiples of 4) — already the established scale across `NativeSecurityConsole.tsx`, `Modal.tsx`, and every existing tab component:

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, tab-nav item gap (`gap-1`) |
| sm | 8px | Compact spacing, button vertical padding (`py-2`) |
| md | 16px | Default element spacing, button horizontal padding (`px-4`), nav bottom margin (`mb-4`) |
| lg | 24px | Console page padding (`p-6`), header bottom margin (`mb-6`), Modal body padding (`p-6`) |
| xl | 32px | Reserved for cross-tab layout gaps (not yet used, available if a tab needs a two-column layout) |
| 2xl | 48px | Reserved for major section breaks (not used at console-tab scale) |
| 3xl | 64px | Not used in this phase |

Exceptions: none.

## Typography

Existing codebase uses 3 informal weights (`font-bold`/`font-semibold`/`font-medium`) across similar components. Per the 2-weight-max contract, this phase's new `components/itam/*.tsx` files consolidate to 2 weights — a deliberate, minor tightening of the clone target, not a new invention:

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body / table cell | 14px (`text-sm`) | 400 regular (`font-normal`) | 1.5 |
| Label / meta / badge | 12px (`text-xs`) | 600 semibold (`font-semibold`) | 1.4 |
| Heading (tab section title, Modal title) | 18px (`text-lg`) | 600 semibold (`font-semibold`) | 1.2 |
| Display (console page H1) | 24px (`text-2xl`) | 600 semibold (`font-semibold`) | 1.2 |

Note: `NativeSecurityConsole.tsx`'s literal H1 uses `font-bold` (700) — new ITAM components use `font-semibold` (600) at the same 24px size instead, to hold the line at exactly 2 declared weights platform-wide for this phase. The visual difference is negligible; do not introduce a third weight anywhere in `components/itam/`.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#111827` (Tailwind `gray-900`) | Console page background |
| Secondary (30%) | `#1f2937` (Tailwind `gray-800`) / `#374151` (`gray-700` borders) | Modal body, table row zebra/hover, section cards, nav bottom border |
| Accent (10%) | `#06b6d4` / `#0891b2` (Tailwind `cyan-500` / `cyan-600`) | Active tab underline + active tab text, primary action buttons (Add Asset, Add Manufacturer, Check Out, Assign Seat, Save), Modal confirm button, focus rings |
| Destructive | `#dc2626` / `#ef4444` (Tailwind `red-600` / `red-500`) | Delete catalog entity, Delete license, Reclaim seat, inline error text, error toasts |

Accent reserved for: active tab indicator (underline + text color), the single primary CTA button per tab/modal (never more than one accent-filled button visible per view), Modal's `onConfirm` button, and focus-visible rings on interactive controls. Never apply accent color to passive/informational UI (badges, table headers, borders).

**Supplementary status-badge colors** (secondary semantic palette for `lifecycleStatus`/warranty/license-expiry chips — not part of the core 60/30/10 split, but required by ITAM-LIFE-01/ITAM-FIN-02/ITAM-LIC-01 data this phase renders):
- `green-500`/`green-600` (`#22c55e`/`#16a34a`) — deployable, active/compliant, license has available seats
- `yellow-400`/`amber-500` (`#facc15`/`#f59e0b`) — deployed (in-use, neutral-positive), warranty/license expiring within alert window, pending states
- `gray-500` (`#6b7280`) — archived, retired, disposed (neutral/inactive)
- `red-400`/`red-500` — broken, warranty/license expired, overdue audit

These mirror the exact palette already used in `components/nativeSecurity/AuditTab.tsx` (`STATUS_COLORS` map) and `components/AssetComplianceList.tsx` — clone that mapping pattern rather than inventing new hex values.

## Component Inventory & Scope Notes (for planner/executor)

These resolve 61-RESEARCH.md's three Open Questions as UI-contract decisions, consistent with 61-CONTEXT.md's locked decisions (tabs for main sections, paginated tables with search/filter, modal dialogs for all actions, direct integration of `AssetComplianceList`/`SoftwareInventoryTab`):

1. **Tab layout — 6 tabs, not 4.** The four ROADMAP-named tabs (Catalog, Check-Out/In, Procurement & Finance, Licenses & Consumables) plus two additional tabs for the two existing components CONTEXT.md says to integrate directly: **Compliance** (wraps `AssetComplianceList` with a new control-picker dropdown + data-fetch wrapper cloned from `FrameworkDetail.tsx`'s wiring) and **Software Inventory** (wraps `SoftwareInventoryTab` with a data-fetch wrapper cloned from `SoftwareDeployment.tsx`'s wiring). Tab bar renders all 6 using the exact `TABS` array + `aria-current` pattern from `NativeSecurityConsole.tsx`.
2. **Licenses & Consumables tab is licenses-only for this phase.** No consumables/components UI is built against nonexistent routes (per 61-RESEARCH.md's confirmed backend gap for ITAM-LIC-02/03). The tab label stays "Licenses & Consumables" per the ROADMAP goal text, but its body renders only license CRUD + seat assign/reclaim; a small note ("Consumables and component tracking are not yet available.") is shown beneath the license table so this isn't a silent omission.
3. **`manage:itam` permission** is granted to the same roles that already hold `manage:assets` (admin, Tenant Admin) in both `backend/rbac_utils.py` and `backend/rbac_service.py`, per Pitfall 2 — this is a planning/backend task, noted here only because it gates whether the console described in this spec is ever visible.
