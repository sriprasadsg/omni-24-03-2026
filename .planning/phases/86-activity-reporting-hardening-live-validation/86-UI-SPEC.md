# Phase 86 — UI Design Contract

> Visual and interaction contract for Activity Reporting, Hardening and Live Validation. Six surfaces: (1) a **Statistics** card on the Autonomous Ops screen (period choice, headline numbers, per-rule table with a separate simulation column, time-saved estimate with its method); (2) an **Export** button and dialog beside the Activity list (CSV or PDF, 5,000-row cap note); (3) an **Autonomous Ops Activity** card in the Reporting screen's Data Export Center; (4) the **daily digest** text (in-app notice and email); (5) a platform-only **Going live** card with the five-item live checklist; (6) the per-organization **Lift shadow mode** control and its dialogs. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
> Locked inputs: 86-CONTEXT.md D-01..D-17. Nothing here re-opens them. Details the context left open are recorded as researcher decisions in "Assumptions Recorded" (R1..R16); the planner treats them as decided unless the user overrules. No user was available for this run (autonomous mode).
> Extends, does not replace, `81-UI-SPEC.md`, `82-UI-SPEC.md`, `83-UI-SPEC.md`, `84-UI-SPEC.md` and `85-UI-SPEC.md`: tokens, the four-size and two-weight type scale, the spacing scale, chip anatomy and tones, `.card`, `Modal` conventions (`showClose={false}`, `closeOnBackdrop={false}`), `EmptyStateCard`, `HealthNotice`, the collapsed settings-card anatomy (83 section 6), filter-pill classes, the simulation marks (dashed border, `FlaskConicalIcon`), the 900 px table budget (except for the two wide tables of sections 2e and 6c, which scroll sideways inside their card) and the stop and shadow rules are inherited as written. Only deltas are declared.
> New infrastructure: none. No new library, token, colour, chip tone or icon. Files read for this contract: `components/AutonomousOpsActivity.tsx`, `AutonomousOpsActivityList.tsx`, `AutonomousOpsStatusCard.tsx`, `AutonomousOpsHealthChips.tsx`, `AutonomousOpsResponseSettingsPlatform.tsx`, `AutonomousOpsResponseSettingsDialogs.tsx`, `ReportingDashboard.tsx` (lines 144-182, 547-601), `NotificationCenter.tsx`, `Modal.tsx`, `icons.tsx`, `backend/autonomous_ops/notify.py`, `backend/pending_agents.py`, `backend/export_report_endpoint.py`, `backend/autonomous_ops_platform_endpoints.py`.

> Revised 2026-11-14 for UAT gap G-86-5 (plan 86-16). The two wide tables are wider than the card's content column between 1024 px and their fit widths, so each scrolls sideways inside its card in a keyboard-focusable, labelled region (`role="region"`, `aria-label` = the caption, `tabIndex` 0, `overflow-x-auto`). The inherited 900 px table budget is a constant that never accounted for the shell, so it does not apply to these two tables (sections 2e and 6c).

## Spacing Scale

Inherited unchanged from 81-UI-SPEC (4, 8, 16, 24, 32, 48; 64 unused). Phase 86 usage:

| Token | Tailwind | Usage in this phase |
|-------|----------|---------------------|
| xs 4px | `1` | Icon-to-text gap in chips, buttons and table headers |
| sm 8px | `2` | Gap between pills, chips and the buttons of one row; stacked helper lines; numeric table cell `py-2` |
| md 16px | `4` | Table cell `px-4`, readout cell padding, check row padding, dialog block padding, gap between readout cells |
| lg 24px | `6` | Card padding (`.card p-6`), gap between sections inside a card (`space-y-6`), dialog gaps |
| xl 32px | `8` | Empty-state card padding (unchanged) |
| 2xl 48px | `12` | Empty-state icon circle (unchanged) |

Exceptions (all multiples of 4):
- Period pills use the filter-pill size (`min-h-8`, `px-3`).
- `Export activity`, `Download CSV`, `Download PDF`, `Record this check`, `Record check`, `Lift shadow mode`, `Turn shadow mode on`, `Turn shadow mode back on` and every dialog confirm are `min-h-10` (40px, `px-4`), the consequential-control rule.
- Format and period radio rows in the Export dialog: `min-h-10`, the whole row is the hit area.
- Note and confirmation inputs: textarea `min-h-24` (96px, `rows={3}`); typed-name input `min-h-10`.
- Per-rule table: numeric columns `px-4 py-2` (dense, a multiple of 4). Column minimums: Rule 240, seven count columns 72 each (504), Would have done 144. A `min-w-[72px]` on a border-box `th` includes the 32px of `px-4`, so a header such as `Approved` needs about 82px and the measured table is about 946px. The table scrolls sideways inside the card below its fit width.
- No half-steps in new elements.

## Color

Inherited from 81 to 85: dominant `--bg-main`, secondary `.card` surface, accent `primary-600`, destructive `red-600`, amber warning, blue info, neutral text. 60/30/10 unchanged: the cards, tables and dialogs are `.card`/`Modal` surfaces; accent stays small. No tone is added; Phase 86 meanings map onto existing chips (anatomy from 81: 12px `aria-hidden` icon plus visible text):

| Meaning | Chip | Tone and icon |
|---------|------|---------------|
| Time-saved figure is an estimate | `Estimate` | OUTLINE, `InfoIcon` |
| A go-live check was recorded | `Recorded` | GREEN, `CheckCircleIcon` (`HealthChip kind="ok" label="Recorded"`) |
| A go-live check not recorded yet | `Not recorded` | NEUTRAL, `InfoIcon` (`HealthChip kind="not_tested" label="Not recorded"`) |
| Organization still in shadow mode | `Shadow mode on` | The 81 Simulation chip (dashed outline, `FlaskConicalIcon`) |
| Organization out of shadow mode | `Shadow mode lifted` | GREEN, `CheckCircleIcon` |
| Gate not met (blocker) | amber `role="status"` text lines, not red: a to-do, not a failure | AMBER `ClockIcon` 16px |

Simulation marks (the 81 rule, extended): every simulation number, column, line and digest section is set apart by a dashed neutral border (`border-dashed border-gray-400 dark:border-gray-500`) and the words "simulation", "would have done" or "shadow mode". Simulation values are never summed into a real count, never drawn in a real-count cell, and never in green.

Accent reserved for (the 81 list items 1 to 4, 82 item 5, 83 items 6 to 9, 84 items 10 to 13 and 85 items 14 to 18 stand; Phase 86 adds exactly three):
19. The confirm of `Lift shadow mode for {name}?` (`Lift shadow mode`) and of `Turn shadow mode back on for {name}?` (`Turn shadow mode on`): the pattern of `Resume automatic actions`. Only one dialog is open at a time.
20. `Record check`: the one affirmative action of an open check form (only one form is open at a time).
21. `Download CSV` / `Download PDF`: the one affirmative action of the Export dialog.
The selected period pill uses item 2 (the selected-pill rule) unchanged.

Accent is NOT used for: `Export activity` (opens the dialog), `Record this check`, `Record again`, `Lift shadow mode` or `Turn shadow mode back on` in the table (they open dialogs), `Show minutes per kind of action`, `What the columns mean`, `Show all {n} rules`, `Close`, `Close form`, the report-card CSV and PDF buttons (they keep the Reporting screen's own styles), any chip, or section headings.

Destructive red: none in this phase. Nothing deletes data. Red appears only on inline error text and error blocks.

Meaning never relies on colour alone: every chip carries an icon and visible text; a disabled button carries a visible reason line referenced by `aria-describedby`; every gate reason is written in words.

### 2. Statistics card (ACTV-05, ACTV-07, D-05..D-08)

A collapsed `.card p-6`, same anatomy as `Response settings`: `<h2>` 18/600 containing `<button aria-expanded aria-controls>` with `BarChart3Icon` 20px, `Statistics`, rotating `ChevronRightIcon`. Under it a 14/400 muted summary line, always visible, loaded on mount with the default period (one fetch; refetch on expand, on period change and on the screen's Refresh; no polling):
- With real decisions: `Last 30 days · 42 done · 3 undone · About 5 h 40 min saved (estimate)`
- Shadow mode, simulation only: `Last 30 days · Simulation only: 18 would have been done · Nothing was carried out`
- Nothing at all: `Last 30 days · No decisions yet`

Expanded body (`border-t pt-6 space-y-6`), top to bottom:

**b. **c. Simulation line** (only when the period holds simulation rows, or the organization is in shadow mode): a `rounded-lg border border-dashed border-gray-400 dark:border-gray-500 p-4` block, `FlaskConicalIcon` 16px, 14/400: `Simulation: 18 would have been done in this period. **d. Time saved** (`TimeSavedBlock`): `<h3>` 14/600 `Time saved` with the `Estimate` chip; value 18/600 `About 5 h 40 min` (formats in R16); the **method**, always visible, 12/400 muted: `This is an estimate, not a measurement. These minutes are fixed in the product and can't be changed.` Under it a text-button disclosure `Show minutes per kind of action` / `Hide minutes per kind of action` (`aria-expanded`) opening a small table (server-supplied, read-only): columns `Kind of action`, `Counted`, `Minutes each`, `Subtotal`, and a `Total` footer row. ### 5. Daily digest (ACTV-04, D-01..D-04)

## Accessibility and Interaction Notes

- Focus: global `:focus-visible` ring only; dialogs take focus on open (Export: `Close`; Lift: the typed-name input; Turn on: `Keep it lifted`); the inline check form moves focus to its textarea and returns it to the row's button on close.
- Cards: `<h2><button aria-expanded aria-controls>` as in 83 section 6. Period pills: `aria-pressed` inside a labelled group. Format and period choices are real radio groups in `fieldset`/`legend`.
- Tables: real `<table>` with `sr-only` caption and `scope` headers; the simulation column header contains the words `(simulation)`, so the distinction is never colour-only or border-only. A wide table sits in a focusable, labelled scroll region (`role="region"`, `tabIndex` 0, `overflow-x-auto`), so keyboard users can scroll it.
- Live regions: load errors and form errors `role="alert"`; gate reasons, the export summary and the cap note `role="status"`; polling does not exist, so nothing announces on a timer.
- Typed confirmation: no paste blocking; the disabled `Lift shadow mode` button carries `aria-describedby` to the visible reason.
- Touch targets: consequential buttons 40px high, pills 32px. Motion: only the existing spinner and chevron rotation, both under the global reduced-motion rule.
- Security of rendered strings: every server string (rule name, target, notes, organization name, file name) is React text; no `dangerouslySetInnerHTML`, no link-ification. The export file name comes from the server's `Content-Disposition`, as `exportReport` already does.
- Idempotency: Download, Record check and both shadow confirms disable on first click and send one request.
