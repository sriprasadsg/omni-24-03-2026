<objective>
Fix the intermittent 401 Unauthorized session bug (SESS-01) by closing the confirmed root cause: the revoked_tokens collection is missing the unique index on jti that refresh_access_token's atomic-consume logic already assumes exists. The consume code (find_one_and_update + $setOnInsert + upsert=True, at authentication_endpoints.py:415-437) is already correct — its inline comment even claims "a unique index on jti guarantees only one request wins" — but that index was never created in database.py (only a TTL index on revoked_at exists). Without it, two concurrent /refresh calls with the same token can both "win", corrupting single-use rotation and producing intermittent 401s. This plan adds the one missing index (D-05 Mechanism A) and adds the concurrent-refresh regression test that never existed.

Purpose: A user's authenticated session must stop intermittently dropping to 401 during normal use. This is the narrow, in-scope fix per D-03/D-05 — Mechanism A only.

Scope boundary (D-05): Mechanism B (multi-tab/cloned-tab sessionStorage divergence in the frontend) is explicitly OUT of scope for this phase and is a separate frontend surface. Do NOT plan or implement a frontend fix. A one-line code comment noting the deferral (pointing to the CONTEXT.md deferred item) next to the index is acceptable but do not expand scope.

Output: The jti unique index in database.py, and a live-Mongo regression test proving exactly-one-winner semantics under concurrency.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser client → /api/auth/refresh | Untrusted refresh-token presented for rotation; must be consumable exactly once |
| API → MongoDB revoked_tokens | Single-use enforcement depends on a DB-level uniqueness constraint |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-40-04 | Spoofing / Elevation of Privilege | refresh-token rotation (authentication_endpoints.py::refresh_access_token) | mitigate | Add the unique index on revoked_tokens.jti so a captured-but-rotated refresh token cannot be replayed by racing the legitimate holder — without the index both requests could "succeed". This is the exact V3 (Session Management) single-use-rotation control the code intended. |
| T-40-05 | Repudiation / Information Disclosure | concurrent /refresh race | mitigate | Regression test proves exactly one winner and exactly one persisted jti document, guarding against silent regression of the single-use guarantee |
| T-40-06 | Denial of Service (index build) | background index creation on revoked_tokens | accept | background=True avoids blocking; collection is TTL-bounded at 24h so it stays small — negligible build cost |
| T-40-SC | Tampering | pip dependencies | accept | No new packages — motor/pymongo are already direct dependencies; no installs in this plan |
</threat_model>
