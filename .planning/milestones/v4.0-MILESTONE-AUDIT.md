## Cross-Phase Integration & E2E Flows (gsd-integration-checker, 2026-08-11)

**24/27 ITAM backend routes have a confirmed frontend caller. 2 routers (7 routes) have no authorization gate. 1 shipped feature (3 routes) has no UI entry point at all.**

- **Field contract (`lifecycleStatus`/`assetSource`, Phase 56)** — correctly read/written by Phase 57's checkout/checkin guards. Phases 59/60 don't reference it at all, which is correct (no requirement demands lifecycle-gating for finance/license/consumable/component operations) but does mean a `disposed` asset can still have a license seat assigned or a component attached — not a contract break, flagged as a design question rather than a bug.
- **BLOCKER — RBAC gap:** `itam_consumable_endpoints.py` and `itam_component_endpoints.py` (Phase 60) depend only on `get_current_user`, never checking `manage:assets`/`manage:itam`/`view:itam`. All 7 sibling ITAM routers (catalog/asset/lifecycle/label/finance/license) correctly gate via `_require_itam_admin`. `router_registry.py` applies no compensating `dependencies=` gate at registration. Net effect: any authenticated user in a tenant — including roles that can't even see the ITAM nav entry — can hit these two routers directly and mutate consumables/components. 60-VERIFICATION.md never checked this (confirmed via grep — zero RBAC mentions for either router).
- **BLOCKER — Phase 58 unreachable:** `components/itam/` has `CatalogPanel.tsx`, `LifecyclePanel.tsx`, `FinancePanel.tsx`, `LicensesPanel.tsx`, `CompliancePanel.tsx`, `SoftwareInventoryPanel.tsx` — no Labels panel, and `services/apiService.ts` has no function for `/label/qr`, `/label/barcode`, or `/labels/sheet`. 61-VERIFICATION.md's own criterion-2 evidence lists exactly the 6 tabs above; Labels was never one of them.
- **Data shapes:** no mismatches found. `purchaseCostCents` consistently integer across models/endpoints; warranty alert docs write both `tenantId` and `tenant_id` (Phase 59's own CR-01 fix, already reconciled by tenant-scoped readers).
- **App boot:** `python -c "import app"` from `backend/` succeeds cleanly; all 9 ITAM routers confirmed registered in `router_registry.py` lines 82-90.
