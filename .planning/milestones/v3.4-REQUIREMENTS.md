## v1 Requirements — all shipped

### Native File/URL/IP/Hash Scanning (Phase 50)

- [x] **NSCAN-01**: Offline file scan (bundled ClamAV-signature subset + hash-sig/YARA-fallback matching) — Clean/Suspicious/Malicious verdict + confidence score, no live lookup.
- [x] **NSCAN-02**: URL/IP/domain/hash reputation against signed, bundled threat-intel feeds — no live lookup at scan time.
- [x] **NSCAN-03**: `scan_file`/`scan_url`/`scan_hash`/`scan_ip` scan API surface, invokable by an operator and by internal FIM/behavioral event triggers, with per-tenant backend ingestion.

### Vulnerability Detection Engine (Phase 51)

- [x] **VULN-01**: Agent-side local vulnerability scan — installed-package CVE matching, misconfiguration checks (weak SSH, open ports, deprecated protocols), exposed-secret detection — prioritized finding list, no external NVD call at scan time.
- [x] **VULN-02**: CVE/vuln feed ships as a signed bundle (reuses Phase 50's signed-bundle mechanism); agent applies delta updates autonomously.
- [x] **VULN-03**: Each finding carries CVE ID, CVSS, affected package/path, a remediation hint, and a playbook reference (consumed by Phase 53).

### File Integrity Monitoring (Phase 52)

- [x] **FIM-01**: Low-overhead path monitoring via native OS facilities (inotify/fanotify Linux; `notify` crate on Windows) on configured critical paths.
- [x] **FIM-02**: Change events (create/modify/delete/permission) carry before/after hash, process tree, and user context, routed to a local queue for the remediation engine.
- [x] **FIM-03**: Baseline snapshots are ed25519-signed, with drift detection on agent restart.

### Autonomous Remediation (Phase 53)

- [x] **AUTO-01**: Finding → playbook selection → execute → verify → complete pipeline, with human override available at every step.
- [x] **AUTO-02**: YAML-defined remediation playbook system per finding class (patch package, kill process, restore file, block IP, rotate key, disable service), operator-extensible.
- [x] **AUTO-03**: Safety guards — dry-run mode, approval gate for destructive actions, rollback on verification failure, per-agent max-concurrent-remediations cap.
- [x] **AUTO-04**: Immutable, append-only remediation audit trail (finding, playbook, actions, verification result, any operator override).

### Integration & Operator UI (Phase 54)

- [x] **INT-01**: Per-tenant operator dashboard — live scan status, findings feed, remediation queue, audit trail.
- [x] **INT-02**: Operator can trigger on-demand scans, approve/deny pending remediations, browse/create playbooks from the UI.
- [x] **INT-03**: API endpoints expose every agent security function (scan, vuln-scan, fim-status, remediation-trigger, playbook CRUD).

### Advanced Threat Detection & Response (Phase 55)

- [x] **INT-04**: Threat intel feeds + correlation engine — `SiemEngine.correlate_native_findings()` ingests native findings into the existing rule-evaluation loop; HTTP-reachable via `POST /api/threat-intel/correlate-native`. Route mounting was blocked at initial verification by a pre-existing `virustotal_client.py` import bug (55-VERIFICATION.md gap #1) — resolved by plan 55-05 (commit `766e3ca`), re-confirmed live at this milestone close.
- [x] **AUT-03**: Predictive automated containment — UEBA `shadow_ai` anomaly detection triggers approval-gated `kill_process` remediation via `select_playbook()`'s deterministic anomaly branch, deduped and fire-and-forget.
- [x] **COMM-01**: Outbound syslog/SIEM webhook (OCSF `class_uid=2004`) at correlation/anomaly/remediation pipeline points, via the existing SSRF-safe HMAC-signed `webhook_service`.

## Out of Scope

| Feature | Reason |
|---------|--------|

| Live VirusTotal lookup at scan time | Offline-first — signed bundled feeds only; the VirusTotal client (55-05) serves the separate threat-intel correlation surface, not the NSCAN scan path |
