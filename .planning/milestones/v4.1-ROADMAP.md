## Phase Details

### Phase 64: User Management
**Goal**: Users can authenticate and manage accounts securely.
**Depends on**: Nothing
**Requirements**: ITAM-USR-01, ITAM-USR-02, ITAM-USR-03, ITAM-USR-04, ITAM-USR-05, ITAM-USR-06
**Success Criteria**:
  1. User can create, edit, delete user accounts.
  2. User can be assigned RBAC roles.
  3. User can authenticate via LDAP/AD and SAML/SSO.
  4. User can manage API access tokens.
  5. User can enable/disable 2FA.
**Plans**: 6 plans (waves 1→2: 64-01 and 64-02 in wave 1; 64-03, 64-04, 64-05, 64-06 in parallel in wave 2)
**UI hint**: yes — frontend for user CRUD, RBAC, 2FA, and API keys already exists (see each plan's `<frontend_scope>`); phase 64 is backend-only and constrained to not break the shipped components. LDAP/SAML admin UI deferred to the Phase 65 console work.

Plans:
- [x] 64-01-PLAN.md — User CRUD with ITAM fields, tenant isolation, admin gating (ITAM-USR-01)
- [x] 64-02-PLAN.md — RBAC extension with ITAM roles, fixed normalization, super-admin guard (ITAM-USR-02)
- [x] 64-03-PLAN.md — LDAP/AD integration: config, auth, user sync, group-to-role mapping (ITAM-USR-03)
- [x] 64-04-PLAN.md — SAML/SSO: metadata, ACS, SLO, assertion validation, provisioning (ITAM-USR-04)
- [x] 64-05-PLAN.md — API token management: lifecycle, scopes, expiration, rate limits (ITAM-USR-05)
- [x] 64-06-PLAN.md — 2FA: TOTP enroll/verify, backup codes, disable, fixed pitfalls (ITAM-USR-06)

### Phase 65: Core Data, Audit & Customization
**Goal**: Admins can define custom data structures, track activities, and configure global UI settings.
**Depends on**: Phase 64
**Requirements**: ITAM-DAT-01, ITAM-DAT-02, ITAM-DAT-03, ITAM-SET-01, ITAM-SET-02, ITAM-SET-03
**Success Criteria**:
  1. User can add/edit custom fields to asset models.
  2. User can view audit trail for any asset/entity.
  3. User can bulk import/export assets via CSV.
  4. User can update branding (logo, colors) in Global Settings.
  5. User can change the interface language.
**Plans**: 4 plans (waves 1→4, sequential — every plan touches services/apiService.ts and the ITAM console shell)
- [ ] 65-01-PLAN.md — Custom Fields Manager: model fieldset read route, authoring UI, usage counts (ITAM-DAT-01)
- [ ] 65-02-PLAN.md — Audit trail: entity-filtered query + log_itam_action backfilled into all 20 write routes across 7 itam_*_endpoints.py files, Activity tab (ITAM-DAT-02)
- [ ] 65-03-PLAN.md — CSV import/export: formula-safe export, size-capped validated import with dry run, Import/Export tab (ITAM-DAT-03)
- [ ] 65-04-PLAN.md — ITAM-console Global Settings: branding applied to the console + hand-rolled locale switch, Settings tab (ITAM-SET-01/02/03)
**UI hint**: yes
