## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| API → filesystem | Two more generated file types are written into the shared reports directory and later streamed by filename. |
| Exported file → spreadsheet/PDF reader | Tenant-authored strings (asset names, notes, consumable names) are embedded into documents opened outside the app. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-72-06 | Tampering | Cell values written into CSV/XLSX | medium | mitigate | Every cell passes through `_sanitize_cell` from `compliance_reporting_data` (CWE-1236) in both new renderers, asserted by a test. |
| T-72-11 | Tampering | User strings embedded into PDF markup | medium | mitigate | Cell text is `html.escape`d before being wrapped in a reportlab `Paragraph`, exactly as `compliance_reporting_pdf.py` already does. |
| T-72-04c | Information Disclosure | New file types downloadable by filename | high | mitigate | Both renderers route through `itam_reporting_service.generate`, which stores `{filename, tenantId}` in `itam_report_exports`; the unchanged download route's ownership check therefore covers pdf and xlsx, asserted by a cross-tenant test. |
| T-72-08 | Denial of Service | Very large PDF/Excel generation | medium | mitigate | The shared `MAX_REPORT_ROWS` ceiling applies before any renderer runs, and the truncation is stated in the document rather than applied silently. |
| T-72-SC | Tampering | npm/pip installs | low | accept | reportlab 5.0.0 and openpyxl 3.1.5 are already installed in `backend/venv` and already used by the compliance exporters; no install task exists. |
</threat_model>
