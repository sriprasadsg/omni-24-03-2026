<objective>
Wire the two window-crossing webhook events (D-05 category 2) into background sweeps, correctly.

This is the one genuinely non-obvious piece of engineering in the phase. `WebhookService.trigger_webhook` resolves its database through the request-scoped accessor and looks subscriptions up through the tenant-isolation wrapper, which reads the tenant from ambient contextvars. A sweep loop has no request and therefore no ambient tenant, so an unbracketed call resolves against a deliberately unmatchable filter and the webhook silently never fires — no error, no log, nothing (RESEARCH Pitfall 3). Every dispatch here is individually bracketed with the tenant id taken from the document being processed.

D-08 is honoured literally: `asset.warranty_expiring` is added inside Phase 71's existing periodic warranty job, and `license.expiring_soon` is added as a sweep driven from that same scheduler loop rather than a newly registered job.

Purpose: without this plan two of the eight advertised event types would appear in the subscription picker and never deliver — the worst possible failure, because it is invisible.
Output: both expiry events dispatching correctly under tenant context, plus the mixed-tenant regression that proves it.
</objective>
