<objective>
Ship the ITAM-API-01 auth spine end-to-end and prove it with a real vertical slice: an API key authenticates, is narrowed by its scopes, performs a real ITAM mutation, and that mutation dispatches a real webhook event.

This plan implements D-01 (swap `_require_itam_admin` to dual session/API-key auth), D-02 (all `_require_itam_admin`-gated ITAM routers, not a curated subset), D-03 (no `/v1/` prefix — API keys unlock the existing `/api/itam/*` and `/api/assets/*` paths), D-04 (reuse the existing per-key rate limiter as-is), and closes RESEARCH.md Pitfall 1 — the scope-narrowing gap that makes scoped keys security theater the instant D-01 ships. Per D-13 no API docs artifact is produced: FastAPI's existing auto-generated `/docs` covers the ITAM routers once API-key auth is added, so there is deliberately no docs task in this phase.

Purpose: every other plan in this phase depends on this auth spine and on the single-source event-type constants created here. Getting the vertical slice committed first means an architectural dead-end surfaces after one commit, not after five layers.
Output: dual-auth + scope-narrowed `_require_itam_admin`, an explicitly session-only sibling guard for the four excluded non-ITAM surfaces, `manage:assets` as an issuable scope, the eight ITAM event-type constants, the first webhook call site, and the ITAM-API-01 regression suite.
</objective>
