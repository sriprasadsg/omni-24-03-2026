## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client→API | Untrusted input (asset request details, approval decisions) crosses here. |
| API→Database | Backend services interact with the database. |
| Approval Service→Notification Service | Approval actions trigger notifications. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-71-09 | Tampering | Asset request details | high | mitigate | Input validation on `item_description`, `quantity`, `reason`. RBAC enforcement: only authorized users can submit requests; only authorized approvers can approve/reject. |
| T-71-10 | Elevation of Privilege | Approval/Rejection actions | critical | mitigate | Strict RBAC checks on `approve_asset_request` and `reject_asset_request` endpoints. Ensure `approver_id` is derived from authenticated user, not client input. |
| T-71-11 | Information Disclosure | Asset request details/Approval queue | medium | mitigate | Tenant isolation enforced for all asset request data. Approvers only see requests relevant to their scope/tenant. |
| T-71-12 | Denial of Service | Notification spam | medium | mitigate | Implement rate limiting for notifications (e.g., X notifications per minute per request/user). Batch notifications if many events occur rapidly. |
| T-71-SC | Tampering | npm/pip/cargo installs | high | mitigate | slopcheck + blocking human checkpoint for [ASSUMED]/[SUS]. |
</threat_model>
