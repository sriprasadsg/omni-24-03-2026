<objective>
Deliver ITAM-DAT-02 (Audit Trail / Activity Log for entities): every ITAM write is recorded in the platform's existing hash-chained ledger, and an ITAM admin can read the trail for any entity from the ITAM console.

Purpose: `backend/audit_service.py` already implements a tenant-isolated, SHA-256 hash-chained, rollback-capable audit ledger, and `GET /api/audit-logs` already exposes it — but `grep -rn "log_action_async" backend/itam_*.py` returns zero matches, so today the ITAM module writes nothing to it. This plan closes exactly that gap. It does not build a second ledger.

**D-02 (user scope decision, recorded here — no CONTEXT.md exists for this phase):** ITAM-DAT-02's "view audit trail for any asset/entity" is read as covering the whole ITAM surface, not only what Phase 70 adds. Audit calls are therefore backfilled into all seven pre-existing endpoint files — `itam_catalog_endpoints.py`, `itam_asset_endpoints.py`, `itam_component_endpoints.py`, `itam_consumable_endpoints.py`, `itam_finance_endpoints.py`, `itam_license_endpoints.py`, `itam_lifecycle_endpoints.py` — covering all twenty of their write routes. This is deliberately larger than a new-endpoints-only reading (65-RESEARCH.md Pitfall 3 / Open Question 3).

Output: one new thin service module, two small extensions to existing platform audit code, twenty instrumented write routes, a new Activity tab in the ITAM console, and backend + frontend tests.

Non-goal (65-RESEARCH.md Anti-Patterns): no ITAM-specific audit collection, no new hashing scheme, no direct `db.audit_logs` write/update/delete anywhere in the diff.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser → `GET /api/audit-logs` | Untrusted query parameters (`resourceType`, `resourceId`, `limit`, `skip`) reach a query builder over a cross-tenant collection. |
| ITAM write route → audit ledger | Application code crosses into an append-only, tamper-evident store whose integrity guarantee other features depend on. |
| tenant A → tenant B's history | The ledger holds every tenant's entries in one collection; separation is enforced by query construction, not by physical partitioning. |
