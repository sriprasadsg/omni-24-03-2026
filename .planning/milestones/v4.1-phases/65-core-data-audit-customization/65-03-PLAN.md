<objective>
Deliver ITAM-DAT-03 (Bulk CSV Import/Export): an ITAM admin can export their asset inventory to CSV and load assets back in from a CSV, with per-row validation and a readable failure report.

Purpose: this is the last of the three Core Data requirements and the one with the widest blast radius — a bulk write path is the easiest place to accidentally bypass the validation every single-asset write enforces, and a bulk read path is the easiest place to leak another tenant's inventory. Both risks are closed by routing through code that already exists: `itam_catalog_service.validate_custom_field_values` for values, `itam_asset_endpoints.build_asset_document` / `next_asset_tag` for document assembly, and the tenant-isolated `get_database()` wrapper for every query.

Output: two new backend modules (a pure CSV service and a routes file), a shared asset-document builder extracted from the existing manual-create route, router registration, a new Import / Export tab in the ITAM console, and backend + frontend tests.

Non-goal: no Excel (.xlsx) support in this phase. `openpyxl` is installed and `compliance_framework_mgmt_endpoints.py` shows the pattern, but ITAM-DAT-03 says CSV, and stdlib `csv` is the in-repo convention for CSV-specific paths (65-RESEARCH.md Standard Stack). No `pandas` in this diff.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser → `POST /api/itam/data/import` | An arbitrary uploaded file crosses into a bulk write path that creates persistent tenant records. |
| server-generated CSV → the admin's spreadsheet application | Exported data leaves this system's control and is re-interpreted by a program that executes formulas. |

| T-65-03-01 | Tampering | CSV export cell values (formula injection) | high | mitigate | `sanitize_csv_cell` prefixes an apostrophe to any value whose first character would make a spreadsheet treat the cell as a formula or escape sequence, and it is applied to every base and custom-field cell on the way out. The precedent this clones (`compliance_framework_mgmt_endpoints.py`) has neither cap — this is a phase-specific addition, not an inherited guarantee. |
| T-65-03-03 | Tampering | import bypassing custom-field validation | high | mitigate | Every row is constructed as a `ManualAssetCreate` (which forbids extra fields) and then passed through `collect_field_defs` + `validate_custom_field_values` — the identical pair `create_manual_asset` uses. The import path defines no validator of its own, so the two write paths cannot drift. Problems are surfaced verbatim from the shared validator. |
| T-65-03-04 | Information Disclosure | cross-tenant export | high | mitigate | The export query runs through the tenant-isolated `get_database()` wrapper, which injects `tenantId`; an acceptance criterion asserts the raw `db._db` handle appears nowhere in `itam_data_endpoints.py`. `MAX_EXPORT_ROWS` additionally bounds any single response. |
| T-65-03-05 | Elevation of Privilege | unguarded bulk routes | high | mitigate | Both routes depend on `_require_itam_admin` imported from `itam_asset_endpoints` — the same `manage:assets` gate every other ITAM write uses. No new role-string set is introduced. |
| T-65-03-06 | Repudiation | untraceable bulk creation | medium | mitigate | Each created asset gets an `itam_asset.create` ledger entry and each batch gets an `itam_import.assets` summary entry, both through 65-02's `log_itam_action`. A dry run writes neither data nor audit entries. |
| T-65-03-07 | Tampering | server-owned fields supplied by the uploader (`id`, `tenantId`, `assetSource`, `createdAt`) | medium | mitigate | `row_to_asset_payload` drops those columns before validation rather than forwarding them, and `build_asset_document` sets them server-side; `ManualAssetCreate`'s `extra="forbid"` rejects anything else unexpected. |
| T-65-SC | Tampering | npm/pip package installs | high | accept | No package installs. CSV handling uses the Python standard library; `pandas` is explicitly excluded from this diff by an acceptance criterion. The file upload UI is hand-rolled, adding no frontend dependency. |
