<frontend_scope>
## Frontend wiring (ROADMAP "UI hint: yes")

Audited `components/` and `src/`: there is **no LDAP/AD UI of any kind** — no directory-config settings tab, no sync-status view, and no directory option on `components/LoginPage.tsx` (382 lines, which offers local credentials plus a Google SSO button only).

**Deliberately deferred to a later UI slice.** Rationale:
1. LDAP configuration (bind DN, base DN, TLS settings, group-to-role mapping table, test-connection button, sync schedule) is a full settings screen with its own design surface — building it here would blow this plan's context budget on top of a brand-new backend module.
2. LDAP bind is transparent at the login form: an LDAP-sourced user types the same email/password into the existing `LoginPage`, and the backend decides the auth source. No login-page change is required for end users to authenticate via LDAP.
3. Directory setup is a one-time operator task, fully serviceable via the env vars and admin endpoints declared in this plan's `user_setup`.
4. `services/apiService.ts` and the ITAM console shell are owned end-to-end by Phase 65's four plans; adding a settings tab here would collide with that ownership.

Consequence to record in the SUMMARY: ITAM-USR-03 ships operator-configurable (env vars + admin API) but not operator-discoverable (no settings screen). That is a UI follow-up, not a backend gap.
</frontend_scope>
