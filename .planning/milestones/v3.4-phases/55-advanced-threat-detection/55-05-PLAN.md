## Design decisions (documented per deep-work rules)
- **Real API v3 calls, not a mock.** The client makes real outbound
  `https://www.virustotal.com/api/v3/*` GET requests via httpx (already a
  dependency) with the `x-apikey` header. No fabricated verdicts.
- **API-key-absent = graceful degrade.** Missing/empty `VIRUSTOTAL_API_KEY`:
  construction succeeds; every lookup returns `{"error": "VirusTotal API key
  not configured"}`. This keeps keyless CI green and lets existing callers'
  `"error" in result` / `"error" not in result` branches do the right thing.
- **Dead class fate = delete.** `VirusTotalScanCapability` is referenced nowhere
  (grep-confirmed); it is deleted, not repaired. Git-recoverable if a future
  capability-registry phase needs it.

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-55-01 | Information Disclosure | `x-apikey` handling in virustotal_client.py | high | mitigate | Key read only via os.getenv; never logged; error strings returned to callers MUST NOT embed the key value |
| T-55-02 | Tampering / SSRF | user-supplied artifact reaching the outbound path | medium | mitigate | Base host is the FIXED constant `https://www.virustotal.com/api/v3`; artifact is URL-encoded (`quote`) or base64url-encoded into the path only, never used as host/scheme; artifact length already bounded by ScanRequest max_length |
| T-55-04 | Spoofing (mock-as-real) | API-key-absent / API-error path | high | mitigate | Key-absent and error paths return `{"error": ...}` with NO verdict field — never a fabricated Harmless/Clean verdict that callers would record as a real result |

| T-55-SC | Tampering | new package installs | low | accept | Zero new packages — httpx/os/base64 are already present (RESEARCH.md Package Legitimacy Audit: no new third-party deps this phase) |
