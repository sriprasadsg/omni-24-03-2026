<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Kernel→Agent | Fanotify events from kernel are trusted; agent processes them. |
| Agent→/proc | Agent reads from `/proc` filesystem for process info. Integrity of `/proc` assumed. |
| Agent→SQLite | Agent writes FIM events to local SQLite. Integrity of local storage assumed. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-65-01 | Tampering | /proc filesystem reads | medium | mitigate | Validate PID existence before reading `/proc`; handle file not found errors gracefully (return partial info). |
| T-65-02 | Spoofing | PID from fanotify | low | accept | Kernel provides PID; trust kernel source. |
| T-65-03 | DoS | High volume fanotify events | high | mitigate | Implement event buffering/batching in `fim.rs` before enqueueing; graceful error handling for queue overload. |
| T-65-04 | EoP | CAP_SYS_ADMIN privilege | critical | mitigate | Fanotify watcher runs in a dedicated unprivileged process with only `CAP_SYS_ADMIN` if possible; otherwise, agent process runs with least privilege. |
| T-65-SC | Tampering | npm/pip/cargo installs | high | mitigate | slopcheck + blocking human checkpoint for [ASSUMED]/[SUS] |
</threat_model>
