<objective>
Open the closed notification event-type vocabulary so warranty-expiry alerts can actually be routed through the tenant-configurable rule and channel system Phase 21 built, and prove the delivery path is reachable before Plan 59-04 depends on it.

Purpose: ITAM-FIN-02 requires expiry alerts "routed through the existing notification/webhook infrastructure". RESEARCH Pitfall 2 found that infrastructure's event vocabulary is hardcoded in two places — `notification_service.VALID_EVENTS` and `notification_endpoints.RuleCreate.event_type`'s `Literal` — and that a tenant admin trying to create a warranty rule gets a 422 today. Picking a new event-type string alone does not make rule-based routing usable. This plan closes that gap with a one-string addition in each file plus the tests that pin both halves.

**Planning decision recorded here (PD-01):** warranty alerts use **both** delivery paths, not one. The guaranteed in-app write via `get_notification_service(db).send_alert(...)` makes "Admin sees each asset's warranty status and receives an alert" true even for a tenant that has configured no rule; the rule-routed `send_notification(..., "itam.warranty_expiring", ...)` call makes the requirement's literal "notification/webhook infrastructure" wording true for a tenant that has. RESEARCH's Open Question 1 offered the narrower in-app-only path as a default; taking it would deliver less than ITAM-FIN-02 asks for, so this plan takes the fuller path and this is the enabling half of it.

Output: `"itam.warranty_expiring"` added to `VALID_EVENTS` and to `RuleCreate.event_type`, plus `backend/tests/test_itam_warranty_notify.py` pinning both the vocabulary and the calling contract of `send_notification`.

This plan shares no file with Plan 59-01, so it runs alongside it in wave 1.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| tenant admin → `POST /api/notifications/rules` | An untrusted `event_type` string crosses here into a persisted rule document. |
| rule + channel documents → outbound dispatch | Tenant-configured destinations (Slack/webhook URLs, email addresses) drive outbound requests from the server. |
| background caller → `send_notification` | A caller supplying a database handle of the wrong shape crosses an implicit, previously undocumented contract. |
