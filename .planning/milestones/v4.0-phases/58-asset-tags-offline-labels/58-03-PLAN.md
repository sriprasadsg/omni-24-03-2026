<objective>
Expand the proven slice sideways: add Code128 1D barcode generation and its route, then prove the offline guarantee that is this phase's distinguishing requirement.

Purpose: ROADMAP success criterion 1 needs both a QR code and a 1D barcode. Code128 is the symbology that fits — it is alphanumeric-safe and accepts the codebase's real `IT-0001`-shaped tags, unlike the numeric-only EAN/UPC family. Success criterion 3 needs the whole generation path to work with outbound network access blocked, and this is the first point where more than one generator exists to prove it against.

Output: `generate_barcode_png` in `backend/itam_label_service.py`, `GET /api/assets/{asset_id}/label/barcode` in `backend/itam_label_endpoints.py`, and two new test files.
</objective>

Define `generate_barcode_png(asset_tag: str) -> bytes`. Raise `LabelEncodingError` immediately when `asset_tag` is falsy or is not a `str` — before touching the library — so the empty and wrong-type cases produce the same typed error the QR path produces. Otherwise resolve the class through the library's own public factory `barcode.get_barcode_class(BARCODE_SYMBOLOGY)`, construct it with the bare tag string and `writer=ImageWriter(format="PNG")`, write into a fresh `io.BytesIO` with `options={"write_text": False}`, and return `buf.getvalue()`.

Two rules on that function that are not stylistic:

First, the payload is the bare tag string exactly as stored, symmetric with `generate_qr_png` per D-02 — no prefix, no URL, no separator, no case folding, no Unicode normalization. Both codes on a label must round-trip to the same lookup key.

Second, wrap the construction and write in a `try` that catches the library's own error base class (import it from `barcode.errors` and confirm at implementation time that the illegal-character error derives from it) together with `ValueError` and `TypeError`, and re-raise as `LabelEncodingError` chained with `from exc`. Do not catch bare `Exception` — a genuine server fault should still surface as a 500. Do not return a placeholder, blank, or partially-rendered image on failure under any circumstance: an image that looks like a valid label but carries no scannable payload gets printed and stuck onto hardware before anyone finds out, which is strictly worse than an error the caller sees immediately.

`write_text` is off because the human-readable tag, name and model text required by D-01 is drawn by the PDF layout layer in Plan 04, which positions it deliberately within the Avery cell; letting the writer draw its own caption would double it up there.
