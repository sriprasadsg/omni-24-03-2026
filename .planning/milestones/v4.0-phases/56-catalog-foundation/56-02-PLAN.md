<objective>
Expand outward from the proven tracer slice: the same kind-parameterized catalog router now
serves all five ITAM catalog entities, and asset Models gain the two things that make them
more than a name — validated references to a Manufacturer and a Category, and the
model-level fieldsets that define which custom fields the assets of that model carry.

Purpose: ITAM-CAT-01 needs Category and Location alongside the tracer's Manufacturer,
ITAM-CAT-03 needs Supplier as a distinct entity with its own contact shape, and ITAM-CAT-04
needs the fieldset *definition* surface. Consuming those definitions on an asset is 56-04.

Output: four more catalog kinds live, `backend/itam_catalog_service.py` holding the fieldset
contract that 56-04 imports, and `backend/tests/test_itam_catalog.py`.
</objective>

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-56-07 | Information Disclosure | `asset_categories`, `locations`, `suppliers`, `asset_models` | high | mitigate | Every access uses the handle from `get_database()`; an acceptance criterion asserts none of the four collection names appears in the exemption allowlist in `database.py`, and a parameterized test asserts the filter reaching each collection carries the caller's tenantId. |
| T-56-08 | Tampering | fieldset and field-definition payloads | high | mitigate | Field keys are constrained to an identifier shape by `validate_fieldsets`, so a key cannot carry Mongo operator syntax or dotted-path syntax that would later be interpreted as a nested-document write when values are stored. Duplicate keys and option-less select fields are refused with 400. |
| T-56-09 | Elevation of Privilege | all catalog mutation routes | high | mitigate | Every route inherits the `_require_itam_admin` dependency established in 56-01; no route in this plan defines its own auth. |
| T-56-10 | Tampering | supplier contact email | medium | mitigate | `EmailStr` validation at the boundary so a malformed or injected address is rejected before storage; a supplier contact is a future notification target and is never trusted as free text. Primary trust boundary, so mitigated rather than accepted at L1. |
| T-56-11 | Denial of Service | fieldset size on a model document | low | accept | Rationale: fieldsets are admin-authored, bounded by the same request-size limits as every other route, and a model document is read one at a time rather than fanned out; no unbounded growth path exists because fieldsets are replaced, not appended, on update. |
| T-56-SC | Tampering | npm/pip/cargo installs | high | accept | Rationale: no package-manager install task in this plan. `backend/requirements.txt` is untouched; `pydantic[email]` providing `EmailStr` is already an installed dependency. |
</threat_model>
