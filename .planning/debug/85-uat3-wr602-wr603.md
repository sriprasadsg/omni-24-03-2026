# WR-603 requester-set staff fields at creation, WR-602 audience-tagged notices on the tenant WebSocket

Both are from the second-gap-round review (`85-REVIEW.md`, 101bc4e58); the user decided on 2026-11-10 to fix both
in this round rather than accept them.

## WR-603 root cause
`POST /api/tickets` (`backend/tickets_endpoints.py:138-201`) stays open to every `view:dashboard` caller and passes
`body.model_dump()` into `tickets_service.create_ticket` (`tickets_service.py:173`), so a requester can set
`assignee`, `assignee_group`, `watchers`, `approval_required`, `sla_hours` and `due_date` (`tickets_models.py:34-52`),
also through the `template_id` default-merge branch. Watchers is the practical hole: `add_watcher` needs
`manage:tickets` since G-85-4, but any address (including outside the tenant) set at creation then receives
staff-side traffic through `ticket_notifications._recipients` (escalation reason/priority, staff-comment
notices). The structure test classifies routes by permission, not by honoured body fields, so it cannot catch it.

Fix direction: in `create_ticket`, when `not await ticket_access.is_ticket_staff(current_user)`, drop those keys
before the service call and after the template merge; test that a requester's `watchers` and `assignee` are not
stored and that staff can still set them. `backend/tickets_endpoints.py` carries the user's uncommitted WIP
(download route + persistent attachment dir, +38/-11): keep it out of the commits.

## WR-602 root cause
The REST feed/history filter (`reader_filter`) hides `metadata.audience == "tenant_admins"` notices from users
without `manage:agents`, but two live-push paths ignore audience:
- `backend/notification_service.py:91-100` `send_alert` skips the socket only for `audience == "ticket_staff"`;
  `tenant_admins` notices (the desk breaker notice, `service_desk/withdraw.py:133-136`) go to
  `broadcast_notification(tenant_id, ...)` (`websocket_manager.py:380`), i.e. every connected client.
- `backend/pending_agents.py:275-290` `_post_in_app` broadcasts title, message and metadata (agent hostname, seat
  usage) with no audience check.
- `NotificationCenter.tsx:124` renders every pushed `notification` event.

Fix direction: skip the tenant broadcast whenever `metadata.audience` is set (the feed keeps the record), and in
`_post_in_app` skip the broadcast or send only a generic title without hostname or counts; extend
`backend/tests/test_service_desk_notification_audience.py` with the audience-tagged socket case.
